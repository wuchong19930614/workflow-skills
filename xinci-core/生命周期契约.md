# 生命周期契约

候选从捕获到建站决策的唯一状态机。状态只存在于 `数据/新词工作流/账本/候选账本.json`,只能由 `scripts/registrar.py` 写入。skill 提议转移,用户确认,registrar 执行——三者永不合并。

## 状态机

```
(新候选)
   │ xinci-scan 捕获
   ▼
captured ──G1–G5 全过──→ screened ──登记 expiry──→ tracking ──形成达标──→ formation_confirmed
   │                        │                        │    │                      │
   │任一闸门否决             │窗口以天计               │    │expiry 过,用户确认      │ xinci-qualify
   ▼                        │(快道)                  │    ▼                      ▼
rejected                    │                        │  expired          qualified / disqualified
                            ▼                        │                          │
                     xinci-decide 快速模式            │复查中 G1 翻转             │ xinci-decide
                            │                        │或竞品占位                 ▼
                            ▼                        ▼              ┌───────┬────────┬──────┐
                     fast_grab_ready              rejected          ▼       ▼        ▼      ▼
                            │                                 build_ready pilot_ready hold no_site
                            │用户建站/放弃                          │        │
                            ▼                                      └───┬────┘
                     built / expired                                   │用户建站
                                                                       ▼
                                                                     built
```

补充转移:

- 任何非终态候选可由用户转 `withdrawn`(主动撤回)或 `superseded`(被更好措辞的候选取代,`superseded_by` 指向新候选)。
- `hold` 可由用户送回 xinci-qualify 或 xinci-decide 重审(hold → build_ready / pilot_ready / no_site / disqualified)。
- `built` 的快道候选,词若被证明耐久,可由用户发起转回 `tracking`,走完整认定升级成正经全站。

终态:`rejected` / `expired` / `superseded` / `withdrawn` / `built`,以及决策终局 `disqualified` / `no_site`(除 superseded 外无出边)。

## 每转移的证据要求

registrar 逐项校验,缺证据即拒绝;完整表与 `scripts/registrar.py` 实现一致:

| 转移 | 必须提供 |
| --- | --- |
| register(→captured) | slug、term(精确措辞,禁转述)、source.url、task、≥1 个证据文件 |
| captured→screened | 闸门 G1–G5 全 pass;window_estimate ∈ {days, weeks, months};≥1 证据 |
| *→rejected | reason(失败闸门 + 现场证据要点) |
| screened→tracking | expiry(YYYY-MM-DD)+ ≥1 条失效条件 + ≥1 证据 |
| screened→fast_grab_ready | decision_ref(md 存在且同名 html 同批存在)+ expiry;play 固定 fast_grab |
| tracking→formation_confirmed | 累计 ≥2 个 `-track` 观察;本次 G1=pass;≥1 证据 |
| tracking→expired | reason(expiry 已过经用户确认 / 失效条件命中) |
| formation_confirmed→qualified | 整数 score ≥80 + G6/G7/G8 全 pass + ≥1 证据 |
| formation_confirmed→disqualified | reason(决定性缺口:哪一项、差多少) |
| qualified→build_ready / pilot_ready | decision_ref md+html 双文件存在;play ∈ {single_domain, cluster_expansion} |
| qualified/hold→hold / no_site | reason;**不得**携带 decision_ref(no-go 不出决策书) |
| built→tracking | reason(升级理由)+ 新 expiry |
| *→withdrawn | reason |
| *→superseded | superseded_by(账本中已存在的其他 slug) |
| checked(非转移) | 更新 last_checked_at、追加证据,不改状态 |

## 时间字段:只记录,不调度

- 三个时间事实:`first_observed_at`(首见)、`last_checked_at`(上次复查)、`expiry`(失效日,附推理于证据)。
- **没有** next_check_at、默认复查间隔、调紧/放宽规则等任何调度机制。
- skill 被调用时只汇报时间事实("该候选 12 天未复查,expiry 还剩 5 天"),不据此自动做任何事。
- expiry 过期不自动转 expired:skill 提议,用户确认后 registrar 才执行。
- 复查哪些候选、何时复查、何时推进阶段,全部由用户决定。

## 证据与命名约定

- 观察文件:`证据/<slug>/<YYYY-MM-DD>-<阶段>.json`,阶段 ∈ {scan, track, qualify, decide};schema 见 `数据结构/observation.schema.json`。
- 观察只描述看到了什么,不携带读起来像裁决的字段;裁决只在账本。
- **数据极简原则**:只写简单清晰、服务于决策的内容——不写仪式性字段、不写过程流水账、不为"显得完整"而填充。观察写要点,不写转录。
- 运行清单:`运行/<YYYY-MM-DD>-<skill>.json`,每次运行一个小 JSON(日期、skill、打开过的来源、触及的候选、计费调用数),不写过程日志。

## registrar 用法

```bash
python3 /Users/vito.wu/IdeaProjects/workflow-skills/xinci-core/scripts/registrar.py register \
  --slug <slug> --term "<精确措辞>" --source-url <URL> --task "<任务>" \
  --evidence "证据/<slug>/<日期>-scan.json"

python3 /Users/vito.wu/IdeaProjects/workflow-skills/xinci-core/scripts/registrar.py transition \
  --slug <slug> --to <状态> --by <skill名> [--gates G1=pass,...] [--expiry YYYY-MM-DD] \
  [--invalidation "条件1;条件2"] [--score N] [--decision-ref 决策书/<slug>.md] \
  [--play ...] [--reason "..."] [--evidence <路径>]

python3 /Users/vito.wu/IdeaProjects/workflow-skills/xinci-core/scripts/registrar.py checked \
  --slug <slug> --evidence "证据/<slug>/<日期>-track.json"
```
