# xinci 新词工作流

发现并验证英文 Google 搜索词,产出"这个词能不能撑起一个独立 SEO 站"的建站决策书。

由用户人工驱动,skill 不自我调度。仓库层面的事(单元清单、数据区配置、symlink 接入、测试)见[仓库根 README](../README.md);本文讲这套工作流**本身**怎么运转。

---

## 核心前提

这套流程赌的是一件事:**有些搜索任务是有人被迫重复完成、而现有供给答不上来的**。找到这种格子,做一个真能完成任务的页面或工具,就能拿到位置。

它不赌"新词有窗口期"。那个假设在 2026-08-23 的回测里被证伪了——见下文「当前状态」。

### 两条赛道

| 赛道 | 定义 | 量级数据 | 能走哪条盈利线 |
| --- | --- | --- | --- |
| `new` 新词道 | 措辞太新以致 Semrush 查无 | 窗口期禁用(查无是定义属性,查了说明不了任何事) | **只能走订阅线**——广告线要求可测量量级,该道在结构上给不出 |
| `mature` 成熟错价词道 | 有真实搜索量、SERP 被守得弱 | **从第一步就要求取**(量级是准入条件) | 两条都可能 |

两道共用一条硬限制:**KD 与域名指标不得用于判断竞争强弱**。实测三组背离(KD 14 对实测 89、KD 27 对 71、KD 44 对约 85)证明它对此完全失明,竞争强弱只由 G2 完整结构阅读与 G3 三问判定。

### 两条盈利线(G6,任一条过即放行)

| | 收入算式 | 卡在哪 | 容忍量小? |
| --- | --- | --- | --- |
| **订阅线** | 受约束付费者数 × 可行单价 − 获客成本 | 付费者价值 | 能。几千次搜索配五位数赌注也成立 |
| **广告线** | 簇内月量 × 可达位次 CTR ÷ 1000 × niche RPM | 量级 | 不能。查无 = 没量 = 没收入 |

两条都必须算出数、都要写出处,账本记明靠哪条过——**因为 G3 的占位否决是否生效取决于它**:只靠广告线时自然位是唯一入口,位置被占就是真进不来;订阅线能过时可买流量、可直销,占位降级为决策阶段的获客成本论证。

广告线还有一条实测判据:**量级、RPM、弱守三者互相反相关**,是乘性夹逼而非三个独立条件。CPC 高不只是 RPM 代理,它本身就是"这一格里有钱"的证据——有钱就有人守。详见[数据采集指南](xinci-core/数据采集指南.md)的「广告线的选源方法」。

## 候选生命周期

状态只存在于账本,**只能由 `registrar.py` 写入**。共 16 个状态,7 个终态。

```
captured ──G0–G5 全过──→ screened ──登记 expiry──→ tracking ──形成达标──→ formation_confirmed
   │  也是扫描漏斗的排队位                              │                        │
   │                          │窗口以天计(快道)          │复查中闸门翻转           │ xinci-qualify
   ▼                          ▼                        ▼                        ▼
rejected              fast_grab_ready              rejected           qualified / disqualified
                              │                                              │ xinci-decide
                              ▼                                              ▼
                        built / expired              build_ready / pilot_ready / hold / no_site
```

终态:`rejected` / `expired` / `superseded` / `withdrawn` / `built` / `disqualified` / `no_site`。
完整转移表、每条边的证据要求、受控重开规则见[生命周期契约](xinci-core/生命周期契约.md)。

**留痕分界**(容易搞错的一条):还有下一步的、以及走完 G2/G3 深审的候选进**账本**;零成本秒弃与 G1 否决只追加一行**淘汰方向索引**。G1 每轮约 18 条,逐条注册的写入成本会压过本轮真正值钱的 5 次深审。

## 九道闸门

执行顺序 **G0 → G4 → G5 → G1 → G2 → G3**:零成本推理批先行,开浏览器的放后面。G6/G7 在扫描期只做零成本预筛,正式结论在认定阶段。

| 闸门 | 判什么 | 性质 |
| --- | --- | --- |
| **G0** | 合法性与安全 | 硬否决,先于一切 |
| **G1** | Google 首屏是否已把任务做完(featured snippet / 原生计算器 / knowledge panel / AI Overview) | 硬否决,永不复活。**全部闸门中最硬的一道** |
| **G2** | 完整首页结构阅读 | 结构判断 |
| **G3** | exact-task completion:有没有人已经真把这件事做完了 | 三档:`pass` / `veto` / `veto_window_bet` |
| **G4** | 任务能否完全在线完成 | 零成本 |
| **G5** | 陷阱类别检查(9 类) | 零成本;按类别处置档执行 |
| **G6** | 商业闭环 + 两条盈利线算式 | 认定门;含强制的**深审入口预检** |
| **G7** | 耐久性 | 认定门 |
| **G8** | 簇广度 | 认定门 |

定义与判据以[闸门契约](xinci-core/闸门契约.md)为准。**G6 的深审入口预检是最省钱的一道**:开审之前先问"这个任务是否要求有预算的付费者逐个对象重复完成?"答否即弃,不必读任何 SERP。它是 2026-08-23 加的,当天就一次性出清了 11 个厂商 changelog 方向。

## 脚本

| 脚本 | 作用 |
| --- | --- |
| `registrar.py` | 账本的**唯一**状态转移入口,逐项校验证据,原子替换 |
| `screen_index.py` | 淘汰方向索引:批量去重查询与追加。**勿手工编辑,勿整份读进上下文** |
| `dedup_decisions.py` | 疑似重复方向的 same/distinct 裁决登记 |
| `run_controller.py` | xinci-run 的可恢复运行会话控制器 |
| `run_state.py` / `run_manifest.py` | 运行会话与运行清单的共享契约与原子写入 |
| `transaction_journal.py` | 跨文件写入的前滚事务日志 |
| `validate_ledger.py` | 账本不变式 + 运行清单格式校验,有错非零退出 |
| `report_status.py` | 只读状态汇报,不推荐动作、不调度 |
| `data_root.py` | 数据区定位的唯一解析入口,**未配置即拒绝执行** |
| `init_workspace.py` | 创建数据区结构与空账本(幂等),并落盘数据区选择 |
| `build_decision_html.py` | 决策书 md → html 单向生成 |
| `term_normalize.py` / `chinese_labels.py` | 措辞归一化规则 / 中文展示词汇 |

`validate_ledger.py` 是最后一道防线:它同时捕获绕过 registrar 的手工编辑,以及全靠手写的运行清单的字段漂移。**改完任何东西都跑一遍。**

## 怎么开始

数据区首次配置见[仓库根 README](../README.md#第一次使用先定数据区)。配好之后:

| 我想 | 用 |
| --- | --- |
| 一口气跑到出结果 | [xinci-run](xinci-run/SKILL.md)(暗号 `xinci_run`) |
| 看账本现在什么情况 | [xinci-status](xinci-status/SKILL.md) |
| 扫一轮新方向 | [xinci-scan](xinci-scan/SKILL.md) |
| 复查追踪清单 | [xinci-track](xinci-track/SKILL.md) |
| 给候选做认定评分 | [xinci-qualify](xinci-qualify/SKILL.md) |
| 出建站 go/no-go 决策 | [xinci-decide](xinci-decide/SKILL.md) |

每个 skill 的第 0 步都是确认数据区。**脚本不猜数据区在哪**:没配置过就退出码 2 并要求先问用户——账本是整套流程唯一的事实来源,落错地方等于在错的地方留痕。

## 当前状态(2026-08-24,不修饰)

| 指标 | 数 |
| --- | --- |
| 账本候选 | 103(`rejected` 101、`tracking` 1、`captured` 1) |
| 淘汰方向索引 | 1,506 行 |
| 运行清单 | 12 份 |
| 走到过认定(`formation_confirmed` / `qualified`) | **0** |
| **go 决策(可以建站)** | **0** |

**这套流程从未跑通过后半段。** G6/G7/G8、评分契约、决策书生成至今没有在真实候选上执行过一次——它们的判据只在负例上校准过,没有任何真正的正例做对照。

### 已经被实测推翻的假设

- **"新词有窗口期"**——不成立。消费侧答案随对象一起到达(小时到 4 天);企业合规侧答案在义务生效**之前**就到了(家具 DPP 被占位比规则通过早约 4 年)。
- **"没人占位是利好"**——不成立。11 个厂商 changelog 方向 G3 全是 `pass`(首页确实没人专做),但两条盈利线都算不过。**真实原因是这一格里没有钱,所以没人来。**
- **"高 RPM 的地方可以靠广告线切进去"**——接近自相矛盾。CPC 高本身就是有人在经营的证据。

### 唯一确认的假否决

`ppwr-empty-space-ratio`:它的拒绝理由里直接点了赢家的名字(`ppwrcopilot.com`,£49–199/月 订阅 + 一簇免费工具页吃自然流量)。**唯一可行的打法是在已被占位的查询上,做占位者没做的那个工具。**

### 已知缺口

- **G7 / G8 从未回测过**,它们占索引侧否决的相当比例,还停在 G6 修订前的状态。
- **广告线选源方法只跑过一轮**(3 个种子 + 2 个探针),命中率 1/6 进入账本,且那 1 个仍可能死掉。
- **契约里没有"过了弱守但量级待测"这个状态的存放处**——它没有失败的闸门(不该进索引),入门闸门又没跑(不该进账本)。目前暂存在运行清单 notes 里。
- **有一条不对称的护栏**:契约有收尾 E(连续 5 轮漏斗为 0 → 转入闸门校准),但**没有反向那一条**——没有任何规则把执行者从"改尺子"赶回"用尺子"。优化这件事在契约上没有刹车。
