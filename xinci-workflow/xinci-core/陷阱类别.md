# 陷阱类别

陷阱分两型,处置路径不同:

- **SERP 陷阱型**:过 G2、死 G3——SERP 结构看起来诱人(没有大站、没有官方源),但任务早已被免费工具做完。对这型跳过结构阅读,直接验证 G3;失败即弃,不必审计 SERP。
- **前置筛除型**:在"这个发布产生了什么任务"一问就出局,根本产生不了可搜索的任务。对这型不必跑 G3,判定无任务即弃,只记一行进淘汰方向索引。

## 如何追加新类别

每当一次扫描出现新模式:

1. 在本文件追加一节,标题为类别名,并标注类型(SERP 陷阱型 / 前置筛除型);
2. 记录**实际观察**:日期、具体候选词、来源;SERP 陷阱型附 G3 验证中数到的免费工具清单,前置筛除型附判定无任务的依据——不许只写泛化结论;
3. 若该类别还独立命中 G7(无窗口/无耐久),一并记录。

## 类别一:新发布 AI 模型(SERP 陷阱型)

观察于 2026-08-17:`Qwen 3.8 27B`(Hacker News 首页,265 分)与 `GLM-5.3`(Product Hunt)。

结构真诚地诱人,而这正是问题所在。`qwen 3.8 27b vram requirements` 的首页没有大站、没有官方源——Hugging Face 和厂商都没排上;六个主机是一条 Reddit 帖、两家做内容营销的 GPU 云厂商、一个小站、一个工具厂商和 Medium。G2 干净通过。

G3 杀死它。底层任务——"这个模型能不能装进我的 GPU、用哪个量化"——已被免费工具饱和:ApX 的 VRAM 计算器、平台自带的 Hugging Face Space(NyxKrage/LLM-Model-VRAM-Calculator)、能自动检测硬件的 Onyx AI、覆盖 350+ 模型 × 170+ GPU 的社区计算器,外加 Spheron、smcleod.net、logarithmicspirals.com、AIMultiple 和 GitHub 上的开源实现。约八个免费工具,对着"两个即否决"的 G3 线。

两个独立致命的附加发现(G7):

- **没有抢跑窗口**:值得检验的假设是"几天大的模型还没进通用计算器的数据库"——实测 Spheron 在 Llama 4 发布 4 天后就发了显存估算。工具厂商收录新模型以天计。
- **耐久性以周计**:为一个模型版本买的域名随下一版发布而过期;重复任务属于通用工具,那是另一条已被争夺的赛道。

## 类别二:纯品牌名发布(前置筛除型)

观察于 2026-08-17,同一次 Product Hunt 扫描:`Blume`、`Expeditione`、`Vidaya`、`Chert`、`AirAlarm`、`CostLogic`、`HarnessRouter Community Edition`,共七个。

这类发布的搜索需求只有品牌名本身——导航意图,没有一个页面可以完成的任务。死得比陷阱一还早:不用到 G3,在"这个发布产生了什么任务"这一问就出局。识别要点:看它的讨论里除了名字和"这是什么"之外,有没有人在要一个 guide、calculator、converter、checker、tier list 或兼容性答案;没有,就没有词。
