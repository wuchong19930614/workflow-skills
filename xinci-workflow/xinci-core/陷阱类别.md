# 陷阱类别

陷阱按**死因**分两型,按**处置**分两档,两者独立标注在每个类别的标题里。

死因型:

- **SERP 陷阱型**:过 G2、死 G3——SERP 结构看起来诱人(没有大站、没有官方源),但任务早已被免费工具做完。
- **前置筛除型**:在"这个发布产生了什么任务"一问就出局,根本产生不了可搜索的任务;也含"产生了可搜索任务,但既不耐久、付费者也不付费",死在 G6/G7 零成本预筛的情形(类别八起扩入)。

处置档(G5 命中时怎么做,正本见闸门契约「G5:陷阱类别检查」):

- **验证型**：只提供本类别特有检查项，执行与盈利线映射统一按闸门契约 G5 和证据判定契约「现场审计共用步骤」。
- **直接筛除型**：须已有充分结构事实；只否决事实实际影响的任务或盈利线，不能因类别标签跳过六线边界。

注册与留痕只看生命周期契约「留痕分界」；不在类别中重复维护流程。

## 如何追加新类别

每当一次扫描或追踪复查出现新模式,先形成提案并让用户确认。新增/改写本文件属于通用契约变更,不包含在 xinci-run 的标准授权内;连续运行只把提案与实际观察写进运行 notes,不得静默建类。用户确认后:

1. 在本文件追加一节,标题为类别名,标注**死因型**(SERP 陷阱型 / 前置筛除型)与**处置档**(验证型 / 直接筛除型)。处置档按死因型定,两条规则不可混用:
   - **SERP 陷阱型**默认验证型。改标直接筛除型要求 ≥3 次实际观察指向同一结构性死因,且至少跨 2 个日期、2 个来源家族,并包含跨行业或跨发布方的独立样本;同一天、同一行业的三例只能形成待验证假设。计数合并索引侧 `pattern` 与账本侧运行清单 notes。
   - **前置筛除型一律直接筛除型,不受"三次观察"约束**——没有词可搜就没有 SERP 可读、没有 G3 可验证,验证型对它在物理上不成立(类别二即此例)。
2. 记录**实际观察**:日期、具体候选词、来源;SERP 陷阱型附 G3 验证中数到的免费工具清单,前置筛除型附判定无任务的依据——不许只写泛化结论。
3. 若该类别还独立命中 G7(无窗口/无耐久),一并记录。

各类别只保留「识别特征 / 处置档 / 特有检查要点 / 适用边界」，证据出口引用公共契约；不把历史案例写成现行结论;建类过程、实测叙述与被改写的旧版本见闸门校准 §13。

## 类别一:新发布 AI 模型(SERP 陷阱型 · 验证型)

- **识别特征**:方向是刚发布的 AI 模型(HN 首页、Product Hunt、r/LocalLLaMA 当日榜),任务是"这个模型能不能装进我的 GPU、用哪个量化"一类部署需求。首页没有大站、没有官方源(Hugging Face 与厂商都没排上),G2 干净通过。
- **死因**:底层任务已被免费 VRAM 计算器与对比站饱和,过 G2、死 G3。G7 另独立命中两条:①没有抢跑窗口——通用工具收录新模型以天计;②耐久性以周计——为一个模型版本买的域名随下一版发布过期,重复任务属于通用工具那条已被争夺的赛道。
- **处置档**:验证型。收录时差是一个会变的量,必须每次实测、不能引用:2026-04 实测 4 天(Spheron 对 Llama 4),2026-08 实测同一工具(ApX)≥17 天。不要把 4 天当常数——它同时是 G3 判 `veto_window_bet` 时"位置只空几天"的定价依据与 G7「官方答案风险」的依据,用过期的数会同时高估两处风险。
- **检查要点**:
  - 这个新对象是厂商的公共对象(一个答案服务所有人),还是搜索者手上的对象?公共对象不自动否决；核实任务与重复单位，按 G6 逐线判定。类别十二的适用条件不能替代本候选的六线审计。
  - 有没有人被迫用它?答“没有”不能证明无人自愿付费；继续检查实际任务与各适用线，只有全部适用线有否决证据才按 G6 预筛出局。
  - 先核对对象的真实年龄(见数据采集指南「零成本批的一条前置纪律」),别采信信号面的"新"标记。
  - 收录时差与任务反向绑定:有人真部署的模型,发布方页面小时级收录、通用工具天级(实测 4 天 / ≥17 天)、有任务;没人部署的玩具模型,通用工具可能永远不收、但没有任务。"通用工具还没收录"的空位只存在于没有任务的那一行,本类别的 `veto_window_bet` 出口在实践中极难成立(判据不改:临时空位仍记 `veto_window_bet` 而非 `veto`)。
  - 有效 G3 结论先做盈利线条件映射(见序言);不得照历史补记新造 `veto_window_bet`,也不得把决策书交付后的阅读倒写成事前风险确认。
- **不覆盖**:原文未设口子。
- 历史样本见 [陷阱案例历史](history/陷阱案例历史.md) 的同名类别，仅在复核来源时读取。

## 类别二:纯品牌名发布(前置筛除型 · 直接筛除型)

- **识别特征**:发布的搜索需求只有品牌名本身——导航意图,没有一个页面可以完成的任务。看它的讨论里除了名字和"这是什么"之外,有没有人在要一个 guide、calculator、converter、checker、tier list 或兼容性答案;没有,就没有词。
- **死因**:在"这个发布产生了什么任务"这一问就出局,不用到 G3。
- **处置档**:直接筛除型(前置筛除型,不受"三次观察"约束)。
- **检查要点**:讨论里有没有人在要 guide / calculator / converter / checker / tier list / 兼容性答案?没有 → 弃。
- **不覆盖**:讨论里有人明确在要上述工具或答案的,说明任务存在,按正常序列跑 G1/G2/G3。
- 历史样本见 [陷阱案例历史](history/陷阱案例历史.md) 的同名类别，仅在复核来源时读取。

## 类别三:厂商已占位的 B2B 强制任务(SERP 陷阱型 · 验证型)

- **识别特征**:有日期的法规/平台变化 → 受影响付费者明确且有预算(开发者、合规负责人、营销团队)→ 正因为付费者有预算,服务该付费者的厂商早已用内容营销占满 SERP,且发布方常自带完整免费答案。G6 越漂亮,G3 越可能否决——付费者明确只提示优先核实供给，不证明竞争已经完成任务。
- **死因**:过 G2、死 G3。两类待验证的供给风险:①发布方自带模板/计算器/最佳实践的变化,任务已被官方做完,第三方信息站没有位置;②该付费者群体已存在成规模的合规/工具 SaaS 行业(合规软件、ASO 工具、支付网关、律所),其内容机器收录以天计(实测 4 天排上首页),窗口不存在。G7 附带:这类任务的耐久版本通常归工具厂商所有,第三方信息站即便抢到一时位置也无可守之地。
- **处置档**:验证型。独立性要求已凑够(跨 2 日期、2 来源家族、跨行业与发布方),但死因取决于该付费者群体是否已存在对应厂商行业——方向级事实;付费者被迫、有预算、却还没有厂商围着他转的变化确实存在,零成本弃会误杀。只有未来样本证明「有预算的付费者必然已被厂商内容占位」与具体方向无关时,才可再次修订本节改档。
- **检查要点**(在统一现场审计中核实):
  - 发布方有没有自带模板 / 计算器 / 最佳实践?
  - 该付费者群体有没有成规模的合规 / 工具 SaaS 行业?
  - 先按盈利线判断占位否决是否生效:只有当前通过线全部依赖 affiliate / advertising 时判 `veto` 才弃,任一非流量线暂定可行时只记竞争压力。
  - 选源反推:变化面优先探索付费者被迫、但尚无对应厂商行业的群体。
- **不覆盖**:付费者有预算而厂商内容机器尚未围上来的变化——这是本类别放行的空间。与类别七在 `harvest` 一例重叠:类别三讲"谁在写",类别七讲"写的是哪一格",命中任一即按验证型跑 G3。
- 历史样本见 [陷阱案例历史](history/陷阱案例历史.md) 的同名类别，仅在复核来源时读取。

## 类别四:厂商 release note / changelog 衍生任务(SERP 陷阱型 · 验证型)

- **识别特征**:来自厂商变更公告，任务是如何使用或配置新功能。
- **处置档**:验证型。来源身份和官方文档存在不证明任务完成；按公共证据契约核实实际输入、输出、剩余任务及适用盈利线，再映射到 G1/G3/G6。
- **检查顺序**:先做商业预筛，再访问具体文档或工具。纯说明与能执行的工具分开记录，仍补齐 G1/G2；相同 SERP 与覆盖证据复用。
- **不覆盖**:跨厂商迁移、批处理、监控或集成等剩余任务按各自任务重新审计，不能继承原任务的通过结论。
- 历史直接筛除依据与样本见 [陷阱案例历史](history/陷阱案例历史.md) 类别四。

## 类别五:信号面的观点、新闻与旧文回流(前置筛除型 · 直接筛除型)

- **识别特征**:方向来自 Hacker News / Reddit 一类社区信号面的高分条目,而条目本身是随笔、观点评论、时事新闻、科研报道、事故复盘,或多年前旧文回流。
- **死因**:高分等于讨论热度,不等于任务存在——信号面的排序机制奖励可争论、可共鸣、可转发的内容,而"有人被迫重复完成"的任务安静无聊;分数越高往往越是前者。与类别二同理,在「这个帖子产生了什么任务」一问就出局。
- **处置档**:直接筛除型(前置筛除型,不受"三次观察"约束)。
- **检查要点**:
  - 这个条目让谁完成什么具体任务?确无页面可完成的任务才弃；已有按次付费事件时不因缺复购归入本类。
  - 判之前先按类别二的识别要点扫一眼讨论里有没有人在要工具。
- **不覆盖**:①条目虽是新闻/事故,但牵出了有日期的强制变化并落到具体付费者身上——属类别三,仍要跑 G3 验证;②社区帖里明确有人在要 guide、calculator、converter、checker、tier list 或兼容性答案——任务存在,按正常序列跑 G1/G2/G3。
- 历史样本见 [陷阱案例历史](history/陷阱案例历史.md) 的同名类别，仅在复核来源时读取。

## 类别六:管辖机构自维护的对象全集权威查询(SERP 陷阱型 · 验证型)

- **识别特征**:方向来自有日期的法规/标准变化(Federal Register、TTB、APHIS、NPS 一类),而这个变化落在一个已有权威全集查询覆盖的对象类上——发证或管辖机构为该对象类的每一个成员维护一页,或第三方已建成覆盖该对象全集的数据库站。新对象一进入全集,就自动获得一个永久收录、稳定排名的页面。
- **死因**:"被迫任务"与"位置空着"是两件事。有全集维护者,第三方信息站从第一天起就没有位置;这类页面通常是机构官方域的内页,G2 看不出异常——过 G2、死 G3。联邦公报全集的自动镜像(federalregister.gov、govinfo.gov、regulations.justia.com、reginfo.gov)让任何一条规则一发布就自动获得多个永久收录页面。
- **处置档**:验证型,不得零成本弃。是否存在全集维护者是这个对象类的事实,不是变化本身的属性——确实存在没人维护全集的对象类,零成本弃会误杀。(六例同日、同来源家族,亦不满足改档独立性要求。)
- **检查要点**:
  - 措辞落在哪一格?落在「这条规则说了什么 / 要求什么」或派生问题时，都要实测具体对象的任务覆盖；镜像或维护者存在只提示检查，不自动产生 veto。
  - 这个对象类有没有全集维护者?再实测一个具体对象的查询(G3 验证)。
  - "机构没有中央清单"不等于"位置空着":机构常按对象分页维护,分散的每园页合起来就是全集。要问的不是"有没有一张总表",而是"这个对象自己有没有一页权威答案"。
- **不覆盖**:①对象类本身很新、还没有任何全集维护者的——那才是这条赛道要找的东西;②任务是跨管辖区横向比较的(各机构只维护自己那一格),按正常序列跑 G1/G2/G3,横向那一格的死因另见类别七与类别十二。与类别十是同一枚硬币的两面:本类别是位置被占(死 G3),类别十是没有付费需求(死 G6),可同时命中但死因分开写。
- 历史样本见 [陷阱案例历史](history/陷阱案例历史.md) 的同名类别，仅在复核来源时读取。

## 类别七:跨厂商横向对比与迁移(SERP 陷阱型 · 验证型)

- **识别特征**:措辞形如 `alternatives to X`、`X vs Y`、`migrate off X`、`从 A 平台迁到 B 平台`。诱惑在于 X 的厂商确实不会写它,看起来无人占位。
- **死因**:钳形,两侧都不通。本类别堵住类别四与类别六留下的"横向那一半"口子——横向那一半有自己的全集维护者,只是维护者不是发布方。
  - X 的市场足够大 → 横向对比本身已成为一个对象类,并有全集维护者(替代品目录站、分析机构榜单、社区 awesome 清单、专做成对对比的内容站、竞品自建对比页),覆盖每一个有真实市场的 X 与每一对 X/Y,收录以天计。
  - X 的市场小到没人做目录 → subscription 与 advertising 往往一起塌陷,但这不是六线全灭的充分条件,仍须检查 lead_generation / affiliate / transaction / paid_report,少量高价值需求可能让其中一线成立。
- **处置档**:验证型(三例同日,不满足改档所需的 ≥2 个日期)。
- **检查要点**(在统一现场审计中检查以下供给者是否完成目标任务):
  - 有没有替代品目录站?
  - 有没有分析机构榜单或社区 awesome 清单?
  - 有没有专做成对对比的内容站?
- **不覆盖**:横向任务的一侧是尚无市场的新对象(例如刚发布三天、还没进任何目录的东西 vs 一个老对象)——钳形第一侧暂时不成立,属窗口赌注的判断范围,按 G3 三分去测收录时差,不直接判 veto。
- 历史样本见 [陷阱案例历史](history/陷阱案例历史.md) 的同名类别，仅在复核来源时读取。

## 类别八:厂商不利的开关型任务(验证型)

- **检查要点**:核实关闭、退出、删除任务是否有批量办理、持续监控或按次服务需求。单个用户只执行一次不证明所有盈利线不成立；官方答案在途须有日期与任务覆盖证据。
- **处置档**:验证型；先按 G6/G7 做预筛，再按公共证据契约核实需要的供给事实。已有充分证据可复用；未知不淘汰，不增加类别特有硬门。
- **出口**:没有具体任务、六线全部有否决证据或对应闸门产生有效否决时，按实际闸门留痕；否则继续正常序列。G1/G2 不因类别验证而豁免。
- 历史样本与旧处置见 [陷阱案例历史](history/陷阱案例历史.md) 类别八。

## 类别九:零回答与悬赏问题(验证型)

- **检查要点**:零回答只说明该处尚无回答，不证明需求孤立；查独立提问、使用场景与付费事件。浏览量偏小只影响依赖流量的线路，不能否决报告或线索模式。
- **处置档**:验证型；先按 G6/G7 做预筛，再按公共证据契约核实需要的供给事实。已有充分证据可复用；未知不淘汰，不增加类别特有硬门。
- **出口**:没有具体任务、六线全部有否决证据或对应闸门产生有效否决时，按实际闸门留痕；否则继续正常序列。G1/G2 不因类别验证而豁免。
- 历史样本与旧处置见 [陷阱案例历史](history/陷阱案例历史.md) 类别九。

## 类别十:参数发布方连带供给答案(供给验证型)

- **识别特征**:义务是「按官方公布的参数,对每个对象算出一个数或做出一个判定」——每个商品码的原产地、每吨货的隐含排放、每个航段的应税福利、每批进口物质的税额。逐对象重复、付费者明确、有生效日,七条正向选源信号往往一路全中。
- **待验证风险**：官方参数可能附带计算器、默认值或简化申报路径，行业软件也可能已覆盖任务。但供给者有动机不等于已经完成任务。
- **处置档**：验证型。打开实际工具、公式或默认路径，记录输入对象、完成的任务与未覆盖部分；按[证据判定契约](证据判定契约.md)检查剩余任务及逐线变现。不得因任一工具存在就直接否决。已有证据足够时复用，不重复搜索。
- **优先检查**：发证机关工具、法条简化路径、协会计算器、已有软件的具体功能。pattern 保留「参数发布方连带供给答案」，只描述经验证的死因，不自动决定 gate。
- **不覆盖**(三条口子都是实测出来的,不要顺手扩大):
  1. 参数不由单一一方公布的——同一件事跨两个管辖区、各自公布各自的参数,横向那一半没有天然的连带供给者(`uk-machinery-safety-gb-ni-2026`:自助工具 0 个,占位者只写文章,进 tracking)。
  2. 分歧或对象类已经成熟到第三方建起全集数据库的——属类别六,死因是位置被占(`uk-reach-amendment-2026`:存续五年,ChemLinked 逐法规建页,判 veto)。与上一条合起来的时间判据:决定位置是否还空着的不是"是不是跨管辖区",而是这个分歧本身有多新。
  3. 任务根本不需要工具的——是 G6 第②③项自己塌陷,写 reason 时不要挂到本类别名下(`uk-protect-duty-notification-2026` 的 tier 判一次即定;`uk-automated-vehicle-marketing-terms-2026` 是 8 项固定短清单)。
- 历史样本见 [陷阱案例历史](history/陷阱案例历史.md) 的同名类别，仅在复核来源时读取。

## 类别十一:持牌机构合规义务(前置筛除型 · 直接筛除型)

- **识别特征**:义务来自金融监管机构(FCA、PRA、SEC、HMRC 的机构条线、各国央行与证监会),受约束主体是持牌或受监管机构——银行、保险公司、授权基金管理人、券商、支付机构。措辞形如「按 XX 规则分类/评估/申报」。
- **待验证风险**：规则全集与律所内容可能覆盖查询；签字或认证要求可能限制交付。供给者身份、牌照身份、法律责任本身均不证明六线全灭。
- **处置档**：直接筛除型，仅在逐线检查得到充分否决时生效，类别身份不是命中判据。按闸门契约 G6 的自助交付法律效力规则核实具体交付是否声称替代签字；法律效力事实仅否决依赖该效力的线路。
- **检查要点**：非认证报告、线索、办理辅助或供机构使用的软件是否仍有合法可交付任务？全部适用线有否决证据才按 G6 预筛结束；未知按公共证据契约保留，其他线可行则继续现场审计。

- **不覆盖**:
  1. 受约束主体是普通企业、且判错代价只是钱与时间的——一般制造商、进口商、雇主、物业占用者,没有合规部门也请不起国际律所,按正常序列跑 G1/G2/G3。普通主体同样可能受签字效力约束，仍按实际交付逐线判断。
  2. 任务是给持牌机构的交易对手做判断的(例如"我这家小企业发的这个东西,对方银行会怎么归类")——付费者是没有合规部门的那一侧,不适用本类别。
- 历史样本见 [陷阱案例历史](history/陷阱案例历史.md) 的同名类别，仅在复核来源时读取。

## 类别十二:横向汇总型任务已被 AI Overview 接管(SERP 陷阱型 · 验证型)

- **识别特征**:任务的答案能由 Google 首屏 AI Overview 当场合成或转交。诱惑真实(义务新、付费者有预算、没有一方有动机做那张表),但这正是生成式摘要最擅长的形态。三种形态:
  - ①横向汇总——「同一件事在 N 个管辖区 / N 个平台分别怎么规定」的对照表;
  - ②逐对象判定,但规则是已公布的少分支决策树,输入在搜索者脑子里(我是制造商还是进口商?我在不在加州?);
  - ③逐对象计算,首屏把方法、公式与表给完后主动索要对象参数并提出代算。
  - 本类别关的是类别四、六、十留下的"横向那一半没有天然供给者"的口子——占位者不是某个站,是首屏本身。
- **死因**:"没人做那张表"与"那张表很难做"是两件事。原料全是公开且已收录的官方页,合成成本对 AI Overview 接近零,位置被首屏本身占住,任何内容质量都赢不了(G1)。把参数直接写进查询也逃不掉——长尾化不是逃生路线。
  - 变体:首屏不合成而是转交——点名一个官方登记册说"去那里看"(索引 `pattern` = `AI Overview 指路官方转化登记册`,1 例,待验证;它是 IED 2.0 那一格的事实,不是转化矩阵族的通性,逐词实测,不得据此预判)。
- **处置档**:验证型,不得零成本弃。同一题材换一个措辞结论会翻转(措辞级事实),G1 本来就永不跳过;本类别的实际作用是排序纪律,不是零成本筛除权。尚未实测的一半(待验证,见校准 §16「待验证清单」):搜索者接受首屏代算邀请、在 AI Mode 提交参数后,答案对不对、算不算把任务做完——这是处置为验证型的真正理由。
- **检查要点**(挑措辞用的三问合取,答"是 / 是 / 否"才留下;一个方向的多个措辞要一起测,横向措辞死了不等于这个义务死了):
  1. 措辞指向搜索者手上的某个对象(my mixture / this SKU / 我这台机器),而不是问规则、公式或表本身?——问表或公式的措辞首屏当场给全(`battery regulation recycled content calculation methodology`、`cpr product family list 2026`)。
  2. 把那个对象解析成答案,必须对一张大表查行或做一次计算,而不是走一棵分支数得过来的决策树?——问的是"列出规则算不算把任务做完"。小表(4–5 行默认因子表、一个公开罚款率)列出即完成,归条件 1 那半边。
  3. 那份对象参数,官方有没有一个按对象返回答案的系统?有 → 路由类别六 / 类别十三核实具体覆盖与剩余任务，结论按公共证据契约映射到 G1/G3/G6，不凭系统存在否决。
  - 不得采用的简化判据:"措辞里有没有一个 AI Overview 拿不到的对象,有就活"——`california textile epr am i a producer` 的 `am i` 正是首屏拿不到的对象引用,首屏仍把五级 producer 层次列全。
  - 三问都过的正例:`does my mixture need reclassification gb clp`(逐物质对 GB MCL 清单查行再按浓度限值加和)、`cpr avcp system 1+ 2+ 3 4 which applies`(四维查 AVCP 表)。
  - 豁免口②(转化矩阵:横向那一半要逐格追踪当期状态、且 AI Overview 实测给不出完整矩阵)前三项用于选择值得现场核实的查询，第 4 项只提示检索来源，不构成注册门槛:
    1. 转化截止日在当期(NTM 已有部分成员国通报、但远未通报齐);
    2. 有可识别付费者及适用于实际盈利线的收入证据（官方计数不是全局前提）;
    3. 按实际交付核实责任边界；刑责不能替代类别十一要求的六线检查;
    4. 服务商、律所或 NGO 的核心客群画像仅作供给检索提示，不参与硬门；前三项也不能代替现场 G1 与任务覆盖验证。
  - 是否已经存在免费 tracker，必须访问具体实现并检查覆盖；“某类服务商有动机提供”不能授权不注册。旧第 4 条仅有少量样本，不再作为通用前置筛。
- **不覆盖**:①三问都过的逐对象判定——那正是这条赛道要找的;②经现场验证仍有任务缺口的转化矩阵,且 G1 实测首屏给不出完整矩阵的——G1 记 pass 后回正常序列跑 G2/G3。
- 历史样本见 [陷阱案例历史](history/陷阱案例历史.md) 的同名类别，仅在复核来源时读取。

## 类别十三:发证机关自带吃对象的计算工具(供给验证型)

- **识别特征**:有日期的法规变化 → 受影响付费者明确、任务确实是"拿我这个对象去查一张大表或算一个数"(完全符合类别十二合取的两个条件)→ 但已有主体发了一个吃你的对象、直接出结果的东西。
  - 交付形态不限网页工具,更常见的是不起眼的形态:一份 Excel、一张 correlation table、一个在线申请系统的下拉、PDF 里附的计算模板、一份逐对象的判定解释例 / 对象非对象一览 / 附加声明 checklist、covered-materials 定义文档、免费判定软件或数据库、设计电子表格、体制强制设立的登记册。
- **待验证风险**：官方或受理方可能已有对象工具；必须核实实际任务覆盖，不能从身份或收数职责推出供给存在。

## 类别十四:新旧法规过渡条款(验证型)

- **检查要点**:读取具体过渡条款，区分统一时间线与逐对象附加条件。维度少不自动否决；核实官方答案是否完成任务，以及监控、审计或报告是否有剩余需求。
- **处置档**:验证型；先按 G6/G7 做预筛，再按公共证据契约核实需要的供给事实。已有充分证据可复用；未知不淘汰，不增加类别特有硬门。
- **出口**:没有具体任务、六线全部有否决证据或对应闸门产生有效否决时，按实际闸门留痕；否则继续正常序列。G1/G2 不因类别验证而豁免。
- 历史样本与旧处置见 [陷阱案例历史](history/陷阱案例历史.md) 类别十四。
