# 闸门校准:反向回测记录

**这份文件解决闸门契约的一个结构性缺陷:它的每一条规则都是从失败里写出来的,从来没有对照过一个成功案例。**

> 本文件按时间追加,保留当时规则以便审计；同一主题出现多次修订时,以后面的日期为准。第 7 节“两条盈利线”与第 9 节“方案 C”都是两线时代(2026-08-23 / 08-24)的历史版本；2026-09-02 已扩为六线，且单项入口条件不再能一票否决整候选。**当前 G6 口径只看[闸门契约.md](闸门契约.md) G6 一节**,本文件任何一节都不是现行口径;第 9 节里保留的是方案 C 的三个机制(订阅结构硬门 / 广告量级硬门 / `income_score ≥1`),这三点现已并入六线契约,但其“通过线只有 subscription / advertising”的表述已过期。

## 为什么需要它

2026-08-22 查账本得到的事实:

| 项 | 数 |
| --- | --- |
| 有史以来进过账本的候选 | 98 |
| 曾出闸到 `screened` | 25 |
| 曾进入 `tracking` | 50 |
| 曾到达 `formation_confirmed` | **0** |
| 曾到达 `qualified` / 任一 go 状态 | **0** |

也就是说 **G6 商业闭环、G7 耐久性、G8 簇广度、100 分制评分、决策书生成这后半段,从未运行过一次**。闸门契约自述"规则是从真实损失里写出来的",陷阱类别.md 的九个类别全部来自否决案例。

一个只有单向反馈的筛选系统必然单调收紧:每次误放坏方向就加一条规则,而**误杀好方向没有任何机制会告诉它**。更要紧的是,它**无法区分「市场确实关着」与「我的闸门太紧」**,因为它从未见过一个真阳性。

反向回测就是补这个锚点:拿确实做成了的东西,按它上线当天的状态倒回去过一遍闸门,看会不会被否掉;若会,则精确定位是哪一道。

## 方法

看不到过去的 SERP,但可以用两个可得事实倒推:

1. **竞品页面的发布日期**。今天为某查询排名的结果,凡日期早于目标站上线日的,就是它上线时已存在的竞争。
2. **同一 SERP 上新进者的到达时间序列**。若一条查询在数月内持续放进新页面且各自都拿到首页,则"位置已被占满、任何内容质量都抢不回来"这个前提是可证伪的。

回测对象不必外求:**本工作流三次运行(2026-08-21 至 08-22)的否决记录里,已经逐条写下了赢家的域名——只是当时把它们标成了「竞争」,而不是「存在性证明」。**

## 案例一:`ppwr-empty-space-ratio` —— 已证实的误杀

账本原始记录(2026-08-18 由 xinci-run 转 rejected):

- **term**:`ppwr empty space ratio`
- **task**:`向欧盟市场投放包装的经营者计算并证明自己的箱型空隙率合规`

2026-08-22 现场核实这两个被点名的"占位者"是什么:

| 站点 | 实际情况(现场读取) |
| --- | --- |
| **ppwrcopilot.com** | 在跑的付费 SaaS。定价 **£49–£199/月**,另有 £245–£545 的 72 小时人工审阅服务。首页自述「**890+ 份包装档案,190+ 家机构**」。Stripe 支付、英国注册公司、ICO 注册 ZB974172。核心功能面板直接叫 **Article 24 empty space**,显示"实测空隙率与所选包装类别适用的规则"。站点已完整收录(pricing / methodology / security / disclaimer / blog / regulatory-updates 各页齐备) |

**对照结论:**

1. 工作流**正确识别了任务**(计算并证明空隙率合规)
2. 工作流**正确识别了付费者**(向欧盟投放包装的经营者)
3. 工作流**正确识别了市场是真的**——三个专用站同时出现,正是需求存在的最强信号
4. 然后它**因为「已经有人在卖」而否决了这个方向**

而 ppwrcopilot.com 最低档 £49/月 × 190 家机构 ≈ £9,300/月,是 G6 那条 **$200/月门槛的 40 倍以上**。

**这是一次可证实的误杀,而不是推测。** 被 G3 数进否决线的第一个"免费结果",就是这个niche 的赢家本人。

## 诊断

### 一、G3 量的是占位,不是可打败性

G3 的否决线问的是「有没有 ≥2 个免费结果把任务做完」。在 2026 年的互联网上,**任何有商业价值的查询都满足这个条件**——包括那些值得做的。所以 G3 的 veto 并不区分:

- 「这个位置守得住,别来」
- 「这个位置有人赚钱,说明市场是真的」

案例一说明这两件事在数据上长得一模一样。**一次 G3 否决与一次市场验证,是同一个观察。** 反过来说:若某个 niche 里没人建站,那才是需求不存在的证据。

### 二、G3 承接了本该属于 G2 的教训

G3 的规则出处是一次真实损失:有人用排名第一的结果判断整个市场,结论"竞争弱",而真正占据该任务的站在第二页。

那次损失教的是「**必须读满第一页、必要时到第二页**」——这正是 G2 的内容,而 G2 确实是对的、也确实在起作用(本次三次运行里 G2 拦下 5 个)。但那条教训被同时写成了 G3 的**数量否决线**,而"我漏看了第二页"与"有两个实现所以别做"是两个不同的结论。

### 三、工作流只会评估一种商业模式

案例一与案例二里的赢家全部是**带付费墙的产品**(ppwrcopilot £49–199/月、ppwrconnect €29/月、keito.ai、Voltasis、TrackingTime、Rize、Productive),它们把查询当获客渠道之一,收入并不完全依赖赢下 SERP。

G6 的第三项名义上允许这种模式(「自助变现路径」),但 G3 的执行方式假定**排名位置是唯一资产**。因此工作流在结构上看不见"做一个别人愿意付钱的工具,排名只是渠道之一"这条路——而这恰恰是本次回测里唯一验证到的成功路径。

### 四、哪些 G3 否决是站得住的,以及为什么

必须公平记下反例。`go-127-generic-methods` 那次 G3 否决(go.dev 官方 release notes 加六家讲解站,日期跨 2026-04 至 08)应当维持,但**真正的否决理由不是占位**:

- 付费者是开发者,读完即走,不买东西
- 没有可卖的工具(泛型方法的语义由语言规范定义,不存在"帮你算一下"的产品)

也就是说,**这一类的决定性闸门本该是 G6,不是 G3**。同理,`aurora-80k`(8 万参数玩具模型)也是 G6 死因。

**判别法**:当 G3 是决定性闸门时,大概率是误杀;当 G6 是决定性闸门时(没有付费者、没有可卖之物),否决通常成立。账本里 53 个 G3-binding 的否决,都应按这条重审。

## 修订建议

1. **把 G3 拆成两层。** 硬否决只保留给「≥2 个**完成任务的工具或完整实现**,且属于同一商业模式的直接竞争」;「≥2 篇提到答案的文章/律所提示/论坛线程」降级为**评分扣分项**,不再一票否决。理由:文章提到答案与工具替你完成任务,不是一回事,而后者才是 G3 原始案例(显存计算器)的形态。

2. **在 G3 之后增加一道「可打败性」判据**,取代单纯的占位计数。可用的零成本问句:占位者是**综合站的一个栏目**还是**专做这件事的站**?它的答案是**通用的**还是**按对象/按管辖区做到底的**?近三个月**有没有新进者拿到首页**(案例二的时间序列法)?三问里有两问指向"占位者不专、答案不深、SERP 仍在放人",则不否决。

3. **把 $200/月从硬闸改为评分输入**,并给出一个真正值得投入的量级。现值同时犯两个错:低到不值得任何人为它工作,又硬到会杀掉真 niche。

4. **让工作流显式区分两种商业模式**:①靠排名吃流量的内容站(G3 的占位判据对它有意义);②带付费墙的工具/产品(排名是渠道之一,占位不构成否决)。候选注册时就标明打算走哪一种,G3 按模式分档执行。

5. **加一条元规则:连续 N 轮 0 存活即停止扫描,转去审闸门。** 现契约只禁止"因为找不到就停",却没有"一直找不到就该怀疑筛子"的机制。本次 18 轮 0 存活本该在第 5 轮左右触发校准,而不是第 19 轮。

## 结论二:真正的问题在上游,不在闸门

47 个贵候选的来源分布:

| 来源家族 | 数量 | 占比 | 产出真实生意 |
| --- | --- | --- | --- |
| 厂商 changelog / 开发者公告 | **41** | **87%** | 0 |
| 法规(对企业施加合规义务) | 3 | 6% | **1** |
| 社区信号面 | 3 | 6% | 0 |

**深审预算的 87% 花在一个结构上不可能通过 G6 的来源家族上。** "怎么配这个新功能"没有付费者、没有可卖之物——这批候选在 G3 运行之前就已经死了,G3 只是最后签字的那道门。这解释了为什么 61% 的贵候选死于 G3:**不是 G3 杀伤过强,是送到它面前的东西本来就活不了。**

而唯一产出真实生意的来源家族,总共只被喂进 3 条。**1/3 与 0/41 的对比,是这份回测最可操作的数字。**

(补记:类别四「厂商 release note / changelog 衍生任务」已于 2026-08-21 归并为直接筛除型,正是为了掐掉这 41 条的来源。所以这个问题在扫描侧已自我修正;**剩下的缺口是没有正向选择器**——工作流有 9 个负向类别,0 个正向选择器,只会否决,不会瞄准。)

## 结论三:第一个正向选择器(从唯一确证的成功案例反推)

`ppwr-empty-space-ratio` 是账本里唯一被证明对应真实生意的方向。把它的形态拆出来,当时得到七条可检验的判据,并提出“全部命中才进深审”。**这里保留的是当时规则,不是现行硬门**:后续前瞻检验证明样本太小,现行《数据采集指南》已将它们改为“七条正向选源信号”,只用于排序,不在 G0–G8 之外加门:

1. **义务施加给企业**——不是消费者(nps 一例:付费者是买车的人,零售商有结构性优势)、不是政府机构、不是读文档的个人开发者
2. **要求逐个对象重复计算或证明**——每个 SKU / 场址 / 批次 / 市场各算一次,不是读一次就完(PPWR:每个 SKU 的空隙率、可回收性分级、符合性声明)
3. **存在多管辖区差异**,使"汇总本身"成为资产(PPWR:27 个欧盟成员国 + 英国各有本国要求与押金制度)
4. **有明确生效日**,产生时间压力(PPWR:2026-08-12 起适用)
5. **违规有实质后果**(罚款、禁售、审计风险),付费者因此愿意掏钱
6. **官方发布法条但不提供逐对象的计算工具**——欧盟发法规,不发计算器;NPS 发每园页面,不发合并清单
7. **受约束企业数 × 可行单价能过 G6**——这条是 sablefish 的死因(持证渔民数百量级),必须单独估一次

第 6 条要配一句警告(nps 与 sablefish 都栽在这里):**官方不提供工具 ≠ 位置空着**。要再问一句"谁有动机做这个汇总"——若答案是**卖相关产品的厂商**(电动车零售商、合规软件商),他们会用内容营销占住它,且比纯信息站更有优势。PPWR 之所以还开着,是因为占位者本身也是**随这次变化才出现的小而专的新站**,而不是已成规模的厂商。

由此得到 G3 之后那道「可打败性」判据最有用的一问:

> **占位者是"随这次变化才出现的小而专的站",还是"已有的成规模厂商/零售商"?**
> 前者 = 市场已验证且仍在放人(PPWR);后者 = 市场已验证但对手有结构性优势(apple/k-ID、nps/Upway)。

## 这一轮仍未做的事

- 未回测 G6/G7(索引侧 70% 的淘汰归它们)。按本轮判别法,那一侧的否决更可能成立,但这是推论不是实测。
- 上面 47 条里,39 条厂商 changelog 是**按任务措辞零成本判定**"读完即走、无可卖之物"的,没有逐条现场复核。若要更严,应抽样 5 条实测。
- 当时所称正向选择器的七条判据只从 **1 个**成功案例反推,样本量为一。它是假设,不是定律;需要在后续运行中按它选源,并记录命中率来检验。

# 第三轮:按正向选择器反选一次,检验它能否复现

2026-08-22 续做。上一节当时所称的七条判据只从 1 个成功案例反推,样本量为一。本轮按它主动选源,看能否复现。

## 假设

PPWR 不是孤例,而是一个家族:**欧盟的产品合规法规系统性地制造「每个 SKU × 每个成员国」的义务,有明确生效日,而委员会只发法条、不发计算器。** 若选择器成立,那么这个家族的其他成员也应该已经出现同构的小而专的付费工具。

## 复现结果:2/2

按判据枚举家族成员并现场核实其中最符合的一个:

| 义务 | 生效日 | 现场核实到的占位者 |
| --- | --- | --- |
| **PPWR**(包装与包装废弃物) | 2026-08-12 已适用 | `ppwrcopilot.com` £49–199/月、190+ 机构;`ppwrconnect.com` €29/月起(上一节已核实) |
| **DPP / ESPR**(数字产品护照) | 首个强制期 2027-02;纺织品 2028/2029 | **`passportcraft.com`** —— 单一义务专用工具,免费起步转付费,24+ 篇合规指南(2026-02/03/07),做了中文本地化直打中国出口商,另有法国专属义务横幅;**付费者规模写在它自己首页:影响超过 160,000 家向欧洲销售的纺织企业** |
| CRA(网络韧性法) | 2027-12-11 | `continueops.com`(搜索结果列表带 4.8 分 / 24 评价,即已有产品形态) |
| 通用多法规 | — | `complir.io`、`getreadycompliance.eu`、`spacegoats.io`(跨境卖家合规服务) |

**选择器复现成立。** 它准确地指向了"建站者确实在建"的地方。

## 但要说清它到底在做什么

选择器**不识别空位,它识别已验证的市场**。按上一节对 G3 的批评,这恰恰是应当据以行动的信号,而不是回避的信号——PPWR 一案里三个专用站同时存在且共存,说明这类市场能容纳多个进入者。

因此正确的用法是:**用选择器定位家族,再用「占位者是小而专的新站还是成规模厂商」判断该家族成员还能不能进**,而不是用 G3 的数量线一票否决。

## 由此修正一条我自己写错的判据

2026-08-21 第 6 轮我从加州替换轮胎能效标准一案归纳出 pattern「生效日远在未来的变化」,判据是"新闻在今天、任务在几年后,今天没人被迫做任何事"。

**这条对企业合规付费者是错的。** PassportCraft 在 2026 年初就在为 2027-02 至 2029 的义务发内容并卖工具;ppwrcopilot 也在 2026-08-12 生效日之前就已上线并积累到 190+ 机构。企业面对有日期的合规义务会**提前 12–24 个月准备**,所以提前入场正是赢家的做法。

加州轮胎那条之所以仍然成立,是因为**付费者是消费者**——消费者不为 2029 年的换胎规则提前做任何事。

修正后的判据要加一个付费者类型限定:

> **生效日远在未来 + 付费者是消费者 → 任务还没出生,零成本弃。**
> **生效日远在未来 + 付费者是受义务约束的企业 → 这正是入场窗口,不构成否决**;此时该问的是"离生效还有多久"(12–24 个月最佳)与"有没有人已经在建"。

## 本轮为何不往淘汰索引写否决

按现行 G3,上面 12 条枚举出的义务都会被判 veto(每一条都已有占位者)。**本轮刻意不写**,理由有二:

1. 淘汰索引的条目是永久的("这些方向都已终结,永不复活")。用一道**正在被证明有校准问题**的闸门去写永久否决,会把错误固化。
2. 本轮的性质是**校准测试**,不是扫描轮。它的产出是这份文档,不是账本候选。运行清单的 funnel 因此五项全 0,notes 记明原因。

这 12 条(DPP、CRA、电池法规/电池护照、强迫劳动法规、GPSR、CBAM、各成员国 EPR 注册、玩具安全法规、AI 法案、数据法案、新产品责任指令、EUDR)作为**正向选择器的候选池**留在本文档中,待闸门修订后再决定如何进账本。

## 这一轮仍未做的事

- 只现场核实了 2 个家族成员(PPWR、DPP),CRA 只看到搜索结果里的产品化迹象,未打开核实。
- 未估算任何家族成员的**剩余容量**——"能容纳多个进入者"是从 PPWR 三站共存推断的,不是实测。
- 未检验判据 7(受约束企业数 × 可行单价)的下限在哪:PPWR 190+ 机构与 DPP 160,000 家纺织企业都远超 $200/月,而 sablefish 的数百持证渔民不够;两者之间的分界线未测。

# 第四轮:窗口到底什么时候开?——一次把整个调查闭环的证伪

2026-08-22/23 续做。第三轮修正后的时机判据是"生效日前 12–24 个月是入场窗口"。本轮两次测量把它也推翻了,并给出了整个调查最终的统一结论。

## 测量一:生效前 6 个月 → 已占满

电池护照(欧盟电池法规,2027-02-18 强制)是家族里生效最近、计算性最强的一员(每个电池型号的碳足迹、再生料比例、尽职调查数据)。现场核实:

- `circularise.com/battery-passport` —— 专门产品页,自述"为 2027 合规准备好的供应商数据、QR 访问、碳足迹证据"
- `digiprodpass.com` —— 2026-01-08 的电池护照期限文
- `dpp-tool.com` —— 2026-02-22 的电池护照指南
- `makersite.io` —— 可做 LCA 算碳足迹
- `thebatterypass.eu` —— 碳足迹核算规则文档
- 另有 `crunch-is.com` 的合规清单与 iTAC Software AG 这类工业软件商

## 测量二:规则还不存在 → **同样已占满**

家具 DPP 的**授权法案预计 2028 年才定稿**,即此刻规则尚未具体化、义务无法履行。现场核实:

- `renoon.com/digital-product-passport-furniture` —— 家具 DPP 专页
- `digiprodpass.com` —— "ESPR 在 2026 年会怎样影响家具制造商"
- `bluestonepim.com`(2026-03-04)、`myproductpassport.eu`(2025-11-27)、`productipedia.com`、`asuene.com`(2026-03-03)、SAP(2026-03-24)
- **`tributech.io` 的 ESPR DPP 文章日期是 2024-12-03** —— 比家具授权法案预期定稿早约四年

## 统一结论:两侧都没有窗口,但原因相反

| 方向类型 | 答案何时到位 | 相对于"任务成立" |
| --- | --- | --- |
| 消费者/开发者面(前三次运行 18 轮测到的) | 小时到数天 | **与对象同时到** |
| 企业合规面(本轮测到的) | 规则公布甚至**尚未公布**时 | **在义务出生之前就到** |

也就是说:**位置不是在任务出现之后被占的,而是在任务出现之前就被占的**——因为"预期"本身就可变现(卖 PIM、卖咨询、卖工具的都有动机提前写)。

这解释了为什么本工作流三次运行 18 轮、682 个方向、0 存活:**它在寻找一个"措辞已出现、答案未出现"的时间差,而这个时间差在两类市场里都不存在。**

## 但恰恰在这里出现了唯一可行的玩法

看清占位者是**什么东西**:家具 DPP 那一批里,`bluestonepim.com` 是 PIM 软件商的内容营销,SAP、asuene、Tributech 同理,`productipedia.com` 是资源汇总。**它们写的是解释性文章,不是能替你干活的工具。**

而 `ppwrcopilot.com` 做的正相反:别人写"PPWR 要求你算空隙率",它做了**按 SKU 生成带法条引用的档案 PDF 的生成器**,并按 £49–199/月收费,拿到 190+ 家机构。

**结论:唯一可行的玩法不是"找一个没人占的查询",而是"在一个已被占的查询上,做出占位者没做的那个工具"。**

这与本文档第一节提出的 G3 修订(硬否决只留给「≥2 个**完成任务的工具或完整实现**」,而「≥2 篇提到答案的文章」降级为扣分项)**从正反两侧独立地得到了同一个答案**。第一节是从误杀案例反推出来的,本节是从成功案例正推出来的。

## 对工作流前提的最终判断

工作流赌的是"新":措辞太新以致没有数据,因此还没有竞争。四轮回测的测量说明:

- **"新"买不到窗口。** 答案与对象同时到(消费者面),或早于义务到(企业面)。
- **"新"仍然有用,但用法不同**:它标识的是**市场刚被验证、占位者还只写了文章**的时刻。此时该问的不是"有没有人占位",而是"占位的人做了工具还是只写了文章"。

因此建议把 G1/G2/G3 的角色重排:
1. **G1 保留原样**(Google 自己把任务做完了,确实没得打)
2. **G2 保留并加强**(读满第一页——它的原始教训是对的)
3. **G3 改问一句话**:「占位者里有几个是**能替用户完成任务的工具**?」0–1 个 → 放行并进入建站评估;≥2 个真工具 → 否决。文章、律所提示、论坛线程、视频教程一律不计入否决线,只作扣分。

## 这一轮仍未做的事

- 只测了 DPP 家族内部的两个时间点(生效前 6 个月、规则未定),没有测"规则公布后第 1 天"这个最早的时点,因此"占位发生在规则公布之前"是从 Tributech 2024-12 一例推的,样本为一。
- 未验证"占位者只写了文章"这一判断在电池护照一格是否也成立——`circularise.com` 的产品页看起来是真工具,若如此,该格属"≥2 个真工具"应否决,与家具格结论不同。这一点应逐格实测,不能整族一概而论。
- 上述 G3 改法未在任何真实候选上试跑过。下一步应当拿账本里 53 个 G3-binding 的否决,按新判据重跑一遍,看有多少会翻。

**在深审入口加一道 G6 预检**(零成本,拦掉那 42 条那一类):任务是否要求**有预算的付费者逐个对象重复完成**?答否 → 不进深审。

## 7. 两条盈利线:G6 从定性描述改成两个算式,并按新契约重算全部账本(2026-08-23)

### 7.1 修改的起因:G3 在拿一条只对广告变现有效的判据,去否决付费产品方向

前六节的校准把注意力全放在 G3 的占位判据上,但没问一个更前面的问题:**占位为什么算输?**

答案取决于怎么挣钱,而这一点此前的契约从未区分:

- **靠广告变现**时,每个访客只值几分钱,买不起流量,**自然位是唯一入口**。位置被占,就是真的进不来。
- **靠付费产品变现**时,自然位不是唯一入口——可买流量、可直销、可走平台市场。实测佐证:`gdprrepresentative` 正在买 GPSR 那个查询的广告位;而 `eu-machinery-regulation-risk-category` 的赌注是每个产品线 €8,000–11,000,这种客单价下付费获客空间极大。

而第 2 节唯一确认的假否决 `ppwr-empty-space-ratio`,其占位者 `ppwrcopilot.com` 恰恰是**双线并行**:£49–199/月 的订阅,加一簇免费工具页吃自然流量。**它不靠自然位活,自然位又在给它供客。** 用"自然位被占即输"去否决它所在的那一格,判据本身就用错了地方。

### 7.2 改了什么

四处,都在闸门契约与数据采集指南里:

1. **G6 新增两条盈利线的算式**,并要求两条都算、任一条过即放行、账本记明靠哪条线过:

   | | 收入算式 | 卡在哪 | 对"量小"的容忍 |
   | --- | --- | --- | --- |
   | 订阅线 | 受约束付费者数 × 可行单价 − 获客成本 | 付费者价值 | 能容忍 |
   | 广告线 | 簇内月搜索量 × 可达位次点击率 ÷ 1000 × niche RPM | 量级 | 不能容忍 |

   广告线必须写出反推算式(需求会话数 = 目标月收入 ÷ RPM × 1000;需求簇内月搜索量 = 需求会话数 ÷ 可达位次点击率),点击率必须用新站现实可达位次估,不许用位次 1 的 20–30%。**写不出这个数就不算算过。**

2. **G3 的占位否决条件化**:只靠广告线的候选,`veto` 就是 `veto`;订阅线能过的候选,三问结论降级为决策阶段的竞争强度输入,不构成出局。

3. **赛道推论(不是额外判据,是逻辑后果)**:`lane=new` 只能靠订阅线过 G6——广告线要求可测量量级,而"查无"正是新词道的定义属性。**这条推论让新词道的 G6 判定变成零成本**:不取任何量级数据,只问深审入口预检那一问,答否即两条线全灭。想走广告线必须以 `lane=mature` 注册。

4. **补齐配套**:`lane` 从 `const: "new"` 开放为 `enum: ["new","mature"]`(schema 原本就写着"为未来成熟词道预留");Semrush 纪律按赛道分开(mature 道从第一步就允许并要求取量级数据,但两道都禁止用 KD 判竞争强弱——三组背离已证明它对此失明);数据采集指南新建「广告线的选源方法」一节。

### 7.3 同时暴露并补上的契约缺口

G6 由此变成了筛选闸门,但 `rejected` 边的理由清单里只有 G0–G3——**没有出口**。这是本次修改自己制造的缺口,当场补上:生命周期契约 `captured/screened/tracking→rejected` 新增第⑦种情形「G6 双线都不过」。

### 7.5 这次重算证明了什么

**这 11 条此前的 G3 都是 `pass`——首页确实没有专做这件事的站。** 而这恰恰是本次修订要修掉的漏洞:

> G3 只问"有没有人占了位",不问"占了位能不能挣钱"。G6 修订前不是筛选闸门,于是"没人占位"被读成了利好;而真实原因是**这一格里没有钱,所以没人来**。

前六节查明"深审预算 87% 花在结构上已死的厂商 changelog 上",但当时只能解释、不能拦截——因为拦截需要一道会算钱的闸门,而 G6 那时只有一句定性描述。这一节把那句描述变成两个算式,拦截才第一次成为可能:**11 条一次性出清,且判定全程零成本,没有取任何一次计费数据。**

### 7.6 诚实的边界

- 本次重算中广告线的判定**全部靠赛道推论得出,不是靠量级数据实测**。推论本身是硬的(查无即无量),但这意味着"广告线不成立"这个结论在 `lane=mature` 上还从未被真正检验过。
- **G7 / G8 依然从未被回测过**,它们占索引侧否决的相当比例。G6 到今天才第一次真正起作用;G7/G8 还停在与 G6 修订前相同的状态。

`GATE_VERSION` 已进号到 `2026-08-23b`(同日第二次实质修订)。副作用:1502 条淘汰方向索引行**全部**变成"旧闸门"——1494 条早于该字段存在,8 条出自当天上午的闸门。

但这个标记偏宽:索引行记的是 **G1 否决**(Google 已经答了),而本次修订动的是 G6/G3,与 G1 无关。版本号是单一字符串,分不出"哪一道门改了",所以只能把全部历史行一律标为可疑。CLI 的提示语已经是"**可能**是误杀,值得重看"的措辞,不是断言,暂不为此增加按门追踪的复杂度。

## 8. 广告线首轮实测:0/3,以及一个乘性夹逼(2026-08-23)

第 7 节建了广告线,但明确记了"这套选源方法尚未跑过一次"。本节是它的第一轮,以及它带回来的结构性发现。

### 8.1 怎么跑的

未走 xinci-run。理由:`xinci-scan` 与 `xinci-run` 两个 skill 全文一次都没有出现 `lane`,跑自动循环会把候选一律注册成 `lane=new`;而第 1 层的源(changelog、release note)天生产出天级新词,正是 mature 道要避开的。**方法未验证就先改 skill 是本末倒置**,所以手工单步跑,`--by user`。

一个执行差异值得记:mature 道的"广度提取"与"量级测量"合并成了一步——Semrush 一次查询同时给出真实查询列表与量级,不像新词道要先提取再另行测量。

约束:Semrush 未登录,只能用公开免费版,**总共 3 次查询**,每次只回 15 行。SERP 阅读改用应用内浏览器,以满足契约的美区/桌面/未登录要求(用户的 Chrome 登着 Google,会个性化)。

### 8.2 结果:3 个种子全灭,但死因各不相同

| 种子 | CPC(RPM 代理) | 簇规模 | 前 15 行量 | 死因 |
| --- | --- | --- | --- | --- |
| `statute of limitations` | **$4.07–12.11 高** | 10,000+ | 111.6K/月 | **防守**(量级过关) |
| `cost per square foot` | **$1.15–2.68 低** | 10,000+ | 31.0K/月 | **量级**(RPM 低 → 需 66.7 万) |
| `commercial rent per square foot` | $2.85–4.85 中 | **290+** | 0.67K/月 | **量级**(差两个数量级) |

种子 A 是唯一读了 SERP 的。六条弱守信号只中 2 条:#1/#2/#4 是佛州官方法条(`leg.state.fl.us`、`flsenate.gov`)加 FindLaw;Kogan Firm 2026-06 已覆盖 HB 837 把人伤时效从 4 年改成 2 年,不存在内容老化;CPC $12.11、多家律所专页、律所自营 YouTube 频道,说明这一格正被多方当生意经营。**方法要求 3+ 条,不过**,并直接命中陷阱类别六。

### 8.3 主要发现:量级、RPM、弱守是一个乘性夹逼,不是三个独立条件

第 7 节把它们并列成三个要检查的条件。三个种子说明它们**互为对立面**:

- **CPC 高不只是 RPM 代理,它本身就是"这一格里有钱"的直接证据。** 有人正在为每次点击付 12 美元 → 有人把这一格当生意经营 → 防守必然强。
- 防守弱的地方往往正因为商业价值低 → RPM 低 → 需求量级暴涨。
- 窄 B2B 兼具好单价与无总量。

**"高 RPM + 无人经营"在成熟词上接近自相矛盾。** 这条已同步写进 G6。

一个值得对照的观察:第 7 节推出的赛道推论说 `lane=new` 只能靠订阅线过,因为"查无"意味着没量。本轮显示 mature 道的对称困境——**有量的地方有人守**。两条道各自被自己的定义属性卡住:新词道卡在没钱,成熟道卡在有人。

### 8.4 据实修订了方法的四处,其中两处是设计错误

1. **量级/RPM/弱守反相关**(上述),原稿完全没说。
2. **四类源头里有两类自带陷阱类别六**:类型一「官方页排第一但答不全」前提就是权威页在场;类型二「规则改过的老查询」的规则由管辖机构维护。种子 A 死得一字不差。两类降为次级,采用前先零成本问一句"这个对象全集有没有法定/事实上的维护者";**结构上可靠的只有类型三(逐对象查表)与类型四(论坛反复人肉回答)**。
3. **YMYL 排除只列了例子没画边界**:原稿写"健身/补剂/交易/健康",法律不在其中,而种子 A 正是法律。改为按类别定义——影响健康、财务、安全或法律权利的一律按 YMYL 处理。
4. **执行顺序反了**:原稿先列弱守信号,量级隐含在后。但 B、C **根本没读 SERP 就死了**。改为量级前置,并写下实测出的两个门槛(簇内词数 < 约 1,000 弃;前 15 行 < 约 50K 且无单词 > 10K 弃)。这个过滤器本轮三个种子全判对,但阈值是从 3 个数读出来的,不是从分布估出来的。

第 4 条与第 7 节 G6 那次修订是同一个教训:**先算钱,再看竞争。**

### 8.5 配套补上的缺口

淘汰方向索引原本没有 `lane` 字段——mature 道的淘汰理由会和新词道混在一起,而两者死因根本不同(新词道死于"Google 已答",成熟道死于"量级不够"或"防守太强")。已给索引加 `lane`,缺字段视为 `new`,历史 1502 行语义不变。本轮 3 条以 `lane=mature` 入索引。

### 8.6 这一轮不能证明什么

#### 由此得出修订五:挑"答案是一个数字"的,避开"答案是一件可购买的商品"的

两个探针的差别只有一处,机制很直接:**没人卖"80 ft-lbs"**,所以没有零售商有动机建那张逐车型扭矩表,论坛就成了唯一供给;而"D130 用哪根皮带"的答案是一个 SKU,零件商建适配表等于建自己的商品目录,于是第一天起就没有位置。

这条让夹逼更精确:**钱直接挂在答案上时,有人会去建这张表。** 真正的缝隙在"搜索者即将花钱、但答案本身不是 SKU"的地方。**仍是带机制的假设,量级未验证。**

- **`diy.stackexchange.com` 弹机器人验证**,CAPTCHA 不绕,已记入运行清单 `sources_blocked`。改用 Google SERP 做探针工具——一次搜索同时给出六条信号里的 1、3、4、5、6,Semrush 只需补量级那一项,这个组合比原计划更省。
- **扩展所连的 Chrome 配置未登录 Semrush**(右上 Log In/Sign Up、表格空骨架、注册弹窗为硬门)。登录与建账号不由我执行,已交还用户。

#### 这组数定量确认了 8.3 的夹逼

弱守是真的(平均 KD 6–8%、占位者含 2009 年的论坛帖),而**代价正是 CPC 近零**。三个种子 + 本方向连成一条清晰的单调关系:

| --- | --- | --- |

## 9. G6 方案 C 定稿:订阅结构硬门 + 广告量级硬门 + 收入最低分(2026-08-24)

### 9.1 要解决的冲突

第 7 节把 G6 写成了“两条线都算、任一条过”,但同时留下三种互相打架的口径:

1. G6 开头说“收入可达性”是四个硬条件之一;
2. 同节后面又说收入不再是硬闸、$200/月只是参考;
3. 广告线却明确要求按 $200/月反推量级,写不出数字就不过。

若把第 2 条解释成“所有收入都只评分”,广告线可在没有量级证明时通过；若把第 3 条解释成“两条线都必须过 $200”,又会误杀高客单、小受众的订阅 niche。`lane=new` 还会被迫给结构上不可测的广告线编一个 0。

### 9.2 采用方案 C

两条线不再共享同一个金额硬门,而是各守自己的失败机制:

| 盈利线 | G6 硬门 | 金额进入哪里 |
| --- | --- | --- |
| 订阅 | 明确付费者 + 被迫/重复任务 + 自助路径 + 同周期收入式有出处且 base case > 0 | 金额大小进入收入可行性 20 分维度 |
| 广告 | 实测簇量 × 现实 CTR ÷ 1000 × 有出处 RPM 的 base case ≥ $200/月 | $200 是该线硬门,超出幅度再进入评分 |

赛道处理随之固定:

- `lane=new`:订阅线判 pass/veto；广告线记 `N/A`,不伪造 0、不强查不存在的量级。
- `lane=mature`:两条线都判 pass/veto；任一条 pass 即 G6 pass。
- 只有广告线通过时,G3 占位否决生效；订阅线通过时,G3 的占位强度进入 CAC/竞争评分,不直接否决。

### 9.3 为什么收入分最低只定 1/20

现有案例不足以校准“订阅月收入至少多少”或“收入维度至少 5/20、8/20”这类经验阈值。直接定一个更高数字会制造精确但无证据的门槛。因此当前只加**逻辑防绕过线**:`income_score ≥1`。它只排除“收入维度 0 分,其他五维仍凑到 80”的明显矛盾,不表示 1 分就是好生意；金额弱的候选仍应因总分不足 80 被 disqualified。

### 9.4 机器执行

`formation_confirmed→qualified` 除原有 `score ≥80` 与 G6–G8 全 pass 外,新增:

- `income_score`:1–20 的整数;
- `g6_passed_lines`:至少一项 `subscription` / `advertising`(**历史表述**:2026-09-02 起合法取值为六条盈利线中的任一项,registrar 的 `MONETIZATION_LINES` 为准);
- `lane=new` 禁止把 `advertising` 写进通过线。

registrar 在写入时拒绝违规转移,`validate_ledger.py` 再捕获绕过 registrar 的手工损坏。观察文件仍负责保存逐线的 `pass` / `veto` / `N/A`、算式、假设和来源；账本只保留决策所需的通过线与收入分。
