# 数据采集指南

## 真浏览器原则

扫描与复查一律在真实浏览器里打开来源页面阅读,不通过 API、搜索接口或 MCP 数据工具拉取 Reddit / X / Product Hunt / Hacker News 等社区内容。

理由(含出处):要下的判断是"这像不像人们会去搜的东西",它来自读真实页面——社区怎么谈论它、用什么词称呼它、名字是否稳定。API 结果集恰恰剥掉这些语境。旧系统有实测失败:搜索 API 显示竞争疲软,live 页面呈现的却是完全不同的战场。

### 适用边界:社区面必须浏览器,变化面可结构化采集

上述规则约束的是**社区内容**——判断"人们怎么称呼它、叫法稳不稳"必须读真实页面,API 结果集会剥掉这层语境。

**变化面(有日期的法规/政策/平台规则/release notes)不受此限**:那里要取的是结构化事实——什么变了、哪天生效、影响谁——不是语境。因此变化面允许用源自带的列表页、RSS、导出接口批量采集素材,一次拉一批。广度扫描要把素材量提到数百条/轮,逐页人工读是做不到的。

不可放宽的部分:

- **G1/G2/G3 一律真浏览器**——SERP 判断本身就是语境判断,任何阶段都不得用接口替代;
- **社区面(Reddit / X / Product Hunt / Hacker News / 即刻 / 应用商店)一律真浏览器**;
- 无论用哪种方式采集,**未在本次会话实际取回的来源不得声称已检查**。

配套纪律:

- **未在本次会话打开的来源,不得声称已检查。** 每次运行把实际打开的 URL 记入 `运行/<日期>-<skill>.json` 与观察文件的 `source_urls`。凡 observation 提交 gates,支撑该 gate 的 source_urls 必须非空且随同一次 registrar 写入提交;registrar 会逐门核对,不能用另一份无关观察替代。
- 记录精确措辞和来源 URL;凭记忆重构的词不是证据。

### 变化面的实际取回:各源的正确端点,与"取回成功≠取到正文"(2026-08-25 新增)

上一节说变化面允许结构化采集,但没说各源实际怎么取。2026-08-25 清理 316 个存量候选时把主要官方源都试了一遍,难度差一个数量级,且**有两次因为取错而写出不成立的观察**,所以把结果记在这里,后人不必重试。

| 源 | 正确取法 | 陷阱 |
| --- | --- | --- |
| 美国 IRS 公报 | 直接 curl 公报页(正文约 6 万字),从开头的 `HIGHLIGHTS OF THIS ISSUE` 按文号定位该条的官方摘要 | 少数文号(TD、CC 开头)按标准格式定位不到,改按文号数字重新检索正文即可 |
| 加拿大公报 Part II | 直接 curl `sor-dors*` 页,读 RIAS 的 `Issues` / `Background` / `Objective` / `Description` 四节——它直接说明这次变化解决什么问题、影响谁 | 部分页面非 UTF-8,curl 结果须按**字节**读入再容错解码,否则整批报错 |
| 加拿大公报 Part I | curl 索引页后按 URL 锚点(`#ne3` 一类)定位本条目正文 | — |
| 英国 SI(legislation.gov.uk) | **来源地址后加 `/data.xml`**,取 `dc:title`(法规官方全称)与 `Pblock`/`P1group` 下的 `Title`(逐条条文标题) | 偶发 202 是**临时限流不是结构性阻断**,重试即可;别据此判定该源取不到 |
| 澳洲(legislation.gov.au) | 页面只是外壳,正文由前端以 ePub 异步加载。**先取外壳页解析出 as-made 日期**,再取 `/{ID}/asmade/{日期}/text/original/epub/OEBPS/document_1/document_1.html` | `/latest/text`、`/asmade/text`、`/latest/downloads` **全部返回 200 但全都是外壳**;该正文路径是用浏览器的 `performance.getEntriesByType('resource')` 挖出来的 |
| EUR-Lex | 只能用**真浏览器逐条导航**,读 `.eli-main-title` 与 `#text` | 账本常登记的 `publications.europa.eu/resource/celex/…` 返回的是 `application/rdf+xml` 元数据;`eur-lex.europa.eu` 的正文端点对 curl **与浏览器内程序化 fetch** 一律返回 202,只对真实导航放行 |
| gov.uk / fca.org.uk / bankofengland.co.uk | 直接 curl 可取正文 | — |
| 美国 SEC | curl 返回 403(其自动化访问政策要求 User-Agent 声明联系方式),改用**真浏览器**导航或同源 fetch | **不得为满足该政策而把用户本人的邮箱写进 User-Agent**——那是把用户个人信息发给无关服务 |
| 欧盟理事会(consilium.europa.eu) | 有 JS 挑战。**换一个真实浏览器通道**即可通过(实测:in-app 通道卡死、用户自己的 Chrome 一次通过) | in-app 通道停在"请稍候"页,`document.body.innerText` 长度恒为 60、等待 9 秒无变化;这不是页面没内容,是挑战没过 |
| 德国议会文献检索(dip.bundestag.de) | **取不到**。它是单页应用,两个浏览器通道下 `document.body.innerText` 长度都恒为 0、`readyState` 停在 `loading` | 该站只能人工用浏览器看;要拿德国立法文件,走 Google 定位到 `dserver.bundestag.de` 的 Drucksache PDF 更快 |
| 英国 legislation.gov.uk 的列表页 | 逐页**真实导航**读 HTML;链接选择器用 `a[href*="/uksi/<年>/"]` 且文本长度 >20(滤掉编号链接) | `data.feed` 与页面内程序化 `fetch` 一律返回 202,与 EUR-Lex 同一模式;只有真实导航放行 |

**配套的通道分工(2026-08-29 新增,一条实测出来的省事规则)**:SERP 必须走**干净的未登录通道**——那是 G1 结论成立的前提,不可替代;而**被 JS 挑战拦住的普通网页可以交给用户已登录的浏览器**,因为那些页面的正文与登录态无关。2026-08-29 就是靠这条拿到了 `platform work directive transposition` 的关键出处:欧盟理事会那一页在 in-app 通道卡死,换 Chrome 一次读到 11,032 字符正文与 around 500 digital labour platforms 这个数,该候选据此完成 G6 第④项并出闸进入 tracking。**别在一个通道上反复重试,先问这一页要不要干净环境。**

**最该记住的一条教训:HTTP 200 不等于取到正文。**同一天有 9 份观察在初次写入时称"现场在正文中直接读到官方参数本身",事后核实发现取到的是页面外壳(legislation.gov.au)或 RDF 元数据(EUR-Lex),初次匹配到的 `Schedule` / `Part` 字样来自**页面导航目录**而不是正文里的费率表,9 份文件全部重写并以`【同日更正】`开头写明。**批量取回后必须先验一次正文长度与内容形态,再据以写判定**;外壳页通常只有一两千字且全是导航词。

### 一条配套的分组方法:用条文结构决定哪些要逐个判

取到英国 SI 的条文标题后,107 个候选不必逐个硬啃。**剔除 `Citation` / `Commencement` / `Extent` / `Interpretation` / `Application` / `Revocation` 这些例行条款,再看两个数**:剩余实质条文有几条、其中 `Amendment of…` / `Insertion of…` / `Revocation of…` 形式占多大比例。

- 实质条文为零、或修订条款占比 ≥80%、或实质条文 ≤2 → 归上一节的形态⑨(纯技术性修订或单点规定),按类处置;
- 其余 → 逐条读条文标题,单独判死因。

实测 107 个据此分成 68 与 39 两组。**这不是为了省事,是让每一类的证据与理由都落在它自己的结构事实上**;归入形态⑨的那 68 个仍逐个扫过法规全称,确认没有藏着重大新义务的(几乎每个标题里都带 `(Amendment)`)。同样的思路可迁移到其他有稳定条文结构的源。

## G1/SERP 检查的环境构造(美区、桌面、未登录)

闸门契约要求 G1 在"美区、桌面、未登录"条件下搜精确词。真实浏览器往往带登录态与本地地区,SERP 会被个性化与地域污染,按以下方式尽力逼近目标条件:

- 用无痕/隐私窗口打开搜索,压掉登录态;
- 搜索 URL 显式带参数:`https://www.google.com/search?q=<精确词>&gl=us&hl=en&pws=0`(gl=us 美区、hl=en 英文、pws=0 关闭个性化);
- 连续运行在每轮开始前由**本轮实际执行者**用 `browser_preflight.py --executor-id <id>` 记录 channel、可控性、桌面、美区与未登录事实，再以同一 ID 调用 `run_policy.py` 和 `begin-round`。预检同时绑定执行者与目标轮次；父任务、其他子代理或上一轮状态不可借用。任一条件达不到时进入 `trigger_only`：可以采集官方变化并保留搜索语言假设，但不得写 G1、不得把缺 G1 的新方向注册为 captured，也不得以 queued 冒充推进。单步模式可以记录受污染观察，但不能据此下 G1 结论。

### 环境对了还不够:读取方法必须能读到 AI Overview(2026-08-26 新增,出处是一次系统性误判)

**这一条与上面三条同等硬,漏掉它会让 G1 结论整体失效。**

**问题**:浏览器工具里那类"提取页面主要内容"的读法(Claude Browser 的 `get_page_text`、以及一切先找 `article`/`main` 容器再回退的实现),在 Google SERP 上会**选中 web results 容器,整块跳过 AI Overview**。它返回的文本从 `Web results` 起始,读起来完全正常——没有任何报错、没有截断提示,**看不出少了东西**。

**后果**:用它读 SERP 判 G1,会把"AI Overview 已经把任务整段做完"的页面读成"首屏干净、无原生组件",从而系统性地把该 veto 的候选判成 pass。

**正确读法**:用 JavaScript 读 `document.body.innerText`(或等价的整页文本),再在其中检索 `AI Overview` / `Featured snippet`。

**自检**:读回来的文本若从 `Web results` 或第一条自然结果开始,而不是从 `Skip to main content … Search Results` 这类整页开头开始,说明工具选错了容器,该次 G1 观察作废重读。

**出处**:2026-08-26 复查账本仅剩的两个 tracking 候选时,先用 JS 读法发现 `uk-machinery-safety-gb-ni-2026` 的核心任务措辞首屏有 AI Overview 且把 GB/NI 标记判定整段做完;随即在**同一页面、同一时刻**用 `get_page_text` 对照,返回内容里完全没有该区块。据此回查前一日:2026-08-25 那批观察共写下 **36 条 `G1=pass`**,全部出自 `get_page_text`,**均不可靠**。其中 35 条因候选另死于 G6 而结论不受影响,但**当时仅有的两个出闸候选正是靠这条不可靠的 G1 才通过 `captured→screened`**——复测后两条 G1 全部翻为 veto。同日重测最后一个存活候选 `au-nfp-tier3-financial-statements-2026`,G1 同样翻为 veto。**账本因此从"2 个活口"归零。**

**这条教训的一般形式**:工具"成功返回"不等于"读到了该读的东西"。这与本文件上面「变化面的实际取回」那节记的是同一类错误——那次是 HTTP 200 返回的却是页面外壳与 RDF 元数据,这次是文本提取成功却少了整个 AI Overview 区块。**凡用工具替代肉眼看页面,都要先确认它到底读到了什么。**

### 容器选对了还不够:AI Overview 是异步生成的,读早了等于没有(2026-08-31 新增)

**这一条与上面那条是同一个后果、不同的成因,漏掉它同样会让 G1 结论整体失效。**

**问题**:AI Overview 在页面 `load` 之后才异步生成。导航返回、DOM 就绪、整页 `innerText` 能正常读出来——**但那一刻 AI Overview 区块还不在里面**。

**实测(2026-08-31,精确词 `which f gas gwp limit applies to my heat pump`,同一页面同一次导航)**:

| 时点 | 整页 `innerText` 长度 | 检索 `AI Overview` |
| --- | --- | --- |
| 导航返回后立即读 | 3,704 | **整页连这个字符串都没有** |
| 等 6 秒后重读 | 5,687 | 完整区块,含逐档 GWP 限值与主动索要机型参数 |

注意**立即读时不是读到占位符,是什么都没有**——没有 `Thinking`、没有骨架、没有任何提示说"还有内容在路上"。同一次运行的另一个执行者在 `which emdn code applies to my device` 上读到的是 `Thinking / Searching / Thinking a little longer` 占位符,那还算幸运;上面这一例连占位符都没有。**两种情况都看不出少了东西。**

**后果与 `get_page_text` 那次完全一样,而且方向相同**:把"AI Overview 已经把任务整段做完"的页面读成"首屏干净、无原生组件",系统性地把该 veto 的候选判成 pass。

**正确读法**:导航后**先等待再读**,并且**判 G1 之前必须确认 AI Overview 已生成完**。可操作的做法:

1. 导航后等待若干秒再读整页 `innerText`;
2. 读回的文本里若出现 `Thinking` / `Searching` / `Thinking a little longer` 这类占位词,**说明还在生成,等待后重读**;
3. **文本里完全没有 `AI Overview` 字符串时,不得直接判定"该词没有 AI Overview"**——先隔几秒重读一次确认。只有重读后仍然没有,才算真的没有。

**这条教训的一般形式(与上一条合起来)**:读页面这件事有两个独立的失败点——**读错了地方**(容器选择跳过 AI Overview)与**读早了**(内容还没生成)。两个都要防,任何一个漏掉,G1 的结论都不可靠。**凡用工具替代肉眼看页面,不但要确认它读到了什么,还要确认它是什么时候读的。**

**延迟不是恒定的,所以"等 N 秒"不能当保证——载重的是自检,不是等待时长(2026-08-31 当日复查实测)。** 同一轮里连测 6 个候选:

| 候选措辞 | 立即读长度 | 立即读有无 AI Overview | 等待后长度 |
| --- | --- | --- | --- |
| `cpr avcp system 1+ 2+ 3 4 which applies` | 2,912 | 无(有占位符) | 5,765 |
| `CCPA DROP compliance` | 3,071 | 无(有占位符) | 4,991 |
| `DBS rule change September 2026 checklist` | 3,273 | 无(有占位符) | 5,815 |
| `EU AI Act Article 50 compliance checklist` | 6,583 | **有(首读即生成完)** | 6,583 |
| `eu right to repair directive transposition by member state` | 2,994 | 无(有占位符) | 5,344 |
| `platform work directive transposition` | 3,092 | 无(有占位符) | 5,336 |

6 个里 5 个要等,1 个不用等。**所以不要把"等够 N 秒"当成通过条件**——它既可能不够,也可能白等。真正载重的是上面那三条自检:占位词在就重读、没有 `AI Overview` 字符串就重读确认、容器起始位置对不对。等待只是让自检有机会通过的手段。

**这条纪律抓到的第一个实例**:`DBS rule change September 2026 checklist` 在 2026-08-26 与 08-28 两次复查里都判 G1=pass,而两次的观察**都记下了 `Thinking/Searching` 占位符却没有重读**。08-31 按新读法等待 10 秒重读,首屏 AI Overview 直接给出三步成品清单,并把该任务的判定阈值(`more than 3 days in any 30-day period, or overnight (between 2:00 AM and 6:00 AM)`)整句写出——阈值一给,逐岗位审计就不再需要任何工具。该候选当日转 `rejected`。**无法排除首屏确实在这 3 天内新增了该区块,但两次基线在写下时本就该按占位符提示重读,不论哪种成因,原 G1=pass 都不可靠。**

### AI Overview 里的数字一律先当线索,不当证据(2026-08-29 新增)

AI Overview 现在会给出**带出处标注、看起来完全可信**的具体数字。它同时是本工作流最方便的线索来源和最危险的假证据来源——**任何要写进判据的数字(尤其是 G6 第④项的受约束付费者数),必须先核实再用**。

两步核实,都很便宜:

1. **把数字加引号精确检索一次。** 零结果就说明它在网页索引里根本不存在,是合成出来的。实测:AI Overview 称德国 UWG 修订的受约束企业为 96,938 家并标注来源 lindenpartners/HEUKING/PwC,加引号复检时 Google 明确返回 `No results found for "96.938 Unternehmen" ...`,当场证否。
2. **打开它指名的那个来源,在正文里找到那句话。** 上例中 lindenpartners 原文摘要里并无该数字;而 `around 500 digital labour platforms operating in the EU` 则在欧盟理事会官网正文里逐字读到,才被写进候选的 G6 第④项。

两步都过不了的数字,按"未取得"处理——**宁可让候选卡在 `captured`,也不要用一个合成的数字把 base case 撑起来**。这与「变化面的实际取回」那节是同一条纪律的两面:合成能力越强,越要把输出当作待核实线索。

**第二步不是第一步的备份,它抓的是另一种失效模式(2026-08-30 补记)**:上面两步里,第一步(加引号精确检索)只能证否**合成出来的**数字。还有一种变种它抓不住——**数字是真的,但被安在了错的法令上**。

实测:`eu-product-liability-transposition-2026` 的检索中,AI Overview 断言"欧委会对产品责任指令 2024/2853 的影响评估估计约 130 万家企业受影响",并带三段分解。加引号精确检索**通过**——该数字确实存在,出自 `SWD(2024) 230 final`,PDF 挂在 europarl.europa.eu。但打开来源一看,SWD(2024) 230 是 *Fitness Check of EU consumer law on digital fairness*,那 130 万计的是数字环境下适用三部**消费者法**指令的企业,与产品责任指令毫无关系。改查产品责任指令自己的影响评估 `SWD(2022) 316`,同样给不出有限计数,正文还自述 *confirmed the lack of data*。

**所以第二步要问的不是"这个数字在这份来源里吗",而是"这份来源计的是不是同一个总体"**——同一个数字挂错法令、错年份、错地理范围、错主体口径,在原文里都能逐字找到。第一步过了不等于可以跳过第二步;两步查的是两件事。

**第三种失效:事实是旧的,或者已经被撤销/反转(2026-08-30 补记)**。前两步核的是"这个数存不存在"与"它计的是不是同一个总体",都默认了**事实还成立**。日期类事实经常不成立:

同一轮扫描里 10 条 G1 否决有 **3 条是 AI Overview 自己纠正了 AI Overview**——发现期读到的生效日/截止日,到 G1 复测时被首屏当场推翻:

- India BIS 机械 OTR 被断言 2026-09-01 生效,实际该 Order 已于 2026-01-16 由 S.O. 239(E) **撤销**;
- California SB 707 纺织 EPR 被断言注册截止 2026-09-04,实际截止日是 **2026-07-01,早已过**(主上下文 2026-08-30 复测确认:首屏直接答 was July 1, 2026,并给出 PRO 为 Landbell USA、年费 $1,000);

**所以凡是"生效日 / 截止日 / 适用日"这类日期事实,必须回到发布机关自己的页面确认它当前仍然有效**——尤其要确认没有被后续文件撤销、延期或替代。合成模型是按语料里的历史陈述作答的,一条被撤销的规则在语料里留下的痕迹,比撤销公告本身多得多。

**一条派生的选源纪律**:以"某某截止日是哪天"为核心的措辞,在结构上就是死的——截止日是一个**已存在的固定事实**,正是合成最擅长的形态,首屏必然做完(这与上面类别十二收窄后的判据是同一件事)。日期只该用来**定位窗口**,不该用来当搜索措辞。

## 自动补全:有建议是正证据,零建议不是否决(2026-08-29 新增)

Google 自动补全是本工作流最便宜的需求侧信号,也因此最容易被误用成一道门。**它只有一个合法用法:出现相关建议,是"这个说法已经在被搜"的正证据,可以抬高该方向的优先级。零建议不构成任何否决**——它不在 G0–G8 里,也不得作为零成本预筛的独立死因。这与本文件末尾「Semrush 探针纪律」里那句"自动补全出现与否是形成信号证据,不是资格证据"是同一条,写在这里是因为误用发生在扫描期,而那一条写在形成期一节里,扫描时不会被读到。

**理由是结构性的,不是个案**:自动补全的触发门槛是搜索量,而本赛道的定义属性正是低量高值的 B2B 义务(闸门契约 G6 记过 `eu-machinery-regulation-risk-category` 一年可能只有几千次搜索)。用一个按搜索量筛的信号,去找刻意避开搜索量的机会,方向是反的。

## 正向选择器:优先找"义务",不是找"新词"(2026-08-23 新增)

**这是本文件唯一的正向选择器,也是工作流此前完全缺失的东西**——在此之前它有 9 个负向陷阱类别、0 个正向选择器,只会否决、不会瞄准。依据见 [闸门校准.md](闸门校准.md)。

### 为什么触发条件要换掉

原触发条件是"一个措辞变新了"。四轮回测的测量说明**"新"买不到窗口**:

- 消费者/开发者面:答案与对象**同时**到(小时到数天)。实测——律所在最终规则发布后 3–5 小时占位;发布方自己的页面小时级被收录;通用 AI 工具收录新模型 4 天;竞品迁移内容 4 天。
- 企业合规面:答案**早于义务**到。实测——`tributech.io` 在 2024-12 就写 2028 才定稿的家具 DPP 授权法案,比义务成形早约四年;家具 DPP 规则尚未具体化,专页已有七八个。

位置不是在任务出现之后被占的,而是在任务出现**之前**就被占的——因为"预期"本身可变现。所以要换的不是扫得更快,而是换判断标准:

> **新触发条件:一个义务被公布了,而占位者只写了文章、没做那个工具。**

这里的“触发”是原料，不是 candidate。官方标题、法案全名和公告标题先写入 `触发池.jsonl`；只有找到用户实际搜索的 task query 和独立搜索语言证据，并完成 payer / repeat unit / self-serve path / base-case source 商业预检后才能批准进入 G0。这样防止把“官方存在的措辞”误当成“有人会搜索且可建站的任务词”。

### 七条正向选源信号(用于排序,不是七道额外硬门)

从账本里唯一被证明对应真实生意的方向(`ppwr-empty-space-ratio` → `ppwrcopilot.com`,£49–199/月、190+ 机构)反推,并在 DPP 一格复现。它们用于**先扫谁、同层候选谁优先拿到深审配额**,不是在 G0–G8 之外再造七道硬门。强制入口仍以闸门契约为准:先过 G0/G4/G5/G6–G7 零成本预筛;其中“有预算的付费者逐个对象重复完成”只直接建立或否决 subscription,答否后仍须检查 lead_generation、affiliate、transaction、paid_report。其余信号用于建立逐线暂定结论、判断耐久性与排序;某一项缺失时按对应闸门处理或留在 `captured` 补证据,不得因为“七条未全中”一句话直接秒弃。

1. **义务施加给企业**——不是消费者、不是政府机构、不是读文档的个人开发者
2. **要求逐个对象重复计算或证明**——每个 SKU / 场址 / 批次 / 市场各做一次,不是读一次就完
3. **存在多管辖区差异**,使"汇总本身"成为资产(PPWR:27 个成员国 + 英国各有本国要求与押金制度)
4. **有明确生效日**,产生时间压力
5. **违规有实质后果**(罚款、禁售、审计风险)
6. **官方发布法条但不提供逐对象的计算工具**——欧盟发法规不发计算器;NPS 发每园页面不发合并清单。**零成本层先查一句:发证机关自己有没有发计算工具、模板或 Excel?有 → 直接弃,不进深审**(首检修订一,`cbam` 即死于此,原本花了一次深审才发现)
7. **同一周期的受约束付费客户数 × 可行单价 − 获客与交付成本**有初步出处且 base case > 0,可作为窗口期 `subscription=tentative_pass` 的证据；确认期仍须重取正式证据并由 G6 判定,金额大小进入收入可行性评分(这条是 `sablefish-inseason-trip-limit` 的死因:持证渔民仅数百量级且无法形成可信正向 base case)

第 6 条配一句警告(`nps-powered-micromobility-devices` 与 `sablefish` 都栽在这里):**官方不提供工具 ≠ 位置空着**。要再问"谁有动机做这个汇总"——若答案是**卖相关产品的厂商**(电动车零售商、合规软件商、PIM 厂商),他们会用内容营销占住它且更有优势。

第 6 条还要配一个**豁免口**(2026-08-31 新增,三次实测):**发证机关发布了"可检索的表本身",不等于它发布了"逐对象判定工具"。** 前者不触发第 6 条的秒弃,后者才触发。

分界是**这个官方工具吃不吃进搜索者的对象**:

| 官方发布的东西 | 吃不吃对象 | 第 6 条是否成立 |
| --- | --- | --- |
| 欧委会 CosIng | 只按**单一物质**查它的 Annex 状态,不吃整份配方 | **不成立**,不弃 |
| 欧委会 EMDN 浏览器(`webgate.ec.europa.eu/dyna2/emdn/`) | 只按**术语**检索表本身,不吃器械描述、不输出该器械的码 | **不成立**,不弃 |
| ECHA 生物杀灭剂库 | 同上,查条目不判对象 | **不成立**,不弃 |
| BIS Know Your Standard | **吃产品,直接返回适用标准** | **成立**,零成本弃 |
| CBAM 官方计算器 | 吃申报数据出结果 | **成立**,零成本弃(首检修订一即死于此) |

判法一句话:**打开那个官方工具,看它的输入框要的是"表里的一个词"还是"你的那个对象"。** 要词的是索引,要对象的才是判定工具。

**这句话有一个会翻转的边界(2026-08-31 再补,`run-20260831T123815Z-6737e1f9` 第 1 轮实测)**:要词还是要对象,不是那个工具的固有属性,而是**它的输入粒度与搜索者对象的粒度对不对得上**。上表第一行 CosIng 之所以判"不成立",真正的理由写在它自己那一格里——"不吃**整份配方**";搜索者的对象是配方,工具的粒度是单一物质,两者错开,所以它只是索引。

**当搜索者的对象本身就是那一个单一物质时,同一个工具就变成了判定工具。** 实测:`is my chemical subject to a significant new activity requirement on the canadian domestic substances list` —— 这里的 my chemical 就是一个物质,CAS 号**既是表里的一个词、也是他的那个对象**,官方 Substances Search 输入 CAS 号直接返回 S / S′ 标记,判定当场完成。此时豁免口不成立,第 6 条照常秒弃。

所以判法要问两句,不是一句:**①那个工具吃什么粒度?②搜索者的对象是什么粒度?两者重合,它就是判定工具,豁免口不适用。**

### 反向用法:官方登记册粒度错开时,它是**原料源**,不是竞争者(2026-08-31 新增)

判据 6 判否的官方工具是死因;**判据 6 判"不成立"的官方登记册,反过来是本工作流最便宜的一个零成本判据来源**。

实例:EUR-Lex 的 National Transposition Measures(NTM)。它对搜索者只是书目索引(粒度错开,见上),但对**我们**,它一页就给出某部指令 27 国的转化截止日与**已通报措施数**——这是判断"这张矩阵此刻有没有行在动"的最快判据:

- **0 条通报** → 窗口**未开**,还没有任何国家动,搜索需求不存在 → 零成本弃
- **27/27 全通报** → 窗口**已过**,矩阵已定型,不再有逐格追踪的需求 → 零成本弃
- **中间态**(如 2/27、6/27) → 窗口**当期**,才值得往下跑 G1

`run-20260831T123815Z-6737e1f9` 第 4 轮实测的 8 部指令里,**3 部靠这一条当场秒弃**(honey origin labelling 27/27 已过、urban wastewater EPR 0 条未开)。留档:PLD 2024/2853=2026-12-09(2/27)、IED 2024/1785=2026-07-01(6/27)、EPBD 2024/1275=2026-05-29、EmpCo 2024/825=2026-03-27、Single Permit 2024/1233=2026-05-21、Breakfast 2024/1438=2025-12-14(27/27)。

**推广的问法**:每当判据 6 判出"这个官方东西只是索引,粒度错开",紧接着问一句——**它能不能反过来给我一个零成本的时点判据或计数判据?** 官方索引往往是全集里最权威、最新、最便宜的那份数据。

出处与纪律说明:这条判据 2026-08-31 之前只活在某条 trigger 的 reason 里,属**观察层**。按生命周期契约「观察也不得创造通用判据」,它必须落到契约层才生效——否则下一个执行者读到观察就当判据用,而它从未经过复核。现在补在这里。

所以画像④要连着问:**这一格的现成服务商靠什么收钱?** 靠工具收钱的,位置多半没了;靠人和实验室收钱的,位置往往还在。

**但④其实是两个独立的半边,(a) 过了不代表 (b) 过(2026-08-31 第 6 轮 0/21 实测得出)**:

- **(a) 服务商靠什么收钱**——上面这条;
- **(b) 发证机关有没有自己发逐对象的判定材料**——计算器、模板、Excel、对照表、在线系统,**以及一份静态的"对象/非对象解释例表"**(见陷阱类别十三及其第三形态)。

第 6 轮两条走到画像①②③⑤全部成立的方向(欧盟植物健康 2019/2072 逐批进口要求、日本 DENAN PSE 逐型号归类),可见服务商清一色是检测认证型(JQA、TÜV、UL、SGS、Intertek、NPPO 顾问),按 (a) 该判"位置还在"——**实际却被 (b) 占掉了**:METI 发了「対象・非対象の解釈事例」,NVWA 发了逐植物的附加声明 checklist。

**所以画像④要按两半边分别查,(b) 尤其容易漏**:它常在发证机关的**母语页**上,藏在 FAQ / Q&A / 解釈 / guidance note / checklist 栏目里,不在法规正文旁边。

**(b) 里的"发证机关"是写窄了——正确的主语是「受理方」(2026-08-31 第 7 轮 0/61 实测得出)。** 第 5 轮 1/13、第 6 轮 0/21 的死因高度集中在 (b),当时的解读是"政府这一侧正在被官方自己填满",于是第 7 轮**刻意换到政府发证机关之外**:赛道 A 平台卖家合规(平台没有发证义务)、赛道 B 美国州法多辖区(没有联邦登记册)。结果 61 条方向 **0 存活**,而且死法完全一样——四个独立确证跨**三种机构类型**:电商平台 Amazon 的 Manage Your Compliance 面板逐 ASIN 出文件清单与截止日;TikTok Shop 的 Qualification Center 逐类目出文件要求;美国州级机关 MPCA 的 PRISM 系统外加分场景 supplemental guide 与"雨衣防水涂层算不算 intentionally added"的解释例;生产者责任组织 CAA 的 "Guidance for Determining Producer Obligations" 与六州 covered-materials 定义文档。

**动机不是发证,是收数**:凡是要**接收这份判定结果**的那一方,都有结构性动机把逐对象判定材料自己做出来并永久免费维护——平台要为违规 listing 担责,机关要收到干净的申报数据,PRO 要按 covered materials 收费。所以 (b) 的零成本一问改成:

> **这份判定的结果,有没有一个单一主体在收?**(收的人是发证机关、平台还是 PRO 都一样)有 → 先假定这一格已被填满,再去它的官网 / 卖家后台帮助 / FAQ / 母语页确认交付形态。

**这条同时关掉一条看起来很有希望的逃生路线**:靠"换一个非发证机关的赛道"绕开 (b) 是行不通的。真正要找的是**没有单一受理方**的判定——判错的代价由市场、买家或诉讼兑现、**没有人收表**的那一类。完整案例见陷阱类别十三「第四次扩类」。

#### 画像④的再一次精化:要找的不是"没有汇总者",是"**汇总者在场,却恰好不带那一列**"(2026-09-01 第 2 轮,2 处实测,待验证)

上一段说"要找没有单一受理方的判定"。`run-20260901T060723Z-2b9e306d` 第 2 轮按这条去开采**行业技术标准体系的适用性判定**(英国指定标准 12 个规制、欧盟协调标准实施决定 3 条),**0 条进入正式漏斗**,而失败的方式指出上一段的问法还差一层:

- **"分散在很多份标准里"并不等于"判定本身分散"。**判定通常写在**一份短附件**里,分散的是判定**之后**要用的那些标准。本轮去重当场命中两个最像同构的方向,都已在 2026-08-31 因画像①判否:`which atex category applies to my equipment`(ATEX 指令 Annex I 只有 M1/M2 与 1/2/3 五档)、`which ped category applies to my pressure vessel`(PED Annex II 只有 I–IV 四档、九张 PS×V 图)。**挑方向时要问"判定依据本身有多大",不是"这个领域有多少份标准"。**
- **"没有汇总者"这个前提在指定/协调标准这一族根本不成立。**本轮下载并读了英国 DBT 的三份合并清单:machinery v16 **1069 行**、radio equipment v10 **249 行**、construction products v02 **449 行**,列头齐备(含 start / end of legal effect、Restriction、superseded)。主管机关自己免费维护对象全集清单,属**陷阱类别六的标准清单变体**;搜索者的对象若是"我文件里那版标准编号",还与清单行键**粒度重合**,按判据 6 直接是判定工具。

**但同一次测量给出了正向的那一半,这是本节真正的产出**:GB 建材指定标准清单(449 行)的列头是 `Legislation / Reference / Title / Notice / Restriction / superseded`——**没有 AVCP 系统列**,与欧盟侧一致。账本里 `cpr-avcp-system-per-product` 之所以活着,不是因为"没有人汇总建材标准"(汇总得很全),而是因为**那份齐全的官方清单唯独不带搜索者要的那一列**——AVCP 系统号只写在各 hEN 的 Annex ZA 与逐产品族的委员会决定里。

**据此把画像④的选源问法改写为两句,先问第二句**:

1. 这一格有没有一份官方或权威的汇总清单?(几乎总是有)
2. **那份清单带不带搜索者真正要的那一列?** 带 → 位置早就没了,连 G1 都不必跑;**不带,而那一列又只存在于逐份标准的附件里 → 这才是要找的格。**

第 2 句是可零成本执行的:打开那份官方清单**读一眼列头**,不要读内容。2026-09-01 第 2 轮的 12 条英国方向就是靠读列头在零成本层全灭的。

**证据基数 2 处(GB 建材清单、欧盟建材清单),处置为待验证**:后续运行请在 notes 记明本条是否再次命中——尤其是有没有出现"清单带了那一列、方向照样活着"的反例。

##### 第 2 句"不带"那一半必须与 (b) 半边合起来问,单独用会放行死格(2026-09-01 第 3 轮,1 例反证,待验证)

第 3 轮拿上面这两句去跑第 2 轮留下的两条未评估方向,**两个方向给出了这条判据的正反两面**:

| 方向 | 官方汇总清单带不带那一列 | 第 2 句给出的结论 | 实际结论 |
| --- | --- | --- | --- |
| `does my radio equipment need a notified body because the harmonised standard has a restriction` | **带**——DBT 无线设备指定标准清单 v10(247 条)列头直接有 `Restriction (3)`,247 条里 52 条填了逐字限制文本(如 EN 302 217-2 V3.2.2 明写 clause 4.3.2 的 note 2 一旦适用即不推定符合 reg 6(2);EN 302 065-4 / EN 302 186 明写不覆盖接收机性能参数);搜索者的对象是他 DoC 里那版标准编号,与清单行键粒度重合 | 位置早没了,连 G1 都不必跑 | **一致**,零成本弃 |
| `which atex equipment category and ex marking applies to my equipment` | **不带**——DBT 防爆设备指定标准清单 v10 共 116 行,列头只有 `Legislation / ESO / Reference and title Provision / Start of legal effect / Publication Notice reference / Notice Publication date / End of legal effect / Removal Notice reference / Removal Notice date`,没有任何标记列或类别列;而 Ex 标记代码恰恰"只存在于逐份标准的附件里"(EN 60079 各分部) | **这才是要找的格** | **相反**:方向照样死 |

ATEX 那一格死在**画像④的 (b) 半边**——欧委会官方 ATEX 页挂着 2026 年 1 月发布的 **ATEX 2014/34/EU Guidelines 第 6 版**,其中 **Table 6「examples for marking of equipment」与 Table 7「examples for marking of equipment having different categories」**逐例给出最难判的边界情形及其成品标记:装在 zone 0/1 之间罐壁的液位计 = `II 1/2 G`、从 zone 22 抽风并装在 zone 22 的鼓风机 = `II 3/3 D`、从 zone 1 抽风装在 zone 2 的风机 = `II 2/3 G`、含 1 类设备安全装置的 2 类设备 = `II 2(1) G`、部分 1 类部分 2 类的气体检测总成 = `II (2)/2 (1)/1 G`。这是陷阱类别十三第三形态(逐对象判定解释例表)。同页另链 ExNBG(欧洲 ATEX 公告机构协调组)的 Clarification Sheets,Guidelines 目录 §118 即其条目——受理方自建。

**所以第 2 句答"不带"只是**必要条件,不是充分条件**:它证明的是"没有人把那一列做成表",不证明"没有人把那一次判定做完"。判定可以不以表的形态交付,而以**逐例解释**的形态交付,后者恰恰专挑最难判的边界情形,杀伤力比表更强。执行上把两句改成三句,顺序不能换:

1. 这一格有没有一份官方或权威的汇总清单?
2. 那份清单带不带搜索者真正要的那一列?**带 → 弃。**
3. **不带的话,收这份判定结果的那一方(发证机关 / 平台 / PRO / 公告机构组)有没有把这次判定以别的形态做完**——计算器、Excel、correlation table、在线申请系统、**或一份逐对象判定解释例表**?有 → 同样弃,连 G1 都不必跑。

第 3 句的检索位置沿用类别十三第三形态那条:官方页的 guidance / FAQ / 解釈 / clarification sheet 栏目,常常不在法规正文旁边,也常常只有当地语言。

**同轮另有两处独立复现第 3 句**(跨市场、跨机构类型):美国 CPSC 自建免费 **Regulatory Robot**(官方页原文 *you will need to run the Robot one time for each product*,7 语种),而 CPSC 同时是 eFiling 合规证书的受理方;加拿大 Health Canada 自发 *Guidance on how to interpret "significant change" of a medical device*、*Guidance for determining medical device application type*,而 HC 正是许可与许可变更申请的受理方。

##### 第 4 次精化:「判定表藏在付费标准内部」这条假设**不可推广**,它有三个必须同时成立的前提(2026-09-01 第 6 轮,33 条方向 0 存活)

第 5 轮存活的 `eu-machinery-ehsr-coverage-per-standard` 揭示了一个看起来很可推广的结构:**判定所需的那张映射表物理上位于一份要花钱买的标准内部(Annex ZA),因此官方免费清单在结构上只能给到书目层;而这类判定又是自我声明的,没有单一受理方。** 第 6 轮沿这条假设定向开采了同族但**不同指令、不同标准体系、不同管辖区**的 33 条方向(ISO 13849 / IEC 62061 功能安全、IEC 60335-2 家电分部、EN 1090-2 执行等级、EN 61439 分部、EN 71 与 MDR 的 Annex ZA 覆盖、EN 45545-2 铁路防火要求集、Eurocode NDP、EN 12464-1 照度表、UL / ASTM / NFPA 美国侧、GB / JIS 亚洲侧),**0 条存活**。

**假设失败的方式本身就是产出——它给出三个前提,缺一即不成立**:

1. **付费墙前提**:那份标准真的要花钱买吗?**只在 EN / ISO / IEC / ASTM 一侧成立。** 实测反例:NFPA 官方 Free Access 页原文 *NFPA makes its codes and standards available online to the public for free*;中国强制性国家标准由 openstd.samr.gov.cn 全文免费公开;JIS 由 JSA 免费阅览。这些体系里"表藏在付费标准内部"从第一句就不成立,不必往下走。**另一半同样要查**:标准**卖**得贵不等于**范围**收费——ULSE 标准商店对每份标准免费公开 Title 与 Scope(2026-09-01 实测 UL 60079-28 页面),所以「我的产品适用哪部 UL 标准」这一格早就被官方目录自己填满了。
2. **书目层前提**:官方清单真的只到书目层吗?**取决于那套标准是按"对象类型"还是按"要求域"编号的。** 机械的 C 类标准按**机器类型**命名,标题不透露它覆盖哪些 EHSR,所以清单确实只到书目层;而实测欧委会实施决定 2023/740 的玩具协调标准清单只有 **11 份**,标题逐条写的正是**要求域**(Part 1 Mechanical and physical properties、Part 2 Flammability、Part 3 Migration of certain elements、Part 12 N-Nitrosamines),与 2009/48/EC 附件 II 各部分一一对应——**清单已经带了那一列**。IEC 60335-2 的百来个分部、EN 61439 的 7 个分部、EN 13001 的数个分部同理,标题即答案。
3. **无受理方前提**:判定结果真的没人收吗?**看那部法规「技术文件应包含什么」的那一条有没有把这次判定的产物逐字列进去。** MDR (EU) 2017/745 附件 II 第 4 点把「哪些 GSPR 适用 × 哪份协调标准覆盖它」这张表直接写成法定提交物,公告机构逐份审——这一格从来没空过。机械那一格之所以还在,正因为自我认证路径下技术文件不交任何机关。

**还有第 4 个前提是老的,但这一轮杀伤最大:表得足够大。** 33 条里有 14 条死在画像①——PL 五档、EXC 四档、SIL 三档、HL 三档、IP 两位数字、EN 1090-2 附录 B 的 12 格。**当日 3 次 G1 实测把这一条钉死了**:`which execution class exc do i need en 1090-2`、`which iec 60335-2 part applies to my appliance`、`which requirement set r1 to r26 applies to my rail component en 45545-2` **三条全部 G1 veto,死法完全相同**——AI Overview 把那张表逐档列全,然后主动索要你的对象参数提出代判("tell me what your appliance does, I can identify the exact IEC 60335-2 part";"share details about your project, I can help you figure out the likely class")。`pattern` = `AI Overview 接管逐对象计算并代算`。**表在不在付费标准内部,对首屏根本不构成障碍——只要它小到能列完,首屏就把它列完了。**

**推论(选源用)**:这条矿脉不是"标准都收费所以到处是机会",而是一条**四重合取**——付费墙 × 标题不透露覆盖 × 无受理方 × 表大到列不完。四条同时成立的地方极少;实测下来欧盟新法规框架(NLF)里也只有机械这一格。**再挖同族之前先用第 1、2 条零成本筛(打开标准体系的免费政策页 + 读一眼官方清单列头),别一上来就跑 G1。**

**证据基数**:33 条方向、3 次 G1、5 个标准体系(EN/ISO/IEC、UL、NFPA、GB、JIS)。处置为**已验证的边界条件**,不是待验证假设——三条前提各有独立现场实证。

##### 第 5 次精化:四重合取还要加第五条——**这个判定服务于谁在卖东西**(2026-09-01 第 7 轮,70 条方向 0 存活)

第 7 轮把上一节的假设搬到一条从未试过的矿脉:**工程设计与施工规范**(欧洲规范 NDP 与国家附件、EN 206/BS 8500 耐久性、EN 1993-1-9 疲劳细节、EN 1090-2 检测比例、ISO 5817/15614 焊接、ASCE 7 美国侧、EN 12845 喷淋、EN 12464-1 照明、IEC/ISO 分级共 70 条)。选它是因为四重合取看起来在这里最可能同时成立:规范付费、官方只发标准编号、**设计判定的结果多数不交给任何机关**(NDP 取值、细节类别、暴露等级只写进设计文件)、参数表可以极大。**结果 0 条存活,6 次 G1 全部 veto。** 失败的方式给出第五条前提:

1. **无受理方这一条在这条矿脉上确实成立**——自我声明的设计判定确实没人逐项收(欧洲规范的 NDP 汇总库 JRC 是有的,但官网原文写明 *The site has restricted and controlled access … only provided to the authorised users*,只对委员会、CEN/TC 250 与各国主管机关开放,第三方拿不到)。**但它救不了这条矿脉**:没人收表 ≠ 没人做工具。
2. **真正的占位者是卖材料的那一方**:钢结构有 SCI/BCSA/Steel for Life 的整套免费设计工具(Blue Book、抗力工具、节点设计器、风荷载计算器…),混凝土有 MPA The Concrete Centre 自 2000 年起免费维护的电子表格(含 TCC-BS 8500,直接吃暴露等级出限值),照明有 400+ 灯具厂商出资、对用户免费的 DIALux evo。**判定是它们的销售前置动作,不是收费点**,所以永远免费、永远维护。完整案例见[陷阱类别十三第六种主体](陷阱类别.md)。
3. **表大这一条同样多数不成立**:70 条里 30 余条死在画像①——后果等级 5 档、可靠性等级 3 档、地基类别 3 档、砌块 4 组、腐蚀性 6 档、场地类别 6 档…**工程规范里绝大多数"判定"是分级,不是查表**,而分级表首屏一列就完。
4. **表确实大的那几条,死法与第 6 轮一模一样**:EN 1993-1-9 疲劳细节类别(约 80 类)、ISO 15614-1 认可范围、ISO 5817 的 26 类缺欠限值、EN 1090-2 表 24 检测比例、EN 12845 占用危险等级、ASCE 7 表 12.2-1 的体系与 R 值——6 次 G1 **全部**是 `AI Overview 接管逐对象计算并代算`:首屏先把规则与因子讲全,再主动索要"你的板厚 / 你的接头构型 / 你的堆高与货物类别 / 你的结构材料",提出替你算。**表大到首屏列不完,并不妨碍首屏把任务接走。**

**据此把选源问法补成第五句**:①有没有官方汇总清单?②清单带不带那一列?③收这份判定的一方有没有以别的形态做完?④起草方有没有免费发判定软件?**⑤这个判定的下游是不是"买哪种材料、买多少"——有没有一个靠卖那种材料赚钱的推广机构?** 五句任一为是即弃,前四句已在此前各轮定,第五句是本轮新加。

**为什么假设错了(这一条要记住)**:免申报 / 免测试类判定同时减少**受理方自己的受理负担**,受理方因此比对普通判定**更有动机**把它讲清楚——判错方向的自我豁免又会给它带来执法麻烦。ROSA 是极限反例:判定的正面结论直接减少欧委会自身的关税收入,它仍然免费做完并维护。**所以第 7 轮那条反向锁不仅命中,还是本轮的主要死因。**

**同时发现一道此前没有的第二道锁,它专治"免测试资格"这一形态**:判定权常被法律保留给**正会因此少一单生意的那一方**。实测防火试验的扩展应用(EXAP):GNB-CPR 与 EA 的规则原文是 *Extended application shall be undertaken by the laboratory which has carried out the relevant fire tests*(SBS 2018 立场文件《Restrictions On SME Notified Bodies Issuing Extended Application Reports And Classification Reports For Fire Resistance》引述),扩展应用报告只能由做过原始试验的认可实验室出具,自助判定不产生可用于 DoP 的结论,实验室随即把它做成收费的 EXAP 服务(如 CSI SpA 的 "EXAP - Extended Application Service")。**"没人有动机免费做"因此往往不等于位置空着,而等于位置被法律封死**——这属闸门契约 G6 第③项`自助结论须第三方签字才算数`,零成本可判。

**两条存活候选真正的共同点要改写**(这是本轮可用的产出):不是"减少某方生意",而是——

> **这次判定的产物虽被法规列为技术文件的法定内容,却在该合格评定路径下不交给任何机关。**

实测对照就在同一族里:PED 2014/68/EU 的技术文件条款(2026-09-01 现场读 EUR-Lex 合并版)原文要求 *a list of the harmonised standards … applied in full or in part, and a description of the solutions adopted to meet the essential safety requirements … In the event of partly applied harmonised standards, the technical documentation shall specify the parts which have been applied* —— 这正是"哪份标准覆盖哪些 ESR"那张映射表,**而 II–IV 类须走模块 B 交公告机构审**,所以 PED 那一格从来没空过;PPE(II/III 类 EU 型式检验)、电梯(一律须公告机构)同理。**机械那一格之所以还在,只因非附件 I 机器走纯自我认证、技术文件不交任何人。**

**据此把选源问法补成第六句**(接在前五句之后,零成本可执行):

> ⑥ **打开那部法规"技术文件应包含什么"的那一条,确认这次判定的产物被逐字列进去之后,再问一句:该合格评定路径下,这份技术文件要不要交给公告机构或主管机关?** 要交 → 受理方存在,弃;**纯自我认证、谁都不交 → 这一格才可能还空着。**

第 6 轮已用 MDR 附件 II 第 4 点给出"列进去且要交"的正例,本轮 PED 给出同族的第二个正例,机械是反例。**同时要注意:不交给机关只是必要条件**——第 5 次精化那条(卖材料的推广机构)与本节这条(判定权被法律保留给检测方)都能在无受理方的情况下把位置填掉。

**方法论提示**:本轮 69 条全部死在零成本层、一次 G1 都没花,是因为把画像④的六句判法排在 G1 之前。这是第 6、7 轮同一条经验的第三次复现,顺序不要倒置。

##### 第 7 次精化:第 6 次那条判据**不是可独立开采的矿脉**,它只是必要条件;真正的绑定约束仍是画像①(2026-09-01 第 9 轮,55 条方向 0 存活、0 次 G1)

第 6 次精化把两条存活候选的共同点写成一句可零成本执行的判据——「这次判定的产物虽被法规列为技术文件的法定内容,却在该合格评定路径下不交给任何机关」。第 9 轮**沿这条判据系统开采「纯自我认证路径」**(欧盟新法规框架里有模块 A / 内部生产控制且全程不需要公告机构的法规,加上英国 UKCA、瑞士、土耳其、中国 CCC、韩国 KC、美国 FCC SDoC、海湾 GSO 的同构自我声明体系,共 28 条方向)。**判据本身站得住,但它开不出新格**:

| --- | --- | --- | --- |

**三部法规都完全满足第 6 次精化的判据——同一条「协调标准清单」条款、技术文件只在市场监督索取时提供、谁都不交——却都因要求侧只有 2 到 23 行而在画像①上差一到两个数量级。**首屏把 10 行列完就等于把任务做完。

**据此把第 6 次精化的地位改写清楚**:它是**第 4 次精化那个四重合取(付费墙 × 标题不透露覆盖 × 无受理方 × 表大到列不完)里第三条的精确化**,不是第五条独立判据。机械那一格能活靠的是**四条同时成立**,而不是「自我认证」这一条;NLF 里满足「纯自我认证 + 技术文件不交人」的法规很多(LVD、EMC、RoHS、CRA、ATEX 3 类、玩具、简单压力容器),满足全部四条的目前**只有机械一家**。**再沿自我认证这条线开采之前,先读一眼那部法规的基本要求附件有几条;少于三位数就不必往下走。**

**同轮的第二个发现(独立,更硬)——「不交任何机关」只保证没有受理方,不保证没有供给方。** MDR Class I 器械是纯自我认证(非无菌、非测量、非重复使用手术器械不需要公告机构),「哪些 GSPR 适用 × 哪份协调标准覆盖它」这张表不交任何人,画像①②③⑤全部成立;**但 2026-09-01 现场实测,欧委会 health.ec.europa.eu 自己就发布了 `Checklist of general safety and performance requirements` 文档**,另有 Pure Global 的免费 AI GSPR Checklist、MedDeviceGuide 的免费证据矩阵模板(自述 *every requirement mapped to applicable harmonised standards*)、Greenlight Guru 免费模板与 OpenRegulatory MDR Templates。这与第 6 次精化里 ROSA 那条反例同型(欧委会连会减少自己关税收入的判定都免费做完),**再次证明第 8 轮那句「免申报类判定受理方更有动机讲清楚」在没有受理方时同样成立**——发证机关的动机不是收数,是让规则被用对。

**同轮的第三个发现——②a(官方计数)与「无受理方」结构性反相关,这解释了第 5–9 轮反复出现的夹逼。** 官方计数几乎总来自一个登记册,而登记册意味着有人在收东西;所以「表够大」的方向往往没有官方计数,「有官方计数」的方向往往有受理方。机械之所以两边都过,是因为它的付费者数来自**一般产业统计**(欧委会 SWD(2021) 82 的 82,239 家),不是一个逐判定登记册。**挑方向时可以直接用这条反查:如果这个主体的人数是靠某个登记册数出来的,那个登记册的运营方多半就是受理方。**

**角度切换(本轮后 27 条)**:自我认证矿脉在 NLF 层 28 条内耗尽后,转去检验一个前八轮完全没碰过的角度——**非产品域的自我评估义务**(职业安全风险评估、化学品暴露评估、环境自我监测、能源审计、管理体系)。**同样 0 存活**,死法正好三面印证上面三条:

- 受约束主体一律是「雇主 / 组织」,按行为界定、范围过广 → ②a 结构性不可得(5 条);
- 有官方计数的那几条(ESOS、DORA 信息登记、取水许可、环境许可自监测)一律有受理方;
- 表确实够大的唯一一条——**逐国职业接触限值矩阵**(2026-09-01 现场实测:28 国 34 份限值清单 × 2,312 种物质 × TWA/STEL/皮肤吸收/粉尘分数,完全满足画像①与画像③)——被 **IFA/DGUV 的 GESTIS-International Limit Values 免费数据库**按 CAS 号逐物质做完,粒度与搜索者对象完全重合。这是 **IFA/DGUV 第二次**以免费判定工具占位(第一次是第 6 轮的 SISTEMA),见陷阱类别十三第五种主体。

##### 第 8 次精化:五条合取里的③④**在欧盟与英国之外结构性同时失效**——非欧盟的合规体制是「注册型」,不是「自我声明型」(2026-09-01 第 10 轮,55 条方向 0 存活、1 次 G1)

第 9 轮把两个存活候选的共同点提炼成一条最强的正向选源键——**受约束主体的官方计数来自一般产业统计或立法影响评估,而不是逐判定登记册**(机械 82,239 家来自 SWD(2021) 82、CWFT 430,000 家来自影响评估 CELEX 52022SC0088)。第 10 轮把它与已验证的四重合取合成**五条合取**,并**换到前九轮完全没扫过的管辖区**去检验:美国联邦规则引用付费共识标准的一族(33 条)、非欧盟主要强制符合性体制加英国专有要求(22 条)。**0 条存活**,而失败方式是同一条:

> **合取③(判定产物不交给任何机关)与合取④(计数不来自登记册)在欧盟新法规框架之外几乎必然同时失效,因为那些体制从设计上就是「先注册后上市」,而不是「自我声明、事后市场监督」。** 同一个国家系统一手当受理方(杀③)、一手当官方计数源(杀④)——不是两次巧合,是一个东西。

### 零成本第一问:这次变化究竟新增了什么(2026-08-25 新增)

**盯对了源头,还要先过这一问,否则会把大量根本不产生任务的变化当成候选注册进账本。** **执行位置在触发池的 `approve` 之前**——生命周期契约要求官方变化的标题先落 `触发池.jsonl`、补齐 task query 与商业预检后才可批准进入 G0;本问就摆在那道批准之前,答"只是取消/推迟/预告/延期/延续/修补/减负"的 trigger 直接 `discard`,连 task query 都不必去找。判定动作只有一句:读官方公告自己的标题与摘要,问——**这次变化是新增了一项义务,还是只是取消、推迟、预告、延期、延续、修补或减负?**后者一律零成本弃,不进 G0 之后的任何一步。

| ⑦只是解决两部法之间的冲突 | `ca-atlantic-offshore-framework-2026`:RIAS 的 Issues 段明写 *a conflict has been identified with the Canada Shipping Act, 2001* |
| ⑧明确以减负为目标 | `ca-fish-habitat-authorizations-2026` 源于 Red Tape Review,目标是 *cutting red tape* 与 *reduce burden*;`ca-industrial-effluent-amendments-2026` 是 omnibus 包,目标是 *provide flexibility and clarity*;`uk-wireless-telegraphy-exemption-2026` 新增的是三类豁免 |
| ⑨对既有法规的纯技术性修订 | 英国 SI 那一批 107 个里有 **68 个**属此:剔除例行条款后,实质条文要么为零、要么近乎全是 *Amendment of…／Insertion of…／Revocation of…*、要么不超过两条 |

**为什么这一问值钱**:它在打开任何 SERP 之前就能筛掉相当大一部分变化面候选。实测比例——加拿大那批 23 个里 7 个(30%)死于此;英国 SI 那批 107 个里 68 个(64%)死于形态⑨。而这些候选此前是按"有日期的官方变化"被批量注册进账本的,每一个都要占一次还债配额才能出清。

**这一问不覆盖什么**:变化虽小但**确实新增了一项要逐对象反复做的判定**时不适用。判据是"有没有新增义务",不是"篇幅大不大"——一条新增条款也可能开出真任务,而一份几十页的修订也可能只是把旧条文重排。

## 广告线的选源方法:成熟错价词道(mature lane,2026-08-23 新建)

**本节与上一节的正向选择器分属两种选源偏好,不要混用。** 上一节的义务雷达优先发现 subscription / lead_generation / transaction / paid_report 等高价值低量级机会；本节优先发现 advertising / affiliate 的成熟流量机会。它们不是六条盈利线的封闭清单，进入 G6 后仍完整检查六线。广告线的 $200/月仍是该线硬门；“查无”只使 new 道 advertising=`N/A`，不否决其他五线。

账本的 `lane` 字段因此开放为 `new` / `mature`(schema 原本就写着"为未来成熟词道预留")。本节的方向一律以 `--lane mature` 注册。

**本节的执行载体是 [xinci-mature](../xinci-mature/SKILL.md)**(2026-08-29 新建)。此前本道没有任何 skill 承接前半程,只能手工照着本节从头走——两个月只跑出 4 个种子,直接原因就是这个。判据仍以本节为准,skill 只负责把它串成可执行的层次;**skill 是单步形态,不接入 xinci-run 的自动循环**,理由是本道累计 0/4、方法尚未验证。

### 数据政策的关键差别:mature 道不适用新词道的 Semrush 禁令

新词道禁用 Semrush/KD/CPC/Trends 的**唯一理由**是"天级新词查无是本赛道的定义属性,查了也说明不了任何事"(闸门契约时间光谱)。这个理由在 mature 道上不成立——本道必须用可测量的历史需求证明它确属 mature 查询；但具体量级门槛只约束依赖流量的盈利线,不是六线共用的整候选硬门。

所以 mature 道从第一步起就允许并**要求**取量级数据。同时保留新词道那条已被实测证明的立场:**KD 不作为鼓励**。契约记录的三组背离都是同一个方向——KD 14 对实测竞争 89、KD 27 对 71、KD 44 对约 85,**指标看起来容易、实际都更难**。因此:

- **量级数据(搜索量)用来证明 mature 需求存在,并判断 advertising / affiliate 等流量线是否有足够规模** —— 不得把广告门槛套给 subscription / lead_generation / transaction / paid_report
- **KD / Authority Score / 外链数不得决定 G2/G3 或直接挣竞争分** —— 那三组背离说明域名强度代理对此完全失明。门结论只由 G2 完整结构阅读与 G3 条件化占位审计(先得原始占位判断,再按盈利线映射有效门结论)判定;确认期的流量、覆盖词量、增速是“实际占据”footprint,只作评分与风险输入

### 要找的是什么:反向错价

三组背离证明了一个方向的错价确实存在(**看起来容易、实际难**)。本道要系统性找的是它的**反面**:

> **量级真实存在,而 SERP 被守得很弱。**

**执行顺序:先算流量线的钱,再看防守**(首轮实测把原稿的顺序改了过来,见下修订四)。一次 Semrush 查询先读两个数做流量线前置过滤——簇内词总数 N < 约 1,000,或前 15 行合计 < 约 50K 且无单词 > 10K 时,advertising 暂定否决,affiliate 也必须按购买意图与可归因流量重新证明；**这不直接淘汰整个候选**,还要完成其余四条非流量线。阈值只来自 3 个样本,须按真实结果继续调。若所有可用线都依赖流量且本层全否,才无需继续昂贵 SERP 阅读。并且记住:量级、RPM 与弱守**互相反相关,是一个乘性夹逼**,不是三个可分别满足的条件(见下修订一与闸门契约 G6)。

"守得很弱"不是靠指标判的,是靠现场读出来的。可用的弱守信号(全部来自 G2 已有的放行信号与 G3 第一问,不新增判据):

1. **占位者是内页、小站、论坛帖**,而非专做这件事的站(G2 原有放行信号)
2. **内容明显老化**且该题目已经变了 —— 首页结果日期集中在数年前,而规则/产品/价格已经改过
3. **没有真工具**,任务要求算/查/比,而占位者只有散文(G3 第一问)
4. **格式错配** —— 查询要的是表格、清单、计算器,排上来的是长文
5. **意图错配** —— 排名页面答的不是这个问题(例如物流"配送路线"占了"网络路由"的位)
6. **没人把这一格当生意经营** —— 无付费产品、无按任务成簇、无维护痕迹(G3 补充判据)

**六条里中三条以上才算弱守**,并且必须写明是哪几条、附现场证据。只中一两条的按正常竞争处理。

### 反向排除:本道最容易踩的三个坑

这三条来自本次调查的实测,不是推理。YMYL 与横向对比可在 SERP 前按任务类型筛除；“成熟工具词”必须在 G2 完整阅读首页后才能判，不得归入零成本层:

- **成熟工具词**(索引 pattern「成熟工具词」已累计多次):量级是真的,但那是多年被争夺过的赛道,弱守信号往往只是错觉。凡 G2 首页出现专做这件事的站,立刻停。
- **YMYL 高竞争垂类**:凡题目影响**健康、财务、安全或法律权利**的一律按 YMYL 处理——按类别定义,举例(健身/补剂/交易/健康/法律)仅作说明,不构成清单(原稿只列例子、漏掉法律,种子 A 正栽在这里,见下修订三)。这类常青问题量级极大,但那是全网竞争最凶的一档(2026-08-21 第 5 轮实测)。
- **横向对比与迁移**(陷阱类别七):`alternatives to X` / `X vs Y` 这类量级也真,但该对象类有自己的全集维护者——替代品目录站、分析机构榜单、社区 awesome 清单、竞品自建对比页。

### 2026-08-23 首次检验:命中率 0/3,并据实修订四处

三个种子,全部淘汰,**命中率 0/3**。但三次淘汰的死因不同,连起来暴露了本节原稿的两处设计错误。

| 种子 | CPC(RPM 代理) | 簇规模 | 前 15 行量 | 死因 |
| --- | --- | --- | --- | --- |
| `statute of limitations`(法律时效) | **$4.07–12.11 高** | 10,000+ | 111.6K/月 | **防守**——量级是过的 |
| `cost per square foot`(每平方英尺造价) | **$1.15–2.68 低** | 10,000+ | 31.0K/月 | **量级**——RPM 低,需 66.7 万 |
| `commercial rent per square foot`(商业租金) | $2.85–4.85 中 | **290+** | 0.67K/月 | **量级**——簇本身太小,差两个数量级 |

#### 修订一(最重要):量级、RPM 与弱守不是三个独立条件,它们互相反相关

原稿把"要有量级"和"SERP 守得弱"并列成两个要检查的条件。三个种子说明它们**是彼此的对立面**:

- **高 RPM 意味着商业价值高,商业价值高就会招来把这一格当生意经营的人** → 防守必然强。种子 A 的 CPC $12.11 不只是"RPM 代理",它**本身就是这一格里有钱的直接证据**:有人正在为每一次点击付 12 美元。
- **防守弱的地方,通常正因为商业价值低** → RPM 低 → 需求量级反而暴涨。种子 B 的 RPM 约 6,需求量级被抬到 66.7 万/月。
- 窄 B2B 垂类兼具好单价与无总量(种子 C)。

**因此"高 RPM + 无人经营"在成熟词上接近自相矛盾。** 广告线要的是 量级 × RPM 大 **且** 防守弱,而前两项与第三项系统性反相关。这是一个乘性夹逼,不是三个可以分别满足的条件。原稿没有说出这一点,是它最大的缺陷。

#### 修订二:原稿四类源头里有两类在结构上自带陷阱类别六

- **来源类型一「官方/权威页面排在首位但答不全」**——它的前提就是权威页在场,而权威页往往正是**管辖机构自维护的对象全集**。种子 A 死得一字不差:#1/#2/#4 是佛州官方法条(`leg.state.fl.us`、`flsenate.gov`)。
- **来源类型二「规则、价格改过之后的老查询」**——规则由管辖机构维护,改了规则的同一个机构会同步它自己那一页。

**这两类源头等于把陷阱类别六写进了选源条件。** 修订:两类都降为**次级**,采用时必须先做一次零成本判断——"这个对象全集有没有一个法定/事实上的维护者?"答有即弃,不必再读 SERP。**结构上可靠的只有类型三(逐对象查表)与类型四(论坛反复人肉回答)**,今后优先用这两类。

#### 修订三:YMYL 排除原稿只列了例子,没画出类别边界

原稿写的是"健身/补剂/交易/健康类"。**法律不在这几个词里,而种子 A 正是法律。** 诉讼时效直接影响人的法定权利,是 YMYL 的核心地带。修订为按类别定义而非举例:**凡题目影响健康、财务、安全或法律权利的,一律按 YMYL 处理**,举例仅作说明,不构成清单。

#### 修订四:执行顺序反了——先算钱,再看防守

原稿先列六条弱守信号,量级放在后面隐含。但实测里**种子 B 与 C 根本不需要读 SERP 就死了**:一次 Semrush 查询同时给出簇规模与 CPC,两个数就够判。修订为量级前置,并给出实测出来的两个门槛:

```
一次查询读两个数:簇内词总数 N,以及前 15 行的量与头部词量

弃 ①  N < 约 1,000            → 簇太小(种子 C:290)
弃 ②  前 15 行合计 < 约 50K
      且无单词 > 10K           → 太扁平,长尾堆不出量(种子 B:31.0K,最高 4.4K)
过     进入弱守信号与 SERP 阅读(种子 A:头部词 60.5K、前 15 行 111.6K,正确放行)
```

**这个前置过滤器本轮三个种子全部判对**(B、C 正确拦下,A 正确放行后才死在防守),但它只有 3 个样本,阈值是从这 3 个数里读出来的,不是从分布里估出来的——**必须继续按真实结果调**。

与订阅线那条 G6 修订是同一个教训:**先算钱,再看竞争**。

#### 修订五:类型三要挑"答案是一个数字",不是"答案是一件可购买的商品"(2026-08-23 同日第二批探针)

同一天用类型三(逐对象查表)做了两个 SERP 探针,结果完全相反,差别只有一处:

| 探针 | 弱守信号 | 首页占位者 |
| --- | --- | --- |
| `2015 honda civic lug nut torque spec` | **4–5/6,过** | 9 条里 6 条论坛帖(Honda-Tech、CivicX、CivicXI、civic11forum、Reddit),第 1 条是 **2009 年 1 月**;结果之间还互相矛盾(80 ft-lbs 对 94 ft-lbs,一条标题写着 "Owners Manual Wrong!") |
| `john deere d130 mower deck belt size` | **0–1/6,完败** | Amazon / Walmart / Home Depot / Lowe's 与购物卡片;V-Belt Guys 已把逐型号适配表建成生意,直接给出 0.50" × 104.00" |

**判据**:逐对象查表的任务里,要挑**答案是一个数字或一个判断**的,避开**答案是一件可购买的商品**的。

机制很直接:**没人卖"80 ft-lbs"**,所以没有零售商有动机去建那张逐车型扭矩表,论坛就成了唯一供给;而"D130 用哪根皮带"的答案是一个 SKU,零件商建那张适配表就等于建自己的商品目录,于是第一天起就没有位置。

这条也让上文的夹逼更精确:**钱直接挂在答案上时,有人会去建这张表**。真正的缝隙在"搜索者即将花钱、但答案本身不是 SKU"的地方——扭矩规格正是这种(查完要去买轮胎或工具,但那个数字本身不卖钱)。这是一个带机制的假设,**尚未验证量级,不要当成结论。**

#### 修订五的后续:该机制推断已被证伪一半(2026-08-25 复审 `vehicle-fastener-torque-specs`)

**判据本身(数字 vs 商品)仍然成立,被推翻的是它后半句的机制表述。**上面写"没人卖 80 ft-lbs,所以没有零售商有动机建那张表"——零售商那半句是对的,**但"所以没人建"这个推论错了**:零售商没动机,**持牌数据商有**,而且早就建好了。

2026-08-25 复审该方向时,订阅线一侧现场查到五层覆盖:

- **免费**——`torkspec.com` 仍在运行(当日实测 HTTP 200),首页写明 *FREE Car Maintenance Software for the DIY Mechanic* 与 *Find Torque Specifications*;ASE 认证技师的社群里就是直接互相推荐它;
- **$3.61/月**——ALLDATA DIY 单车订阅(1 个月 $19.99、1 年 $59.99),自述提供 *original factory repair information that professionals use*;
- **$29.95/年**——Mitchell 1 DIY;
- **专业版内建的专门功能**——Mitchell 1 的 *Torque Specifications Made Easy*(可直接打印扭矩规格表)、ALLDATA 的 *Specifications Quick Reference*;专业版本身是 $209/月;
- **零件商附送**——BCA 的 Torque Specification Lookup Application(随其轮毂轴承产品线)。

**为什么 8-23 那次没看见这些:那次只跑了问句式措辞。**两个探针 `2015 honda civic lug nut torque spec` 与 `cylinder head torque specs chevy 350` 都是"具体对象 + 规格"的问法,看到的确实只有论坛帖、旧页面和互相矛盾的数字。8-25 换成产品向措辞 `torque specs database lookup by vehicle app subscription`,**一次检索就全部浮出来**。

**所以这里要补的不是一条新判据,而是一条早已存在、却在 mature 探针上被漏掉的强制要求**:闸门契约 G3 第一问要求**用户问句式与产品向两族措辞各检索一次,缺一不可**。该要求写在 new 道的语境里,但它约束的是"数占位者"这个动作本身,**mature 道的弱守信号判读同样适用**。只按问句式读弱守,会系统性地把"论坛帖占屏"误读成"没人经营这一格"。

**推广到一般:问"谁有动机建这张表"时,候选答案不止零售商。**至少还有:持有数据授权的专业数据商(本例的 ALLDATA、Mitchell 1)、发证或管辖机构、行业协会、以及把该功能并进既有产品的软件厂商。这与陷阱类别十"四问不要过早锁定答案"是同一条纪律——**先看证据指向谁,不要先挑一个再去凑**。

**该历史方向当时的处置**:advertising 与 subscription 都不过。按现行六线契约，这只证明两条线失败；若要继续作为正式 no-go，还须审完其余四线，不得引用为“六线均 veto”的证据。

### 2026-09-02 来源组合与产能口径（冲突时以本节为准）

来源分配不再只按“换域名”计覆盖，而按任务家族与实际漏斗产出计。每轮在 `record-round` 记录 `source_family_counts`、`source_family_outcomes`（逐来源 formal/G1 pass/deep/tracking）、`task_families`、G1 次数与深审 family；清单自动汇总到状态迁移。初始组合为 50% 已验证高产来源、30% 相邻任务来源、20% 探索来源；每个校准周期依据状态迁移和假阴性结果调整，而不是依据 raw 提取量自我奖励。

一轮仍可广度提取 200–300 个原始方向，但人工/浏览器瓶颈按独立任务 family 管理：G1 常态 30–50 次、深审最多 5 个。十轮的理论上限因此不是 2,000–3,000 个“完整分析”，而是约 300–500 次 G1 与最多 50 次深审；机器清单必须分别报告 raw/formal/G1/deep，禁止把 raw 提取数包装成已分析数。

校准轮用 `false_negative_sample.py` 从索引和账本按 G6/G7/G5/G1/G3 分层抽样。发现 false negative 时，先修闸门或模式别名，再受控重开；不得因为想提高命中率而降低正式 pass 标准。

#### 本轮的方法学限制(不掩饰)

- **样本 3 个**,而且是我按假设挑的种子,不是随机抽样;三次淘汰不能证明这条线整体不可行。
- **免费版 Semrush 每次只给 15 行**,所以"前 15 行合计"是簇量的**下界**,不是簇量。真实簇量更大,但大多少未测。
- **RPM 全部由 CPC 推断,没有一个是实测的**。RPM 与 CPC 正相关但不是同一个数,推断可能整体偏高或偏低。
- 只有种子 A 做了 SERP 阅读,B、C 死在量级前置,**它们的防守强弱至今未知**。

### 本节的诚实状态

**历史已跑两轮:4 个种子,命中率 0/4**。其中第 4 个只审了 advertising / subscription；它可用于校准成熟流量选源，但按现行六线契约不能直接证明整候选 G6 否决。后续复核必须补齐其余四线。

**这条线至今没有一个正例。** 0/4 证否不了什么(样本太小、种子是我按假设挑的),但它也没提供任何可行性证据。更值得注意的是第 4 个种子的死法:它是**唯一一个量级实测通过、弱守信号也通过、却仍然出局**的种子——量级与防守都对了,死在第三件事上,即那一格早已有人以免费或近乎免费的价格在供给。**因此现行执行流程固定为三步:先算钱、再看防守、最后在 G3 核对是否已有免费或近乎免费的同任务供给。** xinci-mature 已承接这第三步，不得把“弱守通过”直接当作存活结论。继续跑的每一轮都要记命中率并据实修订——与订阅线那七条正向选源信号同一个纪律:**不要把它当定律。**

## Semrush 探针纪律(按赛道分,新词道仅形成期起;阶段按**状态**判,不按年龄)

**先分赛道,再看阶段**(2026-08-23 修订)。下面的分阶段禁令**只约束 `lane=new`**:

- **`lane=mature`(成熟错价词道)从第一步起就允许并要求取量级数据**。理由:新词道禁用的唯一依据是"天级新词查无是定义属性,查了说明不了任何事",而 mature 道必须先证明历史需求可测；具体量级门槛只约束 advertising / affiliate 等流量线,不连带否决其他盈利线(见上文「广告线的选源方法」)。
  该道保留一条硬限制:**量级数据不得决定 G2/G3,也不得把广告量级门套给非流量线;KD、Authority Score、外链数不得直接挣竞争分**。契约记录的三组背离(KD 14 对实测 89、KD 27 对 71、KD 44 对约 85)证明域名强度代理对 exact-task 竞争失明;门结论只由 G2 完整结构阅读与 G3 条件化占位审计判定,且 G3 必须把原始占位判断按盈利线映射成有效门结论。确认期的流量、覆盖词量、增速只衡量实际市场占据。

- 每一次计费查询必须能够改变一个决策;为满足流程而跑的查询是禁止的。决策不变,查询不跑。
- **(仅 new 道)**窗口期(`captured` / `screened`,参考年龄 0–14 天)禁用 Semrush / Trends / KD / KGR / CPC:天级新词查无是定义属性,查了也不能说明任何事。
- **(仅 new 道)**形成期(`tracking`)允许轻量探针:自动补全出现与否、首批关键词行出现与否——都是"形成信号"证据,不是资格证据**零建议不是否决**,完整说明见上「自动补全:有建议是正证据,零建议不是否决」。
- 确认期(`formation_confirmed` 起)的完整竞争审计以 live SERP 的 exact-task 阅读为主,Semrush 数据为辅;竞品 footprint 实测(authority、流量、词量、增速)必须至少做一个。authority 只作背景记录;流量、覆盖词量、增速用于衡量实际占据,只进入评分与风险说明,都不得反向改写 G2/G3。**进了 formation_confirmed 就按确认期解禁,不看候选几天大**——最快第 7 天就会到这一步(见闸门契约时间光谱)。
- 环境适配:Codex 环境有 `$export-keyword-csv` skill 时按它的界面路标与预览纪律操作(preview 优先,全量 CSV 必须能改变决策才导);没有时手工走 Semrush UI:Keyword Magic 输入种子 → 看前 50 行预览 → 只记要点进观察文件,不整页转录(数据极简)。
