# 数据采集指南

## 真浏览器原则

扫描与复查一律在真实浏览器里打开来源页面阅读,不通过 API、搜索接口或 MCP 数据工具拉取 Reddit / X / Product Hunt / Hacker News 等社区内容。要下的判断是"这像不像人们会去搜的东西",它来自读真实页面——社区怎么谈论它、用什么词称呼它、名字是否稳定;API 结果集会剥掉这层语境(依据:校准 §14.1)。

### 适用边界:社区面必须浏览器,变化面可结构化采集

- **社区面**(Reddit / X / Product Hunt / Hacker News / 即刻 / 应用商店)一律真浏览器。
- **变化面**(有日期的法规/政策/平台规则/release notes)要取的是结构化事实——什么变了、哪天生效、影响谁——允许用源自带的列表页、RSS、导出接口批量采集,一次拉一批;广度扫描要把素材量提到数百条/轮。
- **G1/G2/G3 一律真浏览器**——SERP 判断本身就是语境判断,任何阶段都不得用接口替代。
- 无论用哪种方式采集,**未在本次会话实际取回的来源不得声称已检查**。

配套纪律:

- 每次运行把实际打开的 URL 记入 `运行/<日期>-<skill>.json` 与观察文件的 `source_urls`。凡 observation 提交 gates,支撑该 gate 的 source_urls 必须非空且随同一次 registrar 写入提交;registrar 逐门核对,不能用另一份无关观察替代。
- 记录精确措辞和来源 URL;凭记忆重构的词不是证据。

通道分工:

- SERP 必须走**干净的未登录通道**——那是 G1 结论成立的前提,不可替代。
- 被 JS 挑战拦住的普通网页可以交给用户已登录的浏览器——正文与登录态无关。别在一个通道上反复重试,先问这一页要不要干净环境。

**HTTP 200 不等于取到正文。** 批量取回后先验一次正文长度与内容形态,再据以写判定;外壳页通常只有一两千字且全是导航词,页面导航目录里的 `Schedule` / `Part` 字样不是正文(依据:校准 §14.2)。

### 分组方法:用条文结构决定哪些要逐个判

取到英国 SI 的条文标题后,剔除 `Citation` / `Commencement` / `Extent` / `Interpretation` / `Application` / `Revocation` 这些例行条款,再看两个数:剩余实质条文有几条、其中 `Amendment of…` / `Insertion of…` / `Revocation of…` 形式占多大比例。

- 实质条文为零、或修订条款占比 ≥80%、或实质条文 ≤2 → 归「零成本第一问」的形态⑨,按类处置;归类后仍逐个扫过法规全称,确认没有藏着重大新义务的。
- 其余 → 逐条读条文标题,单独判死因。

同样的思路可迁移到其他有稳定条文结构的源。

## G1 SERP 读取规程

环境、容器、读的时机三条任一不满足,该次观察不得支撑 G1 结论,须按本规程重读;读到的数字按「数字两步核实与日期回源」核实后才能进判据(依据:校准 §14.4、§14.5、§14.6)。

### 环境参数(美区、桌面、未登录)

- 用无痕/隐私窗口打开搜索,压掉登录态;
- 搜索 URL 显式带参数:`https://www.google.com/search?q=<精确词>&gl=us&hl=en&pws=0`(gl=us 美区、hl=en 英文、pws=0 关闭个性化);
- 连续运行在每轮开始时由本轮实际执行者在 `begin-round` 里提交可控性、桌面、美区与未登录四项预检,再调用 `run_policy.py`。预检绑定执行者与当前轮;父任务、其他子代理或上一轮状态不可借用。
- 任一条件达不到时进入 `trigger_only`:可以采集官方变化并保留搜索语言假设,但不得写 G1、不得把缺 G1 的新方向注册为 captured,也不得以 queued 冒充推进。单步模式可以记录受污染观察,但不能据此下 G1 结论。

### 容器自检

- 浏览器工具里"提取页面主要内容"的读法(Claude Browser 的 `get_page_text`、以及一切先找 `article`/`main` 容器再回退的实现)在 Google SERP 上会选中 web results 容器、整块跳过 AI Overview,且不报错、看不出少了东西。用它判 G1 会把该 veto 的候选判成 pass。
- 正确读法:用 JavaScript 读 `document.body.innerText`(或等价的整页文本),再在其中检索 `AI Overview` / `Featured snippet`。
- 自检:读回的文本若从 `Web results` 或第一条自然结果开始,而不是从 `Skip to main content … Search Results` 这类整页开头开始,说明选错了容器,该次观察作废重读。

### 等待与占位词自检

AI Overview 在页面 `load` 之后异步生成;导航返回、DOM 就绪、整页 `innerText` 能读出来时,区块可能还不在,也可能只有占位符,两种情况都看不出少了东西。延迟不是恒定的,"等 N 秒"不能当通过条件,载重的是自检:

1. 导航后等待若干秒再读整页 `innerText`;
2. 读回的文本里出现 `Thinking` / `Searching` / `Thinking a little longer` 这类占位词,说明还在生成,等待后重读;
3. 文本里完全没有 `AI Overview` 字符串时,不得直接判定"该词没有 AI Overview"——隔几秒重读一次确认,重读后仍没有才算真的没有。

观察里记下了占位符却没有重读的 G1=pass 不可靠,须按本规程重测。

### 数字两步核实与日期回源

AI Overview 给出的带出处标注的具体数字先当线索,不当证据。任何要写进判据的数字(尤其是 G6 第④项的受约束付费者数)必须先核实再用:

1. **把数字加引号精确检索一次。** 零结果说明它在网页索引里不存在,是合成的。
2. **打开它指名的来源,在正文里找到那句话,并确认这份来源计的是同一个总体**——同一个数字挂错法令、错年份、错地理范围、错主体口径,在原文里都能逐字找到;第一步过了不等于可以跳过第二步,两步查的是两件事。
3. **日期类事实(生效日 / 截止日 / 适用日)回到发布机关自己的页面确认它当前仍然有效**——没有被后续文件撤销、延期或替代。合成模型按语料里的历史陈述作答,被撤销的规则在语料里留下的痕迹比撤销公告多。

核不过的数字按"未取得"处理——宁可让候选卡在 `captured`,也不要用一个合成的数字把 base case 撑起来。

派生的选源纪律:以"某某截止日是哪天"为核心的措辞在结构上就是死的——截止日是已存在的固定事实,首屏必然做完(与陷阱类别十二收窄后的判据是同一件事)。日期只用来定位窗口,不当搜索措辞。

## 自动补全:有建议是正证据,零建议不是否决

- 唯一合法用法:出现相关建议,是"这个说法已经在被搜"的正证据,可以抬高该方向的优先级。
- **零建议不构成任何否决**——它不在 G0–G8 里,也不得作为零成本预筛的独立死因。自动补全的触发门槛是搜索量,而本赛道的定义属性正是低量高值的 B2B 义务,用按搜索量筛的信号去找刻意避开搜索量的机会,方向是反的(依据:校准 §14.7)。
- 种子措辞用人们的说法,不用法案自称:带 `recast` 一类立法术语的种子会系统性假阴性。查需求侧至少换两族措辞(问句式 + 产品向),与 G3 数工具的两族措辞要求同理。
- 自动补全**不能**用来推断供给侧是否已被占位。供给侧只能靠 G2 完整结构阅读与 G3 两族措辞实测,没有零成本替代。
- 与「Semrush 探针纪律」里"自动补全出现与否是形成信号证据,不是资格证据"是同一条。

## 零成本批的一条前置纪律:先核对对象的真实年龄,别采信来源的"新"标记

- 来源列表标的"新"往往是那条记录的年龄,不是对象的年龄。
- 零成本批(G0/G4/G5 与 G6/G7 预筛)固定加一步:从对象自身的官方页面或文档上读出它的首次发布日期,不采信列表页的排序位置、标签创建日或摘要里的 "new / newly published"。这一步零成本,能省掉后面的 G1 与 G3(依据:校准 §13.10)。

| 日期 | 来源给的"新"信号 | 实际年龄 |
| --- | --- | --- |
| 2026-08-21 | Google 摘要把一条 ASTM 规范描述为 "newly published" | ASTM 13 年前的新闻页,规范实为 `ASTM E2772`(2013),同族 `E2742` 已于 2020 撤销 |
| 2026-08-21 | r/LocalLLaMA 当日榜上的 `Deepseek V4 Flash-0731` | `0731` 即 2026-07-31;同问题线程可追到三个月前,ApX 已逐个建页 |
| 2026-08-22 | Stack Overflow 新标签榜,`falkordb` 建于 2026-08-16 | FalkorDB 博客文章日期 2025-03-12,对象至少 17 个月大 |

## 正向选择器:优先找"义务",不是找"新词"

"一个措辞变新了"买不到窗口:消费者/开发者面答案与对象同时到,企业合规面答案早于义务到——位置在任务出现之前就被占,因为"预期"本身可变现(依据:校准 §4、§14.9)。所以触发条件是:

> **一个义务被公布了,而占位者只写了文章、没做那个工具。**

这里的"触发"是原料,不是 candidate。官方标题、法案全名和公告标题先写入 `触发池.jsonl`;只有找到用户实际搜索的 task query 和独立搜索语言证据,并完成 payer / repeat unit / self-serve path / base-case source 商业预检后才能批准进入 G0。

### 七条正向选源信号(用于排序,不是七道额外硬门)

七条信号用于**先扫谁、同层候选谁优先拿到深审配额**,不是在 G0–G8 之外再造七道硬门(依据:校准 §2 结论三、§14.10)。

- 强制入口仍以闸门契约为准:先过 G0/G4/G5/G6–G7 零成本预筛。
- 其中"有预算的付费者逐个对象重复完成"只直接建立或否决 subscription,答否后仍须检查 lead_generation、affiliate、transaction、paid_report。
- 其余信号用于建立逐线暂定结论、判断耐久性与排序;某一项缺失时按对应闸门处理或留在 `captured` 补证据,不得因为"七条未全中"一句话直接秒弃。

1. **义务施加给企业**——不是消费者、不是政府机构、不是读文档的个人开发者
2. **要求逐个对象重复计算或证明**——每个 SKU / 场址 / 批次 / 市场各做一次,不是读一次就完。要写明是哪一种:"逐管辖区 × 逐废弃物流反复注册核对"(真正持续,天然带复购)还是"每个产品判定一次"(判完就完,复购靠产品线扩张或法规更新)——它直接决定 G6 的单价与留存假设
3. **存在多管辖区差异**,使"汇总本身"成为资产(如 27 个成员国 + 英国各有本国要求与押金制度)
4. **有明确生效日**,产生时间压力
5. **违规有实质后果**(罚款、禁售、审计风险)
6. **官方发布法条但不提供逐对象的计算工具**。零成本层先查一句:发证机关自己有没有发计算工具、模板或 Excel?有 → 直接弃,不进深审
7. **同一周期的受约束付费客户数 × 可行单价 − 获客与交付成本**有初步出处且 base case > 0,可作为窗口期 `subscription=tentative_pass` 的证据;确认期仍须重取正式证据并由 G6 判定,金额大小进入收入可行性评分

信号 8(旁证,不参与任何硬门):SERP 上的付费广告密度是 G6 付费者价值的正向旁证,应作为 G6 估算的旁证记下;它同时意味着自然位要与投广告的对手同场,这一点计入决策阶段的评分,不构成 G3 否决。

第 6 条的两个配套:

- **官方不提供工具 ≠ 位置空着。** 要再问"谁有动机做这个汇总"——若答案是卖相关产品的厂商(零售商、合规软件商、PIM 厂商),他们会用内容营销占住它且更有优势。
- **豁免口:发证机关发布了"可检索的表本身",不等于它发布了"逐对象判定工具"。** 前者不触发第 6 条的秒弃,后者才触发。分界是这个官方工具吃不吃进搜索者的对象:

| 官方发布的东西 | 吃不吃对象 | 第 6 条是否成立 |
| --- | --- | --- |
| 欧委会 CosIng | 只按单一物质查它的 Annex 状态,不吃整份配方 | 不成立,不弃 |
| 欧委会 EMDN 浏览器(`webgate.ec.europa.eu/dyna2/emdn/`) | 只按术语检索表本身,不吃器械描述、不输出该器械的码 | 不成立,不弃 |
| ECHA 生物杀灭剂库 | 查条目不判对象 | 不成立,不弃 |
| BIS Know Your Standard | 吃产品,直接返回适用标准 | 成立,零成本弃 |
| CBAM 官方计算器 | 吃申报数据出结果 | 成立,零成本弃 |

判法问两句:**①那个工具吃什么粒度?②搜索者的对象是什么粒度?**两者重合,它就是判定工具,豁免口不适用。要词还是要对象不是工具的固有属性,而是它的输入粒度与搜索者对象的粒度对不对得上——搜索者的对象本身就是那一个单一物质(如 CAS 号)时,同一个物质检索工具就变成判定工具,第 6 条照常秒弃。

### 反向用法:官方登记册粒度错开时,它是原料源,不是竞争者

判据 6 判"不成立"的官方登记册,反过来是最便宜的零成本判据来源。例:EUR-Lex 的 National Transposition Measures(NTM)对搜索者只是书目索引,但它一页给出某部指令 27 国的转化截止日与已通报措施数,是判断"这张矩阵此刻有没有行在动"的最快判据:

- **0 条通报** → 窗口未开,搜索需求不存在 → 零成本弃
- **27/27 全通报** → 窗口已过,矩阵已定型 → 零成本弃
- **中间态**(如 2/27、6/27) → 窗口当期,才值得往下跑 G1

推广的问法:每当判据 6 判出"这个官方东西只是索引,粒度错开",紧接着问一句——它能不能反过来给我一个零成本的时点判据或计数判据?

### 正向画像:存活候选长什么样

从活到 `tracking` 的候选反推(依据:校准 §14.12),**五条画像用于选源排序而不是整候选硬门**:

1. **那张表是多维交叉的,不是一列**——≥3 个维度,条目数在数百到数千量级。这一条是与已死样本的分界线:4–5 行的默认排放因子表、5 级 producer 决策树,首屏列出即完成(见陷阱类别十二);维度一多、行数一大,首屏只能讲方法。
2. 措辞是 **`which ... applies to my <对象>`**——对象是搜索者手上那台机器、那个器械、那个产品,不是厂商的公共对象。
3. **逐台 / 逐 SKU 重复**,不是一次性判定。
4. **发证机关只发表、不发判定工具**——按判据 6 的粒度两问确认它错开。
5. 受约束主体有**可用的官方计数**或其他可验证规模口径,能支撑依赖市场总量的算式。缺该口径会降低此类方向的选源优先级,但只否决依赖该口径的盈利线,不越权否决整候选。

怎么用:凡是产品合规领域里带**分类表 / 限值表 / 编码表**的法规变化,都先看一眼那张表有几维、有多少行。五条彼此独立,表形拟合最好的也可能在后续闸门失败;按现行六线 OR 契约,"按行为界定、没有官方计数"只证明依赖官方总数的算式不成立,若要整候选否决,必须补证其他适用盈利线也全部暂定否决。

#### 画像④的判法:六句,顺序不能换,全部排在 G1 之前

画像④要按两个半边分别查(依据:校准 §14.12、§14.13、§14.14):

- **(a) 这一格的现成服务商靠什么收钱**——卖工具 / SaaS 的(HR 合规 SaaS、大所的引流 tracker)会把判定器做出来当获客漏斗,位置被占;卖高接触服务 / 检测的(第三方实验室、认证机构、评估咨询)有动机解释规则、没有动机做免费判定器,位置往往还在。(a) 过了不代表 (b) 过。
- **(b) 收这份判定结果的那一方有没有自己把逐对象判定做完**——主语是「受理方」而不只是发证机关:凡是要接收这份判定结果的一方(发证机关、平台、生产者责任组织、公告机构协调组)都有结构性动机把判定材料做出来并永久免费维护。
  - 零成本一问:**这份判定的结果,有没有一个单一主体在收?**有 → 先假定这一格已被填满,再去它的官网 / 卖家后台帮助 / FAQ / 母语页确认交付形态。
  - 判定材料的形态:计算器、模板、Excel、correlation table、在线申请系统,以及静态的"对象/非对象解释例表"(见陷阱类别十三主体表「发证机关」行)。
  - 检索位置:受理方母语页的 guidance / FAQ / 解釈 / clarification sheet 栏目,不在法规正文旁边。
  - 靠"换一个非发证机关的赛道"绕不开 (b)。

六句判法,任一为是即弃,连 G1 都不必跑:

1. 这一格有没有一份官方或权威的汇总清单?(几乎总是有)
2. **那份清单带不带搜索者真正要的那一列?带 → 弃。** 零成本执行:打开官方清单读一眼列头,不读内容。不带、而那一列又只存在于逐份标准的附件里,才是候选格;"不带"只是必要条件,不是充分条件——判定可以不以表的形态交付,而以逐例解释的形态交付(待验证,见校准 §16「待验证清单」)。
3. 不带的话,**收这份判定结果的那一方有没有以别的形态做完**——计算器、Excel、correlation table、在线申请系统、或一份逐对象判定解释例表?有 → 弃。
4. **标准起草方有没有免费发判定软件?**有 → 弃。
5. **这个判定的下游是不是"买哪种材料、买多少"——有没有一个靠卖那种材料赚钱的推广机构?**有 → 弃。判定是它们的销售前置动作,永远免费、永远维护(见陷阱类别十三主体表「材料与产品推广机构 / 厂商联盟」行)。
6. **打开那部法规"技术文件应包含什么"的那一条,确认这次判定的产物被逐字列进去之后,再问:该合格评定路径下,这份技术文件要不要交给公告机构或主管机关?**要交 → 受理方存在,弃;纯自我认证、谁都不交 → 这一格才可能还空着。这只是必要条件:第 5 句(卖材料的推广机构)与"判定权被法律保留给检测方"都能在无受理方的情况下把位置填掉。

配套结论:

- **判定权被法律保留给正会因此少一单生意的那一方**(如防火试验扩展应用只能由做过原始试验的实验室出具)时,"没人有动机免费做"等于位置被法律封死——属闸门契约 G6 第③项"自助结论须第三方签字才算数",零成本可判。
- **「判定下游减少某方生意 → 没人有动机免费做」不成立。** 免申报 / 免测试类判定同时减少受理方自己的受理负担,受理方比对普通判定更有动机把它讲清楚;没有受理方时发证机关同样会做——它的动机不是收数,是让规则被用对。"不交任何机关"只保证没有受理方,不保证没有供给方。

#### 五条合取:这条矿脉的边界

存活候选(机械 EHSR 覆盖、CWFT)的共同结构是**五条合取**,缺一即不成立(依据:校准 §14.15–§14.19):

| # | 条件 | 零成本查法 |
| --- | --- | --- |
| ① | 付费墙:判定所需的映射表物理上位于要花钱买的标准内部 | 只在 EN / ISO / IEC / ASTM 一侧成立;NFPA、中国强制性国标(openstd.samr.gov.cn)、JIS 全文免费。标准卖得贵 ≠ 范围收费——UL 对每份标准免费公开 Title 与 Scope,"我的产品适用哪部 UL 标准"已被官方目录填满。先打开该标准体系的免费政策页 |
| ② | 标题不透露覆盖:官方清单只到书目层 | 取决于那套标准按"对象类型"还是按"要求域"编号。按机器类型命名的 C 类标准只到书目层;标题逐条写要求域的(玩具 EN 71 各 Part、IEC 60335-2 分部、EN 61439 分部)标题即答案,清单已带那一列。读一眼官方清单列头 |
| ③ | 无受理方:判定产物虽被法规列为技术文件法定内容,却在该合格评定路径下不交给任何机关 | 读法规"技术文件应包含什么"条款 + 合格评定模块(六句判法第 6 句)。这是合取③的精确化,不是独立判据 |
| ④ | 官方计数来自一般产业统计或立法影响评估,不来自逐判定登记册 | 反查:这个主体的人数若是靠某个登记册数出来的,那个登记册的运营方多半就是受理方——官方计数与无受理方结构性反相关 |
| ⑤ | 表大到首屏列不完(画像①) | 读要求侧附件条数:分级表(五档、四档、三档)首屏一列就完;基本要求附件少于三位数不必往下走。表大也不妨碍首屏接管——AI Overview 把规则讲全后主动索要对象参数代算(`pattern` = `AI Overview 接管逐对象计算并代算`),所以表大只是必要条件 |

边界结论:

- 五条同时成立的地方极少;欧盟新法规框架(NLF)内满足"纯自我认证 + 技术文件不交人"的法规很多(LVD、EMC、RoHS、CRA、ATEX 3 类、玩具、简单压力容器),满足全部条件的目前只有机械一家。再沿自我认证这条线开采之前,先读一眼那部法规的基本要求附件有几条。
- **合取③④在欧盟与英国之外结构性同时失效**:注册型体制(美国 NHTSA vPIC、DOE CCMS、沙特 SASO/SABER、澳大利亚 EESS)从设计上就是"先注册后上市",同一个国家系统一手当受理方(杀③)、一手当官方计数源(杀④)。
  - 只有"自我声明 + 事后市场监督"这一种合格评定哲学能同时满足③④,采用它的实质上只有欧盟 NLF 与照抄它的英国、瑞士、土耳其。
  - 不要按管辖区横向铺开:换到注册型体制③④一起塌,换到照抄欧盟的体制判定表与欧盟是同一张。
- 六句判法第 2 句(读官方清单列头)在欧盟之外原样适用(美国 OSHA 29 CFR 1910.6 的 IBR 条目自带引用它的条款号;印度 BIS 的强制认证产品全集页)。
- 非产品域的自我评估义务(职业安全、化学品暴露、环境自监测、能源审计、管理体系)同样受夹逼:受约束主体是"雇主 / 组织",按行为界定,②a 结构性不可得;有官方计数的一律有受理方;表够大的被免费数据库按对象粒度做完。

### 该盯的源头(替换"扫社区找新词"作为首选)

按七条信号排序,优先级最高的是**义务公布的管道**,而不是措辞出现的管道:

| 源头 | 能浮出什么 |
| --- | --- |
| 欧盟授权法案与法规适用日(ESPR/DPP 各品类、电池法规、PPWR、CRA、EUDR、GPSR、CBAM) | 逐 SKU × 逐成员国的义务,带明确生效日 |
| 成员国转化与本国附加要求(EPR 注册、押金制度、标签语言) | 多管辖区差异——"汇总"成为资产的来源 |
| 美国联邦公报里**对企业施加持续义务**的规则(区别于一次性行政动作) | 同型义务;联邦公报本身有多个自动全集镜像,措辞不能落在"这条规则说了什么"上 |
| 平台强制规则(应用商店、支付、广告合规) | 对开发者与卖家的持续义务 |

与陷阱类别六的分工:类别六讲的是"措辞落在规则本身 → 全集镜像已占位,直接判 veto"。本选择器要求的措辞落在**规则之外的派生计算**上——"我这个 SKU 的空隙率合规吗"而不是"PPWR 第 24 条说了什么"。同一个来源的两种用法,一种死一种活。

### 零成本第一问:这次变化究竟新增了什么

执行位置在触发池的 `approve` 之前——官方变化的标题先落 `触发池.jsonl`,本问摆在批准进入 G0 那道门之前。判定动作只有一句:读官方公告自己的标题与摘要,问——**这次变化是新增了一项义务,还是只是取消、推迟、预告、延期、延续、修补或减负?**后者一律零成本弃,trigger 直接 `discard`,连 task query 都不必去找(依据:校准 §14.20)。

九种形态:

1. 取消或缩小既有义务。变体:把多分类合并成少分类,判定随之简化(三分判断收敛为二分)
2. 只改适用日期
3. 只改提交时限
4. 只是预告将来会发规则(*intend to issue proposed regulations*、*notice of intent*)
5. 只是把临时救济再延一年
6. 只是延续一个到期的既有机制
7. 只是解决两部法之间的冲突
8. 明确以减负为目标(Red Tape Review、*reduce burden*、*provide flexibility*、新增豁免)
9. 对既有法规的纯技术性修订(按「分组方法」判)

这一问不覆盖什么:变化虽小但确实新增了一项要逐对象反复做的判定时不适用。判据是"有没有新增义务",不是"篇幅大不大"——一条新增条款也可能开出真任务,一份几十页的修订也可能只是把旧条文重排。

七条信号与五条画像的样本仍极小,继续按它选源时必须记录命中率并据实修订,不能把它当定律(依据:校准 §2 结论三、§14.21、§14.22)。

## 广告线的选源方法:成熟错价词道

本节与上一节的正向选择器分属两种选源偏好,不要混用:

- 义务雷达优先发现 subscription / lead_generation / transaction / paid_report 等高价值低量级机会;本节优先发现 advertising / affiliate 的成熟流量机会。
- 它们不是六条盈利线的封闭清单,进入 G6 后仍完整检查六线。
- 广告线的 $200/月仍是该线硬门;"查无"只使 new 道 advertising=`N/A`,不否决其他五线。

- 账本的 `lane` 字段开放为 `new` / `mature`;本节的方向一律以 `--lane mature` 注册。
- 执行载体是 [xinci-mature](../xinci-mature/SKILL.md)。判据以本节为准,skill 只负责把它串成可执行的层次;skill 是单步形态,不接入 xinci-run 的自动循环(依据:校准 §8、§14.23)。

### 数据政策的关键差别:mature 道不适用新词道的 Semrush 禁令

新词道禁用 Semrush/KD/CPC/Trends 的唯一理由是"天级新词查无是本赛道的定义属性"(闸门契约时间光谱)。这个理由在 mature 道上不成立——本道必须用可测量的历史需求证明它确属 mature 查询,所以从第一步起就允许并**要求**取量级数据;但量级门槛只约束依赖流量的盈利线,不是六线共用的整候选硬门。

- **量级数据(搜索量)用来证明 mature 需求存在,并判断 advertising / affiliate 等流量线是否有足够规模**——不得把广告门槛套给 subscription / lead_generation / transaction / paid_report。
- **KD / Authority Score / 外链数不得决定 G2/G3 或直接挣竞争分。** 三组背离(KD 14 对实测竞争 89、KD 27 对 71、KD 44 对约 85)方向一致:指标看起来容易、实际都更难,域名强度代理对 exact-task 竞争失明。
  - 门结论只由 G2 完整结构阅读与 G3 条件化占位审计(先得原始占位判断,再按盈利线映射有效门结论)判定。
  - 确认期的流量、覆盖词量、增速是"实际占据"footprint,只作评分与风险输入。

### 要找的是什么:反向错价

三组背离证明"看起来容易、实际难"的错价存在。本道要系统性找的是它的反面:

> **量级真实存在,而 SERP 被守得很弱。**

**现行执行流程固定为三步:先算钱、再看防守、最后在 G3 核对是否已有免费或近乎免费的同任务供给。** xinci-mature 已承接这第三步,不得把"弱守通过"直接当作存活结论(依据:校准 §8.8、§14.29)。

**第一步,量级前置过滤。** 一次 Semrush 查询读两个数——簇内词总数 N,以及前 15 行的量与头部词量:

- N < 约 1,000,或前 15 行合计 < 约 50K 且无单词 > 10K → advertising 暂定否决,affiliate 也必须按购买意图与可归因流量重新证明;
- **这不直接淘汰整个候选**,还要完成其余四条非流量线。只有所有可用线都依赖流量且本层全否,才无需继续昂贵的 SERP 阅读;
- 阈值只来自 3 个样本,须按真实结果继续调;免费版 Semrush 每次只给 15 行,"前 15 行合计"是簇量的下界。
- 量级、RPM 与弱守**互相反相关,是一个乘性夹逼**,不是三个可分别满足的条件:高 RPM 招来把这一格当生意经营的人,防守弱的地方通常商业价值低(见闸门契约 G6;依据:校准 §8.3)。

**第二步,弱守信号。**"守得很弱"不是靠指标判的,是靠现场读出来的。可用信号全部来自 G2 已有的放行信号与 G3 第一问,不新增判据:

1. **占位者是内页、小站、论坛帖**,而非专做这件事的站(G2 原有放行信号)
2. **内容明显老化**且该题目已经变了——首页结果日期集中在数年前,而规则/产品/价格已经改过
3. **没有真工具**,任务要求算/查/比,而占位者只有散文(G3 第一问)
4. **格式错配**——查询要的是表格、清单、计算器,排上来的是长文
5. **意图错配**——排名页面答的不是这个问题
6. **没人把这一格当生意经营**——无付费产品、无按任务成簇、无维护痕迹(G3 补充判据)

六条里中三条以上才算弱守,并且必须写明是哪几条、附现场证据。只中一两条的按正常竞争处理。判读弱守时,按闸门契约 G3 第一问的要求**用用户问句式与产品向两族措辞各检索一次,缺一不可**——只按问句式读会系统性地把"论坛帖占屏"误读成"没人经营这一格"(依据:校准 §8.7、§14.27)。

**第三步,免费供给核对。**问"谁有动机建这张表"时,候选答案不止零售商:持有数据授权的专业数据商、发证或管辖机构、行业协会、把该功能并进既有产品的软件厂商。先看证据指向谁,不要先挑一个再去凑(与陷阱类别十"四问不要过早锁定答案"同一条纪律)。

### 反向排除:本道最容易踩的三个坑

YMYL 与横向对比可在 SERP 前按任务类型筛除;"成熟工具词"必须在 G2 完整阅读首页后才能判,不得归入零成本层:

- **成熟工具词**(索引 pattern「成熟工具词」):量级是真的,但那是多年被争夺过的赛道,弱守信号往往只是错觉。凡 G2 首页出现专做这件事的站,立刻停。
- **YMYL 高竞争垂类**:凡题目影响**健康、财务、安全或法律权利**的一律按 YMYL 处理——按类别定义,举例(健身/补剂/交易/健康/法律)仅作说明,不构成清单。这是 mature 道的前置排除,不是 G3 exact-task completion 结论;索引用 `stage=prescreen,reason_code=ymyl_high_competition`,不得伪装成 G0–G8。此类常青问题量级极大,但是全网竞争最凶的一档。
- **横向对比与迁移**(陷阱类别七):`alternatives to X` / `X vs Y` 这类量级也真,但该对象类有自己的全集维护者——替代品目录站、分析机构榜单、社区 awesome 清单、竞品自建对比页。

### 该盯的源头

本道要找的是**需求已经存在、供给却没跟上**的地方。四类源头不同权:结构上可靠的只有前两行,优先用;后两行的前提自带陷阱类别六,降为次级——采用前先零成本问一句"这个对象全集有没有法定/事实上的维护者?"答有即弃,不必读 SERP(依据:校准 §8.4)。

| 源头 | 为什么可能出现反向错价 |
| --- | --- |
| 需要**逐对象查表**的成熟任务(型号、地区、版本兼容性)——挑**答案是一个数字或一个判断**的,避开答案是一件可购买商品(SKU)的 | 散文答不了,而占位者往往只有散文;答案是 SKU 时,零件商建适配表就等于建自己的商品目录,第一天起就没有位置。答案不是 SKU 时零售商没动机建表,但持牌数据商可能早已建好,仍须走第三步核对 |
| 论坛/社区里被反复问、且每次都靠人肉回答的问题 | 反复问 = 有量;每次靠人肉答 = 没人做成页面或工具 |
| (次级)官方/权威页面排在首位但**答不全**的查询 | 权威性把它顶上去了,内容却只覆盖任务的一部分;但权威页往往正是全集维护者,先做上面那句零成本判断 |
| (次级)规则、价格、产品线**改过之后**的老查询 | 量级由历史积累而来,而排名内容是改动之前写的;但改规则的机构会同步它自己那一页,先做上面那句零成本判断 |

### 来源组合与产能口径

- 来源分配按任务家族与实际漏斗产出计,不只按"换域名"计覆盖。来源轮换以触发池事件按 source_family 统计,`run_policy.py` 据此给出 `blocked_source_families`。
- 初始组合为 50% 已验证高产来源、30% 相邻任务来源、20% 探索来源;每个校准周期依据状态迁移和假阴性结果调整,而不是依据 raw 提取量自我奖励。
- 一轮可广度提取 200–300 个原始方向,但人工/浏览器瓶颈按独立任务 family 管理:G1 常态 30–50 次、深审最多 5 个。十轮的理论上限是约 300–500 次 G1 与最多 50 次深审,不是 2,000–3,000 个"完整分析";机器清单必须分别报告 raw/formal/G1/deep,禁止把 raw 提取数包装成已分析数。
- 校准轮用 `false_negative_sample.py` 从索引和账本按 G6/G7/G5/G1/G3 分层抽样。发现 false negative 时,先修闸门或模式别名,再受控重开;不得因为想提高命中率而降低正式 pass 标准。

## Semrush 探针纪律(按赛道分,新词道仅形成期起;阶段按**状态**判,不按年龄)

先分赛道,再看阶段。下面的分阶段禁令只约束 `lane=new`:

- **`lane=mature` 从第一步起就允许并要求取量级数据**,具体量级门槛只约束 advertising / affiliate 等流量线,不连带否决其他盈利线(见上「数据政策的关键差别」)。
  - 硬限制:量级数据不得决定 G2/G3,也不得把广告量级门套给非流量线;KD、Authority Score、外链数不得直接挣竞争分(三组背离见同节)。
  - 门结论只由 G2 完整结构阅读与 G3 条件化占位审计判定,且 G3 必须把原始占位判断按盈利线映射成有效门结论;确认期的流量、覆盖词量、增速只衡量实际市场占据。
- 每一次计费查询必须能够改变一个决策;为满足流程而跑的查询是禁止的。决策不变,查询不跑。
- **(仅 new 道)**窗口期(`captured` / `screened`,参考年龄 0–14 天)禁用 Semrush / Trends / KD / KGR / CPC:天级新词查无是定义属性,查了也不能说明任何事。
- **(仅 new 道)**形成期(`tracking`)允许轻量探针:自动补全出现与否、首批关键词行出现与否——自动补全出现与否是形成信号证据,不是资格证据,**零建议不是否决**(见上「自动补全:有建议是正证据,零建议不是否决」)。
- 确认期(`formation_confirmed` 起)的完整竞争审计以 live SERP 的 exact-task 阅读为主,Semrush 数据为辅;竞品 footprint 实测(authority、流量、词量、增速)必须至少做一个。
  - authority 只作背景记录;流量、覆盖词量、增速用于衡量实际占据,只进入评分与风险说明,都不得反向改写 G2/G3。
  - 进了 formation_confirmed 就按确认期解禁,不看候选几天大——最快第 7 天就会到这一步(见闸门契约时间光谱)。
- 环境适配:Codex 环境有 `$export-keyword-csv` skill 时按它的界面路标与预览纪律操作(preview 优先,全量 CSV 必须能改变决策才导);没有时手工走 Semrush UI:Keyword Magic 输入种子 → 看前 50 行预览 → 只记要点进观察文件,不整页转录(数据极简)。
