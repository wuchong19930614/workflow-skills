# 评分契约(认定阶段)

仅适用于 `formation_confirmed → qualified` 的正式认定,由 xinci-qualify 执行。窗口期与形成期不评分——那时的证据不支持这套刻度。

## 计分

```
final_score = max(0, 六维得分合计 - 红队扣分)
过线:final_score >= 80(整数)
```

**79 分不算过。** 永不为凑候选降门槛;分数差多少如实写进 disqualified 的决定性缺口。

## 六维权重(合计 100)

| 维度 | 分值 | 判据 |
| --- | --- | --- |
| 触发真实性 | 15 | 有日期的原始变化 + 独立佐证;时机仍在影响任务 |
| 被迫付费任务 | 12 | 明确付费者必须重复完成一个有代价、有期限或有风险的动作 |
| 搜索语言形成 | 8 | 独立证据显示受影响的人用可搜索的自然语言表达该任务 |
| 竞争 | 30 | exact-task 完成度与直接产品成熟度为主;竞品实际占据 footprint(流量、覆盖词量、增速)只占小头;KD/Authority Score/外链数不计分 |
| 变现对齐 | 15 | 搜索者与付费者的关系、自助交易路径明确 |
| 收入可行性 | 20 | 按 G6 实际通过的盈利线评分:订阅线写同周期的受约束付费客户数、可行单价、获客/交付成本与出处；广告线写实测簇量、现实 CTR、RPM 与出处。订阅金额无统一硬线；广告线 $200/月是该线硬门 |

计分纪律:

- 新颖性本身不挣分。没有被迫需求的新名词,触发/任务/语言形成三项全零。
- 大受众但没有搜索语言证据,语言形成最多给 2/8。
- 竞争 30 分里,exact-task 完成度与直接产品成熟度占大头;确认期实测的流量、覆盖词量、增速只作为“实际占据”小头。KD、Authority Score、外链数等域名强度代理不计分,也不得改写 G2/G3。KD 与实测竞争的背离案例(KD 14 对 89、KD 27 对 71、KD 44 对约 85)是这个边界的依据。
- **收入可行性不得为 0/20。** 这是方案 C 的最小防绕过线,不是声称“1 分收入就足够好”:金额很弱仍会把总分压到 80 以下。registrar 要求 `--income-score 1..20`,账本同时记录 `g6_passed_lines`;未通过任何盈利线不得评分。

## 红队扣分

评分完成后,换立场做一轮反驳:免费替代被低估?官方答案在路上?任务其实是一次性的?付费者其实不搜索?每条成立的反驳按其对结论的破坏力扣分并记录理由。红队记录随评分一起写入 qualify 观察文件。

## 硬约束

- 硬否决之后**不得**产生最终分数——没有"高分但被否决"这种记录。清单以 registrar 的强制为准:候选只有在 G0/G1/G2/G4/G5=`pass`,且 G3=`pass` 或历史兼容/mature 广告线候选的 `veto_window_bet` 时才能进入 screened。G0/G1/G4 命中即否决;占位否决按盈利线生效时 G3 判 `veto`,含陷阱类别的有效 G3 验证失败;G2 结构阅读结论为否;G5 命中陷阱类别且未通过验证。订阅线暂定可行时,占位事实只进入竞争记录,G3 有效门结论写 pass,不属于硬否决。**认定三道 G6–G8 任一未过**即 disqualified,同样不产生分数。`veto_window_bet` 只走快道,而快道本身不评分(见闸门契约 G8)。
- veto 被推翻的候选回到普通评分,不因此豁免任何数值闸门。
- 评分所需证据缺失 = 该维度不得分,不是"待定给分"。
- `final_score ≥80` 与 `income_score ≥1` 必须同时满足；前者不能替代后者。
