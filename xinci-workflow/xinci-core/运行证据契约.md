# 运行证据契约（session v4）

适用于新建连续运行；历史 v1–v3 会话按原格式恢复，账本与历史观察不迁移。观察文件仍用 schema v3。`start` 默认创建 v4，CLI 不提供降级选项。

## 预检

先 `start` 取得 run_id，再由实际执行者采集现场证据。`begin-round` 增加 `--preflight-evidence <数据区相对 JSON 路径>`、`--work-package '<JSON>'`。四个 `--browser-*` 参数保留，由控制器与证据声明交叉校验。

预检 JSON 示例（值必须来自现场，不能复制示例当作事实）：

```json
{
  "run_id": "<当前运行>",
  "executor_id": "<本轮执行者>",
  "observed_at": "<带时区 ISO 时间>",
  "capture_ref": "证据/运行预检/<本次快照>.txt",
  "query_url": "https://www.google.com/search?q=<现场查询>&gl=us&hl=en&pws=0",
  "observed": {"controllable": true, "desktop": true, "region": "us", "logged_out": true},
  "privacy_context": "isolated_logged_out",
  "privacy_evidence": "<如何核实上下文隔离或无痕>",
  "login_indicator": "<页面可见的登录状态标志>",
  "observation": "<实际浏览器、桌面布局、地区及登录依据>"
}
```

- capture_ref 引用真实工具返回的完整页面文本、无障碍树或截图，不以手写结论替代快照。证据 JSON 与快照必须非空、位于数据区内，控制器绑定两者 SHA-256。
- 预检须发生在当前运行启动之后、开轮前最近 15 分钟，绑定 executor_id；每轮使用新的预检文件。G1 提交及收尾重验快照未被修改。
- `privacy_context` 合规值为 `incognito` 或 `isolated_logged_out`：无痕窗口，或已核实与用户登录环境隔离的未登录上下文。仅看到 Sign in 不足以证明隔离，须同时填写 privacy_evidence；无法核实则降级。
- 美区指搜索地区参数 `gl=us`，并须 `hl=en&pws=0`；它不证明美国出口 IP。IP/页脚位置单独写 observation，不凭未定位自动否决，也不凭 gl 参数声称美国 IP 已核实。
- 参数不支持、句柄失效先按工具文档修正；实际打开并检查页面后才能申报登录态。未知不得填成 yes。
- 机器能检查引用、时间、绑定、一致性与完整性，不能证明截图内容真实或 task_match 判断正确。执行者仍负责核验可见状态与来源语义。

## 工作包与计轮

开轮工作包包含 `targets`（非空、唯一的候选 slug、trigger id 或来源 URL 列表）与 `completion`（具体完成条件）。按实际可完成范围设置规模，不要求每轮遍历全池；未选入工作包的候选不得声称已复查。

```json
{"targets":["<候选slug>"],"completion":"复查 G1 与形成信号，登记观察并执行证据允许的转移"}
```

收尾 `--work-results` 必须逐项覆盖工作包，每项包含：

```json
[{"target":"<候选slug>","outcome":"completed","observed_at":"<带时区 ISO 时间>","reason":"<实际完成了什么，取得什么结论>","evidence_refs":["证据/<候选slug>/<本次观察>-track.json"]}]
```

- outcome 为 `completed`、`blocked` 或 `deferred`；completed 指完成了审计或采集，不要求发现候选或转移。来源零产出仍可算已完成工作，须留下真实的零产出审计证据。
- 至少一项完成实际工作才可计轮；结果时间不得早于本轮开始，证据须存在。仅预检快照不能充当完成工作。候选完成项必须有 registrar 写入或 candidate-reviewed 登记。
- 仅浏览器重试、未处理任何原料或候选时，用 `abort-round --run-id ... --reason ... --evidence-ref ...` 留下失败尝试，不增加完成轮数、降级轮数或消耗预算。已有候选/触发池/轮清单写入时禁止 abort，必须正常 record-round。
- 相同降级快照不得重复开新轮。连续三轮降级上限只统计完成了实质工作的降级轮；不制造空轮触发停止。通道未修复时先检查存量和可行来源；全部停摆可引用现场故障与路径核查文件 `finish --status 执行受阻 --evidence-ref ...`，不必凑三轮。
- `candidate-reviewed.outcome=not_due` 仅在 candidate_actions 的 not_due_allowed=true 时允许；没有到期提醒不等于不能复核形成证据。工作包外未处理项只如实报告未处理。

## 动作与证据路由

`run_policy.py` 的 candidate_actions 逐项给出动作、原因、形成时间、最近证据、unknown_income_lines 与 review_required_gates。它是证据审查入口，不自动证明闸门通过；reachable_ceiling 的 go 仅是条件性路径上限。

`evidence_index.py` 从已登记观察派生缺口：更新的 scan/track 写出未定盈利线且没有新 G3 时，标记 G3 待复核；旧账本 gates 保留为历史。只有更晚的实际复核能解除提醒；正式转 qualified 时须在本次 qualify 观察提交晚于缺口证据的重核结论。不能把较新文件本身解释为所有旧事实已失效。

历史形成确认不回滚。后续新 `tracking→formation_confirmed` 提交必须有 formation_evidence；主题级、任务级、产品级规则见生命周期契约的形成确认要求。
