# 闸门契约

九道闸门(G0–G8)的唯一定义。各 skill 按路径引用本文件,不得复制、不得改写、不得软化。每条规则附失败案例出处——规则是从真实损失里写出来的。

## 时间光谱与适用矩阵

**分段以候选状态为准,年龄只是参考刻度。** 状态决定哪些闸门有意义、哪些数据解禁;年龄那一列是典型情形下的对照,不是准入条件。分段**不是调度器**:何时推进由用户判断,分段只约束"此刻哪些证据是可得且有意义的"。

| 阶段 | 状态(判准) | 参考年龄 | 适用闸门 | 数据要求 |
| --- | --- | --- | --- | --- |
| 窗口期 | captured / screened | 约 0–14 天 | G1–G5 | 只要浏览器证据;禁用 Semrush / KD / KGR / Trends |
| 形成期 | tracking | 约 15–90 天 | G0/G1 重跑 + G2/G3 变化复看 + 形成信号 | 允许轻量 Semrush 探针(仅 decision-changing) |
| 确认期 | formation_confirmed 起 | 约 90 天+ | G6–G8 + 评分 | 早期 Semrush 数据 + 完整竞争审计 |

**为什么以状态为准**:状态机跑得可以比年龄快——`tracking→formation_confirmed` 只要求两次 -track 观察相隔 ≥7 天,所以一个候选最快第 7 天就进确认期。若按年龄判,它会同时落在"窗口期禁用 Semrush"与"确认期必须实测竞品 footprint"两条相反的规则里。按状态判,这处冲突不存在:**进了 formation_confirmed 就按确认期解禁数据,不看它几天大**。

**形成期为什么不是"G1–G5 全复查"**:G4(任务能否完全在线完成)与 G5(陷阱类别归属)是方向的**结构属性**,不随时间推移而改变,例行复查它们是空转(唯一的重看时机是新类别归并后发现某个在追踪的候选正好命中它——那是重新认识,当场按 rejected 处置,不是常规复查项)。会随时间翻转的只有三样:G0(平台 ToS 改了、市场被欺诈供血)、G1(Google 自己把答案补上了)、G2/G3(竞品到位、官方工具上线)。xinci-track 的复查动作按这个范围执行,不多不少。

天级新词无年度曲线、无月度 volume;Semrush 查无是本赛道的定义属性,不是缺陷。**缺失的 volume 不是零需求;缺失的证据也仍是缺失的证据**——两者都不许拿来当结论用。

G0 不在上表:它适用于全部阶段,且永远先于表中一切闸门执行。

**扫描期执行顺序:G0 → G4 → G5 → G1 → G2 → G3。** G0、G4 与 G5 的**直接筛除型**判定是零成本推理检查(不开浏览器),任何一道命中即弃,一次 SERP 都不浪费;**唯一的例外是 G5 命中验证型类别**——那一档要当场跑 G3 验证,会开浏览器读一次 SERP(两档处置见下文 G5)。除这个例外外,G1 是第一道浏览器闸门,之后才轮到结构阅读与竞品验证。同批还跑 G6/G7 的零成本预筛(无被迫任务、官方答案在途——判据见下文「G6/G7 的扫描期用法」),它同样不需要浏览器。

## G0:合法性与安全 = 硬否决(先于一切)

任务本身违法、违反目标平台服务条款、或其市场由欺诈供血(盗刷密钥/信用卡、批量薅取试用账号、未经授权的中间人数据倒卖)的方向,任何指标下直接否决。同样命中:助长欺骗的规避工具(如让 AI 文本躲过检测或水印)、无法合法运营的灰色需求。

- 零成本推理检查,先于 G5 陷阱与 G1 SERP;任何阶段命中即提议 rejected,之后不产生最终分数。
- 需求真实、措辞正在形成都救不了它:能搜的词不等于能建的站。
- 规则出处:2026-08-17 首次扫描,`ai credit resale / token relay market`(HN 277 分)——措辞真实形成中,但线程证实买卖两侧任务均建立在 ToS 违反与欺诈供血之上,当时只能靠 G6"合法自助变现"的措辞兜住;本条把该否决独立成门。

## G1:Google 直接回答 = 硬否决

美区、桌面、未登录,搜精确词。首屏若已完成任务即否决:完整作答的 featured snippet、原生计算器/转换器/单位组件、承载全部答案的 knowledge panel、把任务做完的 AI Overview。

这是全部闸门中最硬的一道:搜索引擎自己能完成的任务,任何内容质量都赢不了。执行位置在零成本推理批(G0/G4/G5)之后、一切结构阅读与竞品验证之前;**正常路径上它是第一道打开浏览器的闸门,唯一的例外是 G5 命中验证型类别**——那一档要当场跑 G3 验证,会先读一次 SERP(见上「扫描期执行顺序」)。

不否决:只做摘要、而任务仍需要工具或工作流的 AI Overview。

**否决后的留痕走淘汰方向索引,不注册进账本**(`gate=G1`,reason 写清是什么把任务做完了:featured snippet / 原生组件 / knowledge panel / AI Overview)。G1 是硬否决且永不复活,需要留下的只是"这个方向见过、死在 G1";按漏斗目标量它每轮约 18 条,逐条注册的写入成本会压过本轮真正值钱的 5 次深审。分界线的完整表述见生命周期契约「证据与命名约定」的留痕分界。

## G2:完整首页结构阅读

读完第一页,继续到第二页或明显质量断层为止。**禁止用 top-3 判断竞争。**

拒绝信号:视频占屏而任务非视频;维基级/大媒体域名霸榜;强品牌首页(而非内页)霸榜。
放行信号:相当比例是内页、小站、论坛帖、明显老化的内容。

规则出处(真实失败):某次调研用排名第一的结果评估整个市场——10 道浅显回忆题、无解析、教学大纲已过期——结论"竞争弱"。真正占据该任务的站在第二页:75/85 题完整题库、对齐现行大纲、分域测验加学习指南。它只在强制枚举十个结果时才现身,而此时一整轮验证已经浪费。

## G3:exact-task completion

把每个竞品按"**做什么**"分类,永不按"是谁"。身份在两个方向上都不说明问题:大品牌的信息页不等于完成任务;无名小站的可用工具就是完成任务。两种误读都真实发生过——一次因为出现了知名安防和保险品牌而把领域判为封死,另一次因为第一名很弱而把领域判为敞开。

**否决线:≥2 个免费结果把任务做好**且**有持续可见度**。

### "持续可见度"怎么判(这半条判据决定结论,不许略过)

否决线的两半都要满足:任务被做完 **且** 做完它的东西**在本查询的 SERP 上稳定可见**。数完"有几个免费实现做完了任务",必须再问一句:**它们为什么(不)在这个查询的首页上?** 三种答案通向三个不同结论:

| 那些免费实现 | G3 结论 | 依据 |
| --- | --- | --- |
| 在本查询 SERP 上有持续可见度 | `veto` | 位置已被占满,任何内容质量都抢不回来 |
| 排不上,但只因对象太新**还没被收录** | `veto_window_bet` | 位置只空几天;是窗口赌注,不是生意 |
| **结构上进不来** SERP | `pass` | 位置没被占——它们不具备"持续可见度",不计入否决 |

"结构上进不来"指:站内应用页(如 Hugging Face Space 这类)被索引得极差、功能在登录墙之后、平台内嵌工具、只存在于 App 而不在 web 上。这类实现无论多好用,都不占据这个查询的位置。

**临时空位的寿命以天计,不是猜测**:实测 Spheron 在 Llama 4 发布**第 4 天**就发了显存估算,工具厂商收录新对象以天计不以周计。所以判"还没收录"就等于判"这个位置几天后消失"。

### `veto_window_bet`:唯一的降级出口

判定为**临时空位**的候选不直接出局,但只准走快道,条件与限制一并生效:

- **判定前提(缺此项只准判 `veto`)**:必须实测至少一个通用实现对**上一个同类对象**的收录时差——打开它的页面看它多久前收了上一个同类对象。这是窗口期拿得到的浏览器证据,也是"空位还剩几天"唯一可证伪的锚点;不做这个实测,"只是还没收录"就只是猜测,一律按 `veto` 处置。时差以天计 → 空位以天计,可赌但须明码标价;时差以月计或压根没收 → 空位比想象的持久,回头重判是否该记 `pass`。
- 进入条件:上述实测 + `window_estimate=days` + 转移必须带 reason(豁免依据写进账本 history) + 观察文件记明数到的免费实现清单、收录时差实测、以及"为何不在本查询 SERP 上"的判断;
- 合法出口共四个:`fast_grab_ready`(唯一的 go 出口)、`rejected`(快道读完证据判定赌注不值)、`withdrawn`(用户撤回),以及它挂在 `captured` 等确认期间排队 expiry 过了的 `expired`。**禁止 → tracking**——G3 的否决理由不会随时间变好只会变坏(通用工具正在收录),放它进追踪等于让它绕过 G3 走到全站;
- 快道决策书必须明码标价:**本次只赌收录时差,通用工具收录后位置即失**;
- built 之后若走 `built → tracking` 升级通路,**必须重跑 G3 并取得真 pass**——豁免只在快道这一次有效;
- **连续运行模式不可用**:G3 豁免是软化闸门的决定,而生命周期契约的标准授权明确"闸门、评分线、证据要求原样适用,不因连续模式软化"。因此 `by=xinci-run` 时 registrar 拒收本出口,必须由用户在单步模式下确认。
  **被拒后候选留在 `captured`**,gates 带着 `veto_window_bet`、带 expiry,观察文件记明豁免依据,等用户单步确认——这是它的合法挂起位。不许转 `rejected`(它没有失败的闸门,用户确认后本可以走快道),也不许换个 `by` 硬推 `screened`。连续运行照常继续,清单 notes 记一句待确认即可,它不是 blocker。

footprint 要求按阶段分层(与时间光谱一致,勿混用):

- **窗口期(scan 当场跑 G3)**:只用浏览器可得证据判否决线——打开竞品页面实测任务完成度、内容新旧、更新频率、`site:` 收录规模。此阶段**不要求**流量/词量数据(窗口期禁用 Semrush,该要求客观无法执行)。
- **确认期(qualify 的完整竞争审计)**:下最终结论前**必须**实测至少一个竞品的真实 footprint(authority、流量、词量、增速)。存在不等于占据——竞品的存在什么都不证明,直到你知道它实际占了多少市场。

## G4:任务可完全在线完成

需要实地检查、物理采样、实验室工作、持照人员到场的任务,一票否决,指标再好也不看。这道过滤零成本、直接取消资格,**与 G0/G5 同批、先于一切浏览器工作执行**。

规则出处:某次调研带着一个月搜 16,250、KD 13%、CPC $3–7 的词一路走到建站决策,才发现任务需要有人爬上屋顶——把零成本检查排在昂贵审计之后,浪费的正是这一整路。

## G5:陷阱类别检查

**先于 G2 结构阅读执行。** 陷阱类别的共同特征是"过 G2、死 G3"——结构看起来诱人恰恰是陷阱的表象,先读结构必然误判且浪费扫描时间。

命中 [陷阱类别.md](陷阱类别.md) 的候选,**按该类别节自带的处置执行**——两种处置,写在类别标题里:

- **验证型**:跳过结构阅读直接跑 G3 验证,G3 判 `veto` 即弃,不必审计 SERP 结构。用于死因取决于本方向具体情形的类别(如类别一「新发布 AI 模型」:窗口有多长要看这个模型的收录时差)。
- **直接筛除型**:零成本判定即弃,一次 SERP 都不跑。用于死因已经结构性确定、逐条验证只是重复劳动的类别。两种来路:①**前置筛除型死因**天生如此,连可搜索的任务都产生不了,没什么可验证(类别二「纯品牌名发布」);②**SERP 陷阱型**验证满三次、死因每次都相同后归并降档(类别三「厂商已占位的 B2B 强制任务」)——归并成正式类别的意义正在于此:验证过三次之后不必再验证第四次。

处置档按死因型定:**SERP 陷阱型**新建时默认验证型,只有当三次实际观察都指向同一个结构性死因、且该死因与具体方向无关时,才在归并时改标为直接筛除型;**前置筛除型一律直接筛除型,不受"三次观察"约束**——它连可搜索的任务都产生不了,没有词可搜就没有 SERP 可读、没有 G3 可验证,验证型对它在物理上不成立(类别二「纯品牌名发布」即此例)。**G3 验证存活的候选,G5 记 pass**(观察文件注明命中的类别与验证要点),回到正常序列把 G1、G2 补齐——captured→screened 仍要求 G0–G5 全 pass,陷阱验证通过不豁免任何其他闸门。

**"存活"含 `veto_window_bet`**:G3 三分里只有 `veto` 是出局,`pass` 与 `veto_window_bet` 都还有下一步(后者只有快道一条)。判出 `veto_window_bet` 的陷阱型方向要**注册进账本**,不再走索引一侧——留痕分界的第一条(它还有下一步)命中了它。

每当扫描出现"过 G2 死 G3"的新模式,追加进陷阱清单,记录实际观察而非只记泛化结论。

## G6:商业闭环

四件事都要有:明确的付费者;被迫或重复的任务;自助(self-serve)变现路径;保守假设下稳定收入 ≥$200/月 的可达性——与评分契约"收入可行性"维度同一把尺:$200/月是基准线不是天花板,保守估算都够不着这条线的方向不值一个域名。

新东西只有通过"真实触发造出真实任务"才挣分:一个没有被迫需求的新名词,触发、任务、语言形成全部零分。

## G7:耐久性

三个杀手逐一排查:

- **版本更替风险**:为一个版本买的域名,随下一版发布而过期。重复任务若属于通用工具,那是另一条已被争夺的赛道。
- **官方答案风险**:厂商、平台多快会发布自己的答案?工具厂商收录新对象以天计,不以周计(实测 4 天)。
- **好奇 vs 任务**:只产生一周好奇、没有重复任务的东西,不值一个域名。直说,不进清单。

## G6/G7 的扫描期用法:零成本预筛,不出正式结论

G6/G7 的**正式结论只在确认期产生**(证据要求见上表),但它们的两条判据在扫描期就零成本可用,且已在实战中筛掉过方向:

- **无被迫/重复任务**(G6 的前两件):只有一周好奇、没人被迫重复做的东西,不值一个域名——直说,不进清单;
- **官方答案在途 / 一次性配置**(G7):厂商自己会在几天内发布答案的方向,窗口不存在。

这类预筛与 G0/G4 同批执行、同样零成本,否决后按秒弃留痕进淘汰方向索引(gate 记 G6 或 G7)。**它们不产生分数,也不构成认定阶段的 G6/G7 结论**——扫描期筛掉的是"连任务都不成立"的方向,不是"商业闭环算不算成立"的判断。

## G8:簇广度

**认定门(硬否决)**:≥3 个任务型查询 × ≥2 个独立 family。达不到即 disqualified,不产生分数——G8 与 G6/G7 同为 qualified 的前置,未过的候选到不了**完整模式的** go 决策(registrar 的 qualified 要求 G6–G8 全 pass,而 build_ready / pilot_ready 只能从 qualified/hold 转入)。

快道的 `fast_grab_ready` 也是 go 决策,但它走的是另一条路:`screened → fast_grab_ready` 根本不经过认定,G6–G8 此刻**客观无证据可判**(天级新词还没有商业闭环、耐久性、簇广度的材料)。这不是豁免而是减配——跳过项在快道决策书里逐条明码标价,由用户读完决定赌不赌。所以准确的说法是:**未过 G8 的候选到不了全站 go 决策,但可以到快道 go 决策**。

**决策门(降级线)**:全站页面地图要求 ≥12 个任务互异页面 × ≥3 个簇 + ≥1 个自助产品资产。合并表述性变体,不许拿同义改写凑页面数。**pilot 由这条线触发**:G8 认定门已过、但决策阶段的页面地图凑不满全站规模的候选,降为 pilot(5–8 页有界实验)或 no_site。

两条线不可混用:认定门问"机会是不是真的",决策门问"够不够撑一个全站"。

## 关于 KD / KGR / allintitle 的统一立场

这些是标题域名信号,对"是否有人已把任务做完"完全失明,而后者才是竞争的大头。实测背离宽且单向:KD 14 对实测竞争 89、KD 27 对 71、KD 44 对约 85——真正把任务做完的站往往域名指标很弱。

因此:低 KD 只触发一次 exact-task 完成度检查(G3),永不作为鼓励;窗口期禁用;任何阶段都不得单独用作决策依据。
