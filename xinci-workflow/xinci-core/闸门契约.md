# 闸门契约

九道闸门(G0–G8)的唯一规范性定义。各 skill 可以为执行方便摘述,但摘述不是第二份契约;一旦冲突,以本文件为准并同步修正摘述,不得自行改写或软化判据。每条判据的出处、实测记录与修订过程见 [闸门校准.md](闸门校准.md),正文只留判据本身。

## 时间光谱与适用矩阵

分段以候选状态为准,年龄只是参考刻度:状态决定哪些闸门有意义、哪些数据解禁;年龄一列是典型情形下的对照,不是准入条件。分段不是调度器:何时推进由用户判断,分段只约束"此刻哪些证据是可得且有意义的"。

| 阶段 | 状态(判准) | 参考年龄 | 适用闸门 | 数据要求 |
| --- | --- | --- | --- | --- |
| 窗口期 | captured / screened | 约 0–14 天 | G1–G5 + G6/G7 零成本预筛 | 只要浏览器证据;禁用 Semrush / KD / KGR / CPC / Trends |
| 形成期 | tracking | 约 15–90 天 | G0/G1 重跑 + G2/G3 变化复看 + 形成信号 | 允许轻量 Semrush 探针(仅 decision-changing) |
| 确认期 | formation_confirmed 起 | 约 90 天+ | G6–G8 + 评分 | 早期 Semrush 数据 + 完整竞争审计 |

- 进了 `formation_confirmed` 就按确认期解禁数据,不看它几天大。(依据:校准 §11.2)
- 形成期复查范围只有会随时间翻转的三样:G0(平台 ToS 改了、市场被欺诈供血)、G1(Google 自己把答案补上了)、G2/G3(竞品到位、官方工具上线)。G4、G5 是方向的结构属性,不例行复查;xinci-track 按这个范围执行,不多不少。(依据:校准 §11.2)
- G4/G5 唯一的重看时机:新类别归并后发现某个在追踪的候选正好命中它——由做归并的一方当场提议 `tracking→rejected`(单步是 xinci-scan、连续运行是 xinci-run),不是 xinci-track 的活;对应生命周期契约 rejected 边的第⑥种情形。
- G0 适用于全部阶段。上表只在形成期一格显式写出它,因为那一阶段它会翻转;窗口期它在扫描的零成本批里首跑(见下「扫描期执行顺序」),确认期沿用已有结论——不是不适用。
- 上表只适用 `lane=new`。`lane=mature` 从第一步起就允许并要求取量级数据,用来证明它确属已有需求的 mature 查询,并判断 advertising / affiliate 等流量线能否成立;量级低于广告线门槛只否决受影响的流量线,不得连带否决 subscription / lead_generation / transaction / paid_report。
- KD、Authority Score、外链数等域名强度代理在两条道上一律不得决定 G2/G3 的放行、否决或竞争强弱(见下「关于 KD / KGR / allintitle 的统一立场」与数据采集指南「广告线的选源方法」)。确认期实测的流量、覆盖词量、增速属于市场占据 footprint,用途是评分与风险说明,不是域名强度替代闸门。
- 天级新词无年度曲线、无月度 volume;Semrush 查无是本赛道的定义属性,不是缺陷。缺失的 volume 不是零需求;缺失的证据也仍是缺失的证据——两者都不许拿来当结论用。
- 窗口期那一格的 G6/G7 只是零成本预筛,不出正式结论(见下「G6/G7 的扫描期用法」);两道门的正式结论只在确认期产生。
- G6 深审入口事实必须映射到六条盈利线:`repeat_paid_task` 只约束 subscription,`official_count_class` 只约束依赖该口径的算式,`self_serve_legal_effect` 才可能否决所有声称替代法律签字的交付。
- 随后完整形成六条 `g6_tentative_lines`,仅供本次 G3 判断否决是否生效;它不是 G6=pass,不得写入账本 gates。

### 扫描期执行顺序

**G0 → G4 → G5 → G6/G7 零成本预筛(含 G6 深审入口预检) → G1 → G2 → G3。**

- G0、G4、G5 的直接筛除型判定与 G6/G7 预筛都不开浏览器,任何一道命中即弃,一次 SERP 都不浪费。
- G5 命中验证型类别时先标记"待 G3 验证",仍须先完成 G6 深审入口预检并取得暂定盈利线,通过后才打开浏览器跑 G3;不能因为类别验证而倒置 G6 与 G3。
- 正常路径上 G1 是第一道浏览器闸门;验证型类别是唯一可能先于 G1 打开 SERP 的例外,但它仍不先于零成本预筛。
- G2/G3 之前有一道强制的深审入口预检(判据见 G6「深审入口预检」):检查重复任务、可验证市场口径与自助交付效力,每个事实只否决它实际影响的盈利线。只有六条适用线全部 `tentative_veto`,或自助交付依法对所有声称的产品形态均无效,才不进深审。答是只表示值得继续建立盈利线证据;仍要完整写六条暂定结论及依据。暂定结论只解决执行顺序,不等于正式通过 G6。
- 数据采集指南的"七条正向选源信号"只负责来源与候选排序,不是额外的七道硬门。其中与 G6 三项入口事实或六线判据重合的证据可用于形成暂定盈利线;其余信号缺失时按对应 G0–G8 判据处理或留在 `captured` 补证据,不得用"七条未全中"替代具体闸门结论。

## G0:合法性与安全 = 硬否决(先于一切)

任务本身违法、违反目标平台服务条款、或其市场由欺诈供血(盗刷密钥/信用卡、批量薅取试用账号、未经授权的中间人数据倒卖)的方向,任何指标下直接否决。同样命中:助长欺骗的规避工具(如让 AI 文本躲过检测或水印)、无法合法运营的灰色需求。(依据:校准 §11.3)

- 零成本推理检查;任何阶段命中即出局,之后不产生最终分数。
- 留痕与 G1 同一条分界(完整表述见生命周期契约「证据与命名约定」的留痕分界):扫描期尚未注册的方向命中 G0,只追加一行淘汰方向索引(`gate=G0`,reason 写清违的是哪一条:违法/违反 ToS/欺诈供血/规避工具),不注册进账本;已在账本里的候选(典型是 tracking 复查中 G0 翻转)才走 `→rejected`。
- 需求真实、措辞正在形成都救不了它:能搜的词不等于能建的站。

## G1:Google 直接回答 = 硬否决

美区、桌面、未登录,搜精确词。首屏若已完成任务即否决:完整作答的 featured snippet、原生计算器/转换器/单位组件、承载全部答案的 knowledge panel、把任务做完的 AI Overview。不否决:只做摘要、而任务仍需要工具或工作流的 AI Overview。搜索引擎自己能完成的任务,任何内容质量都赢不了。

- 环境条件是下终局结论的证据条件,不是"尽量接近"的建议(连续运行下预检共四项:可控、桌面、美区、未登录;完整口径与自检见数据采集指南「G1 SERP 读取规程」)。环境无法满足时,受污染的 SERP 可以作为带环境说明的观察留下,但不能单独支撑 G1=`pass` 或 `veto`;未注册方向不得因此进淘汰索引。
- 缺 G1 的方向要不要留排队位,按运行模式分开:
  - 单步模式:可以注册为 `captured`,gates 不写 G1、带 expiry 排队,之后在合规环境重跑;
  - xinci-run 连续模式:由浏览器预检把该轮降为 `trigger_only`,不得把缺 G1 的新方向注册为 `captured`——原料只能进触发池(registrar 按 `run_policy` 的 `formal_admission` 硬校验;环境条件见数据采集指南「G1 SERP 读取规程」)。
- 执行位置在零成本推理批(G0/G4/G5)之后、一切结构阅读与竞品验证之前;正常路径上它是第一道打开浏览器的闸门,唯一的例外是 G5 命中验证型类别(见「扫描期执行顺序」)。
- 读 SERP 的方法必须能读到 AI Overview,否则本门的结论不成立:读整页文本(如 `document.body.innerText`)再检索 `AI Overview`;读回的文本若从 `Web results` 起始而非整页开头,该次观察作废重读。读法规程见数据采集指南「G1 SERP 读取规程」。(依据:校准 §11.4、§14.4)

### G1=`pass` 之后的自然措辞复测(待验证,见校准 §16「待验证清单」)

- 判出 `G1=pass` 后,先问一句"搜索者真会这样打字吗"。答否(或搜索引擎当场纠正了你的词、或它是把参数硬塞进查询的长尾变体),必须用自然措辞再测一次;两次都 pass 才算 pass,任一次被做完即 `veto`。
- 这一步抓的不只是措辞噪声,还有首屏在不同措辞下选择的不同交付路径(自己做完,或把官方登记册转交出去)。
- 证据基数 2 例:后续运行在 notes 记明本条是否再次命中,累计 3 例后升为正式判据并归并索引 pattern。

### G1 的站点簇反事实

- G1 先判断首屏是否完成精确原子任务,但原子任务被完成不自动等于整个站点机会被否决。
- 必须结构化检查六项:批处理、持续监控、审计轨迹、导出/集成、多辖区,以及原子任务本身。
- 除原子任务外至少一项形成独立、重复且可付费的任务 family → 结论为 `viable_cluster`:改写候选任务,从 G0/G4/G5 与 G6/G7 预筛重新核对新任务后继续 G2/G3。
- 五种扩展都不成立 → `atomic_only`,可按 G1 否决。
- 该反事实不降低 G1,只纠正"关键词=站点"的粒度错误。

### G1 否决后的留痕

- 未注册方向:走淘汰方向索引,不注册进账本(`gate=G1`,reason 写清是什么把任务做完了:featured snippet / 原生组件 / knowledge panel / AI Overview)。G1 否决对它是终局——索引一行留痕,永不复活。
- 已注册候选:走 `captured→rejected`,与 G2/G3 同属会腐烂的 SERP 型否决——registrar 会写 `recheck_after`,可按生命周期契约「受控重开」以新证据重开。分界线的完整表述见生命周期契约「证据与命名约定」的留痕分界。

## G2:完整首页结构阅读

读完第一页,继续到第二页或明显质量断层为止。禁止用 top-3 判断竞争。(依据:校准 §11.7)

- 拒绝信号:视频占屏而任务非视频;维基级/大媒体域名霸榜;强品牌首页(而非内页)霸榜。
- 放行信号:相当比例是内页、小站、论坛帖、明显老化的内容。

## G3:exact-task completion

把每个竞品按"做什么"分类,永不按"是谁"。身份在两个方向上都不说明问题:大品牌的信息页不等于完成任务;无名小站的可用工具就是完成任务。(依据:校准 §11.8)

### 前置:G3 的否决只对"靠自然位吃流量"的模式生效

先看当前阶段可用的盈利线判定,再决定本门的否决是否生效:确认期使用正式 G6 结论;窗口期使用深审入口三项结构事实与六线判据形成的暂定盈利线结论。(依据:校准 §7.1–7.2、§11.9)

- 窗口期观察必须用 `g6_tentative_lines` 逐线写明 `tentative_pass` / `tentative_veto` / `N/A` 及依据,不得把"逐对象重复=是"直接改写成订阅线暂定通过,也不得伪装成 G6=pass。该字段只允许用于 `scan` / `track` 观察,不得与正式 `g6_lines` 并存。
- 暂定盈利线仍未建立时,不能对 G3 作最终门结论,候选留在 `captured` 补证据,不得用未来的 G6 结果倒推当前 G3。
- 窗口期用暂定盈利线得出的只是窗口期 G3 结论;确认期必须随正式 G6 结论复核,不得直接继承"暂定"。

| 靠哪条线过 | G3 占位否决 | 理由 |
| --- | --- | --- |
| **当前通过线全部依赖自然流量**(`affiliate` / `advertising`) | **生效** | 这些模式买不起或不能脱离自然搜索获客;位置被占就是真的进不来 |
| **任一非流量线能过**(`subscription` / `lead_generation` / `transaction` / `paid_report`) | **不生效**,转为决策阶段的获客成本论证 | 自然位不是唯一入口——可买流量、可直销、可走平台市场 |
| **流量线与非流量线同时能过** | **不生效** | 非流量线提供自然位以外的获客与收入路径 |

**映射规则(全文唯一口径)**:下文三问先产出"位置是否被占"的**原始占位判定**,再按上表映射成**有效 G3 结论**:

- 当前通过线全部依赖 affiliate / advertising → 原始 `veto` / `veto_window_bet` 写成同名 G3 结论,`veto` 就是 `veto`;
- subscription / lead_generation / transaction / paid_report 任一为暂定或正式 `pass` → 占位事实只进入竞争记录 / CAC,作为决策阶段的竞争强度输入;有效 G3 一律写 `pass`,不得写 `veto` 或 `veto_window_bet`。

**当前两条赛道的直接推论**:`xinci-scan` 只扫描 `lane=new`,而 new 道 advertising 固定为 `N/A`。

- subscription / lead_generation / transaction / paid_report 任一暂定可行 → 占位事实只进入竞争记录,G3 写 `pass`;
- 仅 affiliate 暂定可行 → 占位否决生效;按下文三分实测判为临时空位时写 `veto_window_bet`(与历史兼容候选走完全相同的挂起与确认流程)。这是 new 道产生 `veto` / `veto_window_bet` 的唯一情形;
- 所有适用线全灭 → 按 G6 预筛出局。
- 下文「唯一的降级出口」与各 SKILL.md 的表述以本段为准。

**占位审计顺序**:经营信号预检 → 真工具计数 → 持续可见度,依次执行;前两步已经得到原始 `pass` 时不再往下走。旧判据"≥2 个免费结果把任务做好即否决"已废止,无论数的是文章还是工具都不再使用。(依据:校准 §5、§6、§11.9)

### 经营信号预检(优先于工具计数)

数工具之前先看三个信号,都能从 SERP 加一次站点访问里读到:

1. 内容后面有没有付费产品(pricing 页、定价档、付费服务)
2. 有没有按国/按任务的簇,而不是孤立单篇
3. 有没有维护痕迹:methodology 页、source status、last-checked 日期、公开 change log

- 三个信号齐备 → 原始占位判定为 `veto`,不必再数工具形态;随后按映射规则得出有效 G3。高质量判定页即使按"工具 vs 文章"判据算文章,只要它是通往付费产品的漏斗且背后有成簇资产,也按此判。
- 只写了孤立文章、没有付费产品、没有维护痕迹的占位者,才回到第一问的工具计数。三个信号只中一个时回到工具计数(反面样例见校准 §6、§11.11)。

### 第一问:只数"能替用户完成任务的工具",不数文章

- 计入否决线的只有真工具——计算器、生成器、结构化查询/数据库、能跑出结果的仪表盘,即替用户把事情做完的东西。
- 不计入否决线(只作评分扣分项):解释性文章、官方文档与流程说明、律所提示与客户通报、论坛线程、视频教程、新闻报道、盘点式 listicle。
- 真工具 0–1 个 → `pass`,直接进入建站评估;真工具 ≥2 个 → 进第二问。
- 数工具必须用两族措辞各检索一次,缺一不可:①用户问句式——搜索者会怎么问;②产品向——`<义务> software` / `platform` / `tool` / `checker`。工具排名靠的是产品向措辞,只按问句式数工具会系统性漏计;能同时通过两族措辞检索的 0 工具结论才可信。(依据:校准 §11.10)

### 第二问:≥2 个真工具时,一律进第三问

真工具 ≥2 个 → 直接进第三问,不看占位者是小站还是大厂。"小而专的新站在场 → pass"的旧修订已回退,不得再用。(依据:校准 §10 校准一、§11.12)

### 第三问:"持续可见度"怎么判(这半条判据决定结论,不许略过)

前提是已有 ≥2 个真工具。此时还要问:它们为什么(不)在这个查询的首页上?下表给的是原始占位判定,再按前置节的映射规则得出有效 G3:

| 那些免费实现 | 原始占位判定 | 依据 |
| --- | --- | --- |
| 在本查询 SERP 上有持续可见度 | `veto` | 位置已被占满,任何内容质量都抢不回来 |
| 排不上,但只因对象太新还没被收录 | `veto_window_bet` | 位置只空几天;是窗口赌注,不是生意 |
| 结构上进不来 SERP | `pass` | 位置没被占——它们不具备"持续可见度",不计入否决 |

- "结构上进不来"指:站内应用页(如 Hugging Face Space 这类)被索引得极差、功能在登录墙之后、平台内嵌工具、只存在于 App 而不在 web 上。这类实现无论多好用,都不占据这个查询的位置。
- 临时空位的寿命必须每次实测,不是常数:收录时差是一个会变的量,同时是本门判 `veto_window_bet` 的定价依据与 G7「官方答案风险」的依据;"还没收录"时空位还剩几天,只能来自下面「判定前提」要求的那次实测(历次实测值见陷阱类别.md 类别一)。

### `veto_window_bet`:唯一的降级出口

占位否决已经按盈利线判为生效(见前置节映射规则;任一非流量线可行时同一批"尚未收录"的事实只作竞争与窗口风险记录,不得写本档)、且判定为临时空位的候选,不直接出局,但只准走快道,条件与限制一并生效。

**判定前提(缺此项只准判 `veto`)**:必须实测至少一个通用实现对上一个同类对象的收录时差——打开它的页面看它多久前收了上一个同类对象。这是窗口期拿得到的浏览器证据,也是"空位还剩几天"唯一可证伪的锚点。

- 不做这个实测,"只是还没收录"就只是猜测,一律按 `veto` 处置;
- 时差以天计 → 空位以天计,可赌但须明码标价;
- 时差以月计或根本没收 → 空位比想象的持久,回头重判是否该记 `pass`。

**进入条件**:上述实测 + `window_estimate=days` + 转移必须带 reason(降级依据写进账本 history)+ 观察文件记明数到的免费实现清单、收录时差实测、以及"为何不在本查询 SERP 上"的判断。

**在 `captured`/`screened` 上的合法出口共四个**,按状态拆开读:

- `fast_grab_ready`:唯一的 go 出口,仅从 `screened` 走快道;
- `rejected`:仅从 `screened`——快道读完证据判定赌注不值;`captured` 挂起候选不得转 rejected,它仍有待确认的快道出口;
- `withdrawn`:用户撤回,两态皆可;
- `expired`:expiry 过了,两条来路都算——挂在 `captured` 等确认期间排队过期,或已出闸到 `screened` 后窗口自己过了。
- 走通快道之后还有 `fast_grab_ready → built`;`superseded` 仅可从非终态以及 `disqualified/no_site` 转入,不是任何状态都可用。这些是 go 后或候选替换的后续,不在四个窗口出口之列。
- `validate_ledger` 的 `WINDOW_BET_STATES` 放行整个终态集,表示这些终态可保留该 G3 历史结论,不表示每个终态都有 `superseded` 出边。
- 禁止 → tracking:这个降级结论的风险不会随时间变好只会变坏(通用工具正在收录),放它进追踪等于让它绕过 G3 走到全站。

**快道与升级**:

- 快道决策书必须明码标价:本次只赌收录时差,通用工具收录后位置即失;
- built 之后若走 `built → tracking` 升级通路,必须重跑 G3 并取得真 pass——降级结论只在快道这一次有效。

**出闸要用户确认,不在连续运行的标准授权内。** 挂起位、确认机制(`run_controller.py confirm-window-bet`)、不许替代性处置、gates 怎么写进账本(register 还是 amend)、以及挂起期间过期怎么走,正本都在生命周期契约「窗口赌注的挂起与出闸」;本节只定判据,不复述那套状态与授权机制。

两种来路的后续流程完全相同:账本里已合法登记的历史兼容候选,与本轮 new 扫描在「仅 affiliate 暂定可行、占位否决生效」前提下新判出的(产生条件见上文「当前两条赛道的直接推论」)。

### footprint 要求按阶段分层(与时间光谱一致,勿混用)

- 窗口期(scan 当场跑 G3):只用浏览器可得证据判否决线——打开竞品页面实测任务完成度、内容新旧、更新频率、`site:` 收录规模。此阶段不要求流量/词量数据(窗口期禁用 Semrush,该要求客观无法执行)。
- 确认期(qualify 的完整竞争审计):下最终结论前必须实测至少一个竞品的真实 footprint(authority、流量、词量、增速)。其中 authority 只作背景记录,不得给 G2/G3 下结论或直接挣竞争分;流量、覆盖词量、增速用来回答"实际占了多少市场",只进入竞争评分与风险说明。存在不等于占据——竞品的存在什么都不证明,直到你知道它实际占了多少市场。

## G4:任务可完全在线完成

需要实地检查、物理采样、实验室工作、持照人员到场的任务,一票否决,指标再好也不看。这道过滤零成本、直接取消资格,与 G0/G5 同批、先于一切浏览器工作执行。(依据:校准 §11.15)

## G5:陷阱类别检查

先于 G2 结构阅读执行。只有 SERP 陷阱型的共同特征是"过 G2、死 G3"——结构看起来诱人恰恰是陷阱的表象;前置筛除型则在任务、商业或耐久性前提上直接出局,根本不进入 G2/G3。两型都应先识别,但死因不能混写。

命中 [陷阱类别.md](陷阱类别.md) 的候选,按该类别节自带的处置执行——两种处置,写在类别标题里:

- 验证型:跳过结构阅读直接跑 G3 验证,但仍要先按盈利线判断占位否决是否生效;只有当前通过线全部依赖 affiliate / advertising 时 G3 判 `veto` 才弃。任一非流量线暂定可行时,同样的占位事实降为竞争输入,G3 有效门结论写 `pass`,不因命中类别直接出局。用于死因取决于本方向具体情形的类别(如类别一「新发布 AI 模型」:窗口有多长要看这个模型的收录时差)。
- 直接筛除型:零成本判定即弃,一次 SERP 都不跑。用于死因已经结构性确定、逐条验证只是重复劳动的类别。两种来路:
  - ①前置筛除型死因天生如此,连可搜索的任务都产生不了,没什么可验证(类别二「纯品牌名发布」);
  - ②SERP 陷阱型验证满三次、死因每次都相同、且样本满足独立性要求(跨日期、跨来源家族,见陷阱类别.md「如何追加新类别」)后改标降档(类别四「厂商 release note / changelog 衍生任务」即此例;类别三独立性虽凑够,但其死因是方向级事实,仍保持验证型)。

处置档按死因型定:

- SERP 陷阱型新建时默认验证型(建类发现即做,不必凑满三次),只有当三次实际观察都指向同一个结构性死因、该死因与具体方向无关、且样本满足陷阱类别.md 的独立性要求(跨日期、跨来源家族)时,才改标为直接筛除型。
- 前置筛除型一律直接筛除型,不受"三次观察"约束——它连可搜索的任务都产生不了,没有词可搜就没有 SERP 可读、没有 G3 可验证(类别二「纯品牌名发布」即此例)。

G3 验证存活的候选,G5 记 pass(观察文件注明命中的类别与验证要点),回到正常序列把 G1、G2 补齐——captured→screened 要求 G0/G1/G2/G4/G5=`pass`,G3=`pass` 或状态机兼容的 `veto_window_bet`;后者是降级出口,不叫"全过"。陷阱验证通过不豁免任何其他闸门。

"存活"含 `veto_window_bet`:

- G3 三分里只有 `veto` 是出局,`pass` 与 `veto_window_bet` 都还有下一步(后者只有快道一条)。两者都要注册进账本,不走索引一侧——留痕分界的第一条(它还有下一步)命中了它,区别只在出口(`pass` 回正常序列走全程,`veto_window_bet` 只有快道)。
- 注册时它还缺 G1/G2,所以按排队位注册:带 gates(含本次 G3 结论)与 expiry,补完 G1/G2 才出闸(见生命周期契约「留痕分界」①的 b 类)。

每当扫描出现"过 G2 死 G3"的新模式,追加进陷阱清单,记录实际观察而非只记泛化结论。

## G6:商业闭环

G6 是六线 OR 闸门:六条盈利线各用适合自己的证据判定,至少一条适用线通过即 pass。不得把某条线的结构条件或金额门槛套给其他线。(依据:校准 §9.2、§11.20;两线到六线的按语见校准「现行结论索引」)

### 六线判定

六条线:`subscription`(持续软件/数据订阅)、`lead_generation`(高价值服务线索)、`affiliate`(可归因购买推荐)、`transaction`(按次撮合/办理)、`paid_report`(一次性付费报告/证明包)、`advertising`(规模化展示广告)。

- 正式与暂定 G6 均逐项检查六线;六条线都要给出判定结果,但"判定"不等于强行取不存在的数据。新观察六项都要写 `pass|veto|N/A` 或对应暂定值;历史只含订阅/广告的观察继续可读,但不得作为"其他四线已否决"的证据。
- 赛道只固定 advertising 的适用性:
  - `lane=new` 的 advertising 结构上不适用,明确记 `N/A`;其余线按证据写 pass/veto/N/A——subscription、lead_generation、affiliate、transaction、paid_report 仍逐项审;
  - `lane=mature` 可审 advertising,并按数据采集指南取量级数据。

| | 硬门 | 金额如何处理 | 适用赛道 |
| --- | --- | --- | --- |
| **订阅线**(付费产品/服务) | ①明确的付费者;②被迫或重复的任务;③自助变现路径;④同一周期的「受约束付费客户数 × 可行单价 − 获客与交付成本」有来源且 base case > 0 | 金额大小不是 G6 硬阈值,进入收入可行性 20 分维度 | `new` / `mature` |
| **广告线**(AdSense 一类) | 有实测簇内月搜索量、现实可达 CTR、有出处的 niche RPM,且 base case 达 **$200/月** | $200/月是该线的量级硬门;超过多少再影响收入得分 | 仅 `mature` |
| **线索线**(lead_generation) | 可验证目标账户或高价值服务需求 × 保守成交贡献,交付为线索而非法律结论 | 少量高价值需求可成立,不套广告量级门 | `new` / `mature` |
| **联盟线**(affiliate) | 有购买意图的自有搜索流量 × 转化率 × 佣金 | 依赖自然位,受 G3 占位与量级证据约束 | `new` / `mature` |
| **交易线**(transaction) | 可重复办理/撮合次数 × 单次抽成 | 用交易频次与客单价,不强制官方主体总数 | `new` / `mature` |
| **付费报告线**(paid_report) | 报告/证明包份数 × 单价 − 生成与支持成本 | 一次性付费可成立,但不得冒充有法律效力的认证 | `new` / `mature` |

- 每条通过线都必须写清:付费者、付费事件/重复单位、可交付物、保守单价与数量、收入算式、来源和最大反证。任一项缺失只能暂定或 inconclusive,不能写正式 pass。
- 订阅线的"base case > 0"只证明结构闭环,不等于值得做。正式认定还要求收入可行性维度至少 1/20;registrar 用 `income_score` 强制。金额偏小、付费者子集或 CAC 不确定,都应压低该维度并进入红队扣分。
- 金额阈值的边界:订阅线的金额大小是评分输入,不是 G6 硬线;广告线的 $200/月是硬线。不得用同一把金额尺判两条线。(依据:校准 §9.2、§11.17)
- 新词道扫描期仍不取 volume,但"无重复任务"只把 subscription 写成 `tentative_veto`;还要继续检查 lead_generation、affiliate、transaction、paid_report。只有所有适用线全灭才出局。
- 判定与留痕:观察文件完整逐线写 `pass` / `veto` / `N/A`、算式、假设与来源;账本 `g6_passed_lines` 只写六线中实际通过的项。任一条 pass 即 G6 放行;`lane=new` 的账本不得写 `advertising`。

**广告线必须把反推算式写出来**,不许只写"可以放广告":

```
需求会话数      = 目标月收入 ÷ RPM × 1000
需求簇内月搜索量 = 需求会话数 ÷ 可达位次点击率
```

- RPM 按 niche 取值并注明出处(金融/法律/保险类显著高于技术/开发类);点击率必须用新站现实可达的位次估,不许用位次 1 的 20–30%。
- 示意量级:目标 $200/月、RPM $8、点击率 5% → 需求簇内月搜索量约 50 万;RPM $30 时约 13 万。
- $200/月是广告线硬门槛;算式、实测量级或来源缺一,该线即 veto。
- 广告线的三个条件是一个乘性夹逼,不许当成可以分别满足的条件(证据基数 3 例,见校准 §16「待验证清单」):广告线要求量级 × RPM 大且防守弱,但前两项与第三项系统性反相关——
  - CPC 高不只是 RPM 代理,它本身就是"这一格里有钱、有人在经营、防守必然强"的直接证据;
  - 防守弱的地方通常正因为商业价值低 → RPM 低 → 需求量级反而暴涨;
  - 窄 B2B 垂类兼具好单价与无总量。
  - 所以"高 RPM + 无人经营"在成熟词上接近自相矛盾。门槛与选源方法见数据采集指南「广告线的选源方法」。

### 订阅线第③项"自助变现路径":这个结论要不要第三方签字才算数

答案本身算得出来,但算出来的结论必须经认可机构周期性核验才具法律效力时,自助网页工具做不出可申报的结论——付费流向能签字的那一方,不流向工具。(依据:校准 §11.17)

- 判法一句话:问"这个结论要不要第三方签字才算数"。要,只否决那些声称可替代该签字或认证的交付线。
- 只有候选声称的所有产品形态都依赖这份法律效力、因而六条适用盈利线全部无法成立时,才记录全局 `self_serve_legal_effect` 并让整候选 G6 出局;若仍可合法提供线索撮合、非认证报告或其他不冒充法律结论的交付,就在对应 `g6_tentative_lines` 逐线判定,不得使用全局入口否决。
- 签字方常常正是"会因这个结论少一单生意"的那一方,要单独认出来:凡措辞是"我能不能免测 / 免检 / 复用既有报告",先查一句这个结论由谁出具才算数;答"由本来要给你做那次测试的机构出具"即命中本项,零成本弃——这类方向看起来"没人有动机免费做",实际是位置被法律封死。
- 索引 pattern 的规范名:本项判否的方向写进淘汰方向索引时,`pattern` 一律写 `自助结论须第三方签字才算数`,不另起名。
- 别和类别十搞混:类别十的死因是「已经有人免费供给了答案」;本条的死因是「没人供给,但自助结论在法律上根本不算数」,杀的是交付路径不是需求。两者可以同时命中,reason 要分开写。
- 与类别十一(持牌机构合规义务)是同一机理的两个位置:类别十一在责任侧(判错的代价是法律责任,付费流向能担责的持牌人),本条在效力侧(判对了也不算数,除非有人签字)。法律把某个签字设为前置条件时,那个签字就是价值链上的收费站,自助工具绕不过去。

### 订阅线第②④项:付费者数与赌注

- 估算「受约束付费者数」:行业规模不等于受约束子集。允许用代理口径起算(判法与三项必写见下文「深审入口预检」②a),但行业规模只能作显式标注的**上界**,算式里必须是折算后的保守下界;折算比例有出处就引出处,是假设就标为假设并取最不利档。
- 同时要写清赌注:付费意愿来自判错的代价,不只是任务的存在;赌注量级是第④项 base case 的输入。
- 赌注必须排在任务后面判,顺序不可倒置:先问第②项(有没有人被迫逐对象反复做这个判定),答"是"再问赌注多大;答"否"就停在第②项,不要再去算赌注——赌注替代不了第②项,第②项不成立时赌注再大也没有可卖之物。引用 `eu-machinery-regulation-risk-category` 作类比之前,先确认对方也得自己判。(依据:校准 §11.17)
- 新东西只有通过"真实触发造出真实任务"才挣分:一个没有被迫需求的新名词,触发、任务、语言形成全部零分。
- 实测价格锚与付费者量级标尺(供估算「可行单价」「受约束付费者数」时对照)见校准 §11.17。

### 深审入口预检(强制,零成本,先于 G2/G3):三项结构事实

两条赛道进入 G2 结构阅读与 G3 竞品验证之前,都必须检查三项:重复任务、官方计数口径、自助交付法律效力(`lane=new` 在 xinci-scan 第 2 层做,`lane=mature` 在 xinci-mature 第 4 层随六线判定一并做)。

- 三项都是零成本结构判断;已有官方原文可直接判,证据不足时先补来源,不得把未知写成否决。
- 前两项只影响依赖它们的盈利线;第三项只有在全部声称交付均依法无效时才使用全局 `self_serve_legal_effect`(判法见上「订阅线第③项」)。

**第一问:这个任务是否要求有预算的付费者「逐个对象」重复完成?**(每个 SKU / 场址 / 批次 / 市场 / 申报各做一次)

- 答否——只把 subscription 判为结构 veto。继续检查 lead_generation、affiliate、transaction、paid_report;只有其余适用线也全部暂定否决才不进深审。
- G3 只是最后签字的那道门,真正的拦截点在这里。(依据:校准 §5、§11.18)

**第二问:这项义务的受约束主体,是不是一个有名称、且官方会去计数的类别?** 问它是因为第④项要求「受约束付费客户数 × 可行单价 − 获客与交付成本」有来源且 base case > 0,而本门禁止拿行业规模当付费者数;受约束主体若不是官方会计数的类别,第④项结构性不可得。拆成两小问依次答:

- ②a 官方会不会去计数这个类别?判定只看主体是怎么被界定的(依据:校准 §11.18):

| 主体怎么界定 | 官方会不会计数 |
| --- | --- |
| 按主体类别,且该类别有通行名称 | 会 |
| 按主体类别,且该类别有法定范围 | 会 |
| 按行为界定(做了某个动作才受约束) | 不会 |
| 主体范围过广,无对应统计口径 | 不会 |

- ②a 答否**不直接把依赖计数的算式判死**,先问一句「有没有可用的代理口径」:官方产业统计或影响评估里的企业数、公告机构/认证机构名录条数、行业协会会员数、平台侧公开的卖家/开发者数、公开登记库里的行为主体数。允许代理口径的理由是实测:账本 428 条否决里 231 条的理由开头就是 G6,其中"受约束主体无官方计数"一族占 60 条——契约本意只否决依赖该计数的那条线,执行时却把其余四线一并写成 `tentative_veto`,结果与一票否决无异。
- **用代理口径必须同时写三样,缺一按未取得处理**:①口径来源(一手 URL 与原句);②它相对受约束主体的**偏差方向**(高估还是低估,为什么);③取值时用的**保守下界**——代理数 × 明写的折算比例,折算比例本身要么有出处、要么标为假设并按最不利档取。示例(2026-08-31 实测):CPR 影响评估 SWD(2022) 88 的 430,000 家建筑产品企业是**上界**(偏高:含不落入 hEN/EAD 覆盖的企业),子集比例未取得,故按 0.05% 的极保守折算得约 215 家进 base case,并在观察文件里写明该折算是假设。
- 代理口径也拿不到时才写 `tentative_veto`,并按下文 `g6_entry_veto` 留痕。无论用不用代理口径,**都不得拿行业规模本身当付费者数**:上界必须显式标成上界,算式里出现的必须是折算后的下界。
- 观察可写 `g6_entry_veto(criterion=official_count_class)` 记录结构事实,它不能单独授权整候选 rejected;必须同时完整填写六条 `g6_tentative_lines`,由"所有适用线均暂定否决"支撑出局。
- ②b 那个计数公不公开、检索得到吗?强制登记只证明官方握有这个数,不证明它发布这个数。②a 是"根本没这个数",②b 是"有这个数但不给看"。(依据:校准 §11.18)
- ②b 答否是证据缺口,不是死刑:该方向停在触发池等一个公开时点(典型是评估报告、影响评估或年度报告发布),不注册为候选、也不判 `rejected`;trigger 的 reason 里写清已穷尽哪些路径、还剩哪一条。什么时候公开不由本工作流决定,所以不该反复重跑同样的路径——路径穷尽后就停手。
- 零成本层怎么判 ②b:开浏览器前先问"这个登记系统是公开检索的,还是只对主管机关开放的"。EUDAMED、F-gas Portal 的 Actor/配额数据是前者;CPNP 是后者。分不清时按未知处理,进深审前必须先解决,不得带着未知往下走。
- 索引 pattern 的规范名:②a **连代理口径也走空**、且其他适用盈利线也全部暂定否决,写进淘汰方向索引时 `pattern` 一律写 `受约束主体范围过广无官方计数`;②a 单项失败但其他线可行、或代理口径可用时不进淘汰索引。历史上的两个名字(`受约束主体范围过广无官方计数` 6 次、`受约束主体无官方计数口径` 3 次)合并计数时按 9 次算。
- pattern 名是给机器数的键,不是给人读的描述:`screen_index.py stats` 按 `pattern` 字符串精确计数,索引是追加式、不得手工编辑。新起一个 pattern 名之前,先用 `screen_index.py stats` 看同一死因有没有已在用的名字;有就照抄,别改写措辞。

## G7:耐久性

逐一排查以下杀手:

- 版本更替风险:为一个版本买的域名,随下一版发布而过期。重复任务若属于通用工具,那是另一条已被争夺的赛道。
- 官方答案风险:厂商、平台多快会发布自己的答案?工具厂商收录新对象的时差是一个会变的量,每次按 G3「判定前提」实测,不引用常数(历次实测值见陷阱类别.md 类别一)。
- 好奇 vs 任务:只产生一周好奇、没有重复任务的东西,不值一个域名。直说,不进清单。
- 生效日远在未来——判之前先看付费者是谁(依据:校准 §3、§11.19):
  - 生效日远 + 付费者是消费者 → 任务还没出生,零成本弃。
  - 生效日远 + 付费者是受义务约束的企业 → 这恰恰是入场窗口,不构成否决。企业面对有日期的合规义务会提前准备,建站者也提前入场。此时该问的不是"还有多久生效",而是"占位者做了工具还是只写了文章"(见 G3 第一问)。

## G6/G7 的扫描期用法:零成本预筛,不出正式结论

G6/G7 的正式结论只在确认期产生(证据要求见时间光谱表),但部分结构事实在扫描期就可零成本预筛:

- 无被迫/重复任务:只把 subscription 写成 `tentative_veto`;继续检查 lead_generation、affiliate、transaction、paid_report。只有它同时表现为一周好奇、没有任何可付费事件,导致所有适用线均暂定否决时,才按 G6 预筛出局;
- 官方答案在途 / 一次性配置(G7):厂商自己会在几天内发布答案的方向,窗口不存在。

这类预筛与 G0/G4 同批执行、同样零成本,否决后按秒弃留痕进淘汰方向索引(gate 记 G6 或 G7)。它们不产生分数,也不构成认定阶段的 G6/G7 结论——扫描期筛掉的是"连任务都不成立"的方向,不是"商业闭环算不算成立"的判断。

## G8:簇广度

**认定门(硬否决)**:**合计** ≥3 个任务型查询,且它们分布在 ≥2 个独立 family(不是每个 family 各要 3 条)。达不到即 disqualified,不产生分数。

- G8 与 G6/G7 同为 qualified 的前置,未过的候选到不了完整模式的 go 决策(registrar 的 qualified 要求 G6–G8 全 pass,而 build_ready / pilot_ready 只能从 qualified/hold 转入)。

快道的 `fast_grab_ready` 也是 go 决策,但走另一条路:`screened → fast_grab_ready` 不经过正式认定。

- 扫描期已形成并留存的 `g6_tentative_lines` 只服务于当期 G3,不能冒充正式 G6;G6–G8 的正式认定证据此刻仍不完整。这是减配不是豁免——未完成项必须在快道决策书里逐条明码标价。
- 单步模式由用户读完披露后确认转移;xinci-run 连续模式中,普通 `G3=pass` 快道由启动命令的标准授权执行,不得谎称用户事前逐条读过;`G3=veto_window_bet` 仍须候选级一次性明确确认。
- 准确的说法是:未过 G8 的候选到不了完整模式的 go 决策,但可以到风险已披露、授权状态已写明的快道 go 决策。

**决策门(降级线)**:全站页面地图要求 ≥12 个任务互异页面 × ≥3 个簇 + ≥1 个自助产品资产。合并表述性变体,不许拿同义改写凑页面数。

- pilot 由这条线触发:G8 认定门已过、但决策阶段的页面地图凑不满全站规模的候选,降为 pilot 或 no_site。
- pilot 的首发范围固定为从现有页面地图中选择 5–8 个最高价值页面;若完整地图已有 9–11 页,仍因未达 12 页全站线而属于 pilot,多出的页面列入实验后的扩展 backlog,不是规格空档、也不把首发硬扩到 9–11 页。

两条线不可混用:认定门问"机会是不是真的",决策门问"够不够撑一个全站"。

## 关于 KD / KGR / allintitle 的统一立场

这些是标题/域名强度代理,对"是否有人已把任务做完"完全失明,而后者才是竞争的大头。实测背离宽且单向:KD 14 对实测竞争 89、KD 27 对 71、KD 44 对约 85——真正把任务做完的站往往域名指标很弱。(依据:校准 §7.2、§14.30)

- 低 KD 只触发一次 exact-task 完成度检查(G3),永不作为鼓励;窗口期禁用。
- KD、Authority Score、外链数等不得决定 G2/G3,也不直接进入竞争分。
- 确认期允许的 footprint 是另一类证据:流量、覆盖词量、增速衡量竞品实际占据,可作为竞争评分的小部分与风险输入,但不得反向改写门结论。
