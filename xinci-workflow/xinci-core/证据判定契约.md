# 证据判定契约

扫描、追踪、认定与决策共用本文件；闸门判据仍归闸门契约，分数归评分契约。

## 事实与缺口

| 类型 | 含义 | 处理 |
| --- | --- | --- |
| structural | 有证据证明条件不成立，例如交付依法无效 | 只影响依赖该条件的任务或盈利线，不自动连带否决其他线 |
| access | 登录、维护、限流等导致本次访问失败 | 不算需求或竞争的负面证据 |
| coverage | 数据服务不覆盖小站、计数不公开或不存在对应统计 | 先找代理证据；无统计不等于无市场 |
| unverified | 尚未核实的假设 | 保留未知，不能写 pass、veto 或用 N/A 掩盖缺证据 |

每个决定性缺口写明影响对象、已查路径与下一项能改变判断的证据。代理估计须列来源、偏差方向、显式假设与敏感性范围；保守假设不是已证实的下界。结论对合理假设范围敏感时仍属未解决。

已证明的硬否决可独立结束认定；否则，决定性缺口未解决时不出分、不作商业否决。非决定性数据缺口不阻断认定，但必须说明其他证据为何足够。缺少第三方 footprint 时，可用已实测的产品覆盖、维护记录、客户或使用案例作替代，不把没有覆盖解释为零占据。

认定暂缓的 pending_until 是复核日期，不是强制判死日期。到期先检查访问条件或替代证据是否变化：已足够则认定；仍不足则记录本次核查及下一项外部事件，用 defer-qualify 更新复核日。相同条件下不重复深审；没有可执行补证据动作时报告受阻并继续其他候选，保留原状态，不以到期制造 disqualified。

## 官方与免费供给

G1、G3、G5 的供给事实共用一次任务覆盖检查：实际完成的任务、对象粒度、剩余任务 family、受影响的盈利线。已有供给不等于全部任务完成；有动机提供工具也不等于工具已存在。

- 首屏完成任务：按 G1 站点簇反事实判断。
- 站点或官方工具完成任务：按 G3 的占位规则及 G6 逐线判断。G5 供给类标签只路由验证，不另造一票否决。
- 剩余可付费任务成立：改写站点任务并复查 G0/G4/G5 与商业预筛，不继承原任务的通过结论。
- 只有经验证的原子任务已被完成、无剩余任务且全部适用线不成立，才按对应闸门淘汰。

同一次审计的 SERP、竞品和收入假设只记录一次于观察的 points/source_urls；G1/G2/G3 引用同一份证据。跨阶段仅在证据失效、任务改变或正式认定要求复核时更新。G6、评分、决策收入三情景引用同一组假设，变化时说明新增证据，不重复编写互相独立的商业计划。

## 共用记录与出口

使用既有 observation.points，不增加独立台账或必填顶层字段。对本次实际需要的事实采用候选内稳定编号；后续阶段引用“数据区相对观察路径 + 编号”，更新时说明替代哪条记录。旧观察无编号时引用文件与具体要点即可，不回写历史。

| 记录 | 一次写清的内容 | 消费者 |
| --- | --- | --- |
| coverage-1 | 输入对象、实际输出、已完成任务、剩余 family、受影响盈利线、现场来源 | G1/G3/G5；G2 复用 SERP 但独立判断意图 |
| income-1 | 盈利线、付费者、付费事件、数量与价格、转化、CAC/交付成本、来源、假设范围和最大反证 | G6、收入评分、决策三情景 |
| risk-1 | 一个事实及其直接影响、对应 coverage/income 引用、唯一扣分归属 | 评分与决策风险复核 |

这里只统一记录形状，不新增闸门。仍按实际阶段提交 gates、六线字段和 assessment；来源打开纪律与证据有效期仍适用。旧证据引用不冒充本次打开的 source_urls。一个事实若有多个独立影响，分别说明因果；换编号不能把同一影响扣两次。

| 当前证据 | 扫描/追踪 | 正式认定 |
| --- | --- | --- |
| 至少一条盈利线充分成立 | 暂定线仅支持当期 G3；不写正式 G6 | G6 可 pass，再审其余硬门与评分 |
| 所有适用线均有否决证据 | 按 G6 预筛及既有留痕边界淘汰 | G6 veto，不评分 |
| 仍有决定性未知且没有独立硬否决 | 记录缺口与下一项证据；按既有入口保留原料或候选 | 暂缓，不用低分代替未知 |
| 其他门已有独立、充分的硬否决 | 按该门既有出口处理 | 可否决，不必补齐无关盈利线 |

判据与数值只维护在闸门契约；本表负责未知/暂定/正式的共用出口。认定提交参数由 qualification.py 生成，阶段 Skill 不另算总分。状态写入仍由 registrar 执行。

## 新认定的机器记录

新 qualify 观察使用 schema_version=3，增加 assessment；旧 v1/v2 继续可读，不回写。字段结构见 [assessment.schema.json](数据结构/assessment.schema.json)。

- evidence_gaps：item、kind、decisive、resolved、reason。resolved=true 必须在 reason 说明取得的证据或替代依据。
- scores：通过硬门且决定性证据充分时填写六维整数分；暂缓或硬否决时为 null。
- risks：每个事实一个稳定 id，只指定一次 charged_to（六维之一或 red_team）。维度 deduction 已体现在 scores 中；只有 red_team 再从总分扣除。不同 id 不能掩盖同一个事实。
- seo：可评分时记录 query、gap、source_urls，证明自然搜索入口与任务缺口；直销或买流量不能代替 SEO 证据。无需评分时为 null。

运行 `python3 xinci-workflow/xinci-core/scripts/qualification.py <观察文件路径>` 校验并生成总分、收入分、通过线与建议出口。输出只是提议；状态仍由 registrar 按既有权限写入。registrar 校验 v3 的计分、硬否决、暂缓及提交参数一致性。
