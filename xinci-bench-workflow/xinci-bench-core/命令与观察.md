## 2. 运行清单

```bash
python3 $S/run_log.py --plan
python3 $S/run_log.py --skill xinci-bench-scan --run-id run-20261014-a --round 1 --max-rounds 3 \
  --source-kind legacy --seed-value "种子池 legacy 前 16 个" --outcome started --next-step scan
python3 $S/run_log.py --finish --run-id run-20261014-a --outcome completed --semrush-calls 5 \
  --direction-touched example-county --note "16 个初核,2 个登记"
```

- 每阶段先写 started，结束用 `--finish`（completed / blocked / skipped），脚本推导下一步。
- found 已有 ≥ 3 个时 `--plan` 返回 `scan_outcome=skipped`：照样先写 scan started，再 `--finish --outcome skipped`。
- `--semrush-calls` 只填本条新增的调用数。
- `--plan` 还给出今天两条道合计的 Semrush 用量：`semrush_calls_today`、`semrush_daily_limit`（100）、`semrush_left_today`、`semrush_stop`（今天已用到 90 次时为 true，此时不再开始花 Semrush 的步骤）。

## 7. 新词快道

### 7.1 运行清单

```bash
python3 $S/run_log.py --plan --lane quick
python3 $S/run_log.py --skill xinci-bench-quick --run-id quick-20261014-a --round 1 --max-rounds 1 \
  --source-kind quick --seed-value "自动补全、Trends 飙升、SteamCharts、Product Hunt" --outcome started --next-step quick
python3 $S/run_log.py --finish --run-id quick-20261014-a --outcome completed --semrush-calls 1 --note "扫 40 条原料,登记 1 个"
```

快道一次运行只有一个阶段：`round` 与 `max-rounds` 固定为 1，`source-kind` 固定为 `quick`；受阻用 `--outcome blocked`，之后同一运行编号再 `--finish`。快道与标杆道的未完成运行互不阻塞。

### 7.2 扫信号与原料池

```bash
python3 $S/suggest_snapshot.py --object "Grow a Garden 2"          # 对象名 + 空格,以及对象名 + 10 个任务词
python3 $S/suggest_snapshot.py --query "grow a garden 2 calculator"
python3 $S/suggest_snapshot.py --object "Grow a Garden 2" --gl gb  # 地区性对象查别的英文国家:gb | ca | au | nz | ie
python3 $S/write_observation.py --input <quick_signal 观察文件>
python3 $S/quick_pool.py add --observation 证据/_quick/<文件名>
python3 $S/wiki_releases.py --output <scratchpad>/wiki_releases.json  # 最近 14 天已上线与未来 30 天要上线的新游戏,按浏览量取前 20(items 并进 quick_signal)
python3 $S/quick_pool.py pending --top 10                          # 按优先级取首屏速判的 10 个(还没到开玩日的不列)
python3 $S/quick_pool.py upcoming --days 14                        # 即将开玩:开玩日在今天之后 14 天内的原料
python3 $S/quick_pool.py expire                                     # 7 天没拿到"有人在搜"证据的标 expired
python3 $S/quick_pool.py mark --id <原料 id> --status used
python3 $S/quick_pool.py reject --term "<说法>" --gate occupied --observation 证据/<方向>/<速判观察> --seed-domain <占位小站>
```

Trends 飙升词在 Trends 页面里用 `scripts/trends_fetch.js` 全文加一行 `await xinciTrendsRising({term: "beta", cat: 8})` 执行（`cat: 8` 是游戏分类，任务词用 `cat: 0`），每次运行最多 6 个种子词、两次执行之间隔 ≥ 30 秒、遇 429 停下（`数据采集.md` §7.2）。返回的 `rising[].rising` 是百分比或 `"breakout"`，可原样写进原料 `rising`。

带 `playable_at` 的原料：开玩日在今天之后的不进 `pending`、只进 `upcoming`，看板列出"建议开玩当天到第 3 天跑一次快道"；保留 7 天从开玩日起算；同一对象再被看到时开玩日期与阶段以最新的为准。

`quick_pool.py reject` 与 `ledger.py register-quick` 会把对应说法的待看原料自动标 used；过期的原料再被来源取回时重新进池（保留原 id，记 `revived_at`）；淘汰过的词再被取回时报淘汰原因。

快道观察的公共字段同 §3.1，`stage` 固定为 `quick`。`quick_signal` 一批一份，`slug` 为 null：

```json
{
  "kind": "quick_signal",
  "readings": {
    "items": [
      {
        "source": "autocomplete",               // autocomplete | trends_rising | trends_rss | steamcharts | apple | itunes | google_play | producthunt | github | hackernews | youtube | wikipedia | policy | reddit | other
        "object": "Grow a Garden 2",            // 催生新说法的对象
        "term": "grow a garden 2 calculator",   // 冒出的任务说法;只有对象时为 null
        "url": "https://suggestqueries.google.com/complete/search?q=grow%20a%20garden%202%20",  // 实际取回的网址
        "seen_at": "2026-10-14",                // 看到日期
        "rising": 200,                          // 可选:Trends 飙升百分比,飙升词标 "breakout";排优先级用
        "playable_at": "2026-10-20",            // 可选:第一次让大量普通用户用上的日期,可在未来(没到这天只进即将开玩)
        "stage": "closed beta"                  // 可选:阶段,如 closed beta、playtest、Early access、Original
      }
    ]
  }
}
```

### 7.4 登记

```json
{
  "slug": "gag2-calculator",
  "title": "Grow a Garden 2 价格计算器",
  "site_type": "tool",
  "object": {"name": "Grow a Garden 2", "type": "game", "first_public": "2026-10-01", "date_source": "<读日期的网址;公布日写在这里备查>"},
  "terms": [{"term": "grow a garden 2 calculator", "source": "autocomplete", "first_seen": "2026-10-14"}],
  "screen": "证据/gag2-calculator/<速判观察文件名>",
  "reason": "速判六条全过"
}
```

```bash
python3 $S/ledger.py register-quick --input <上面的文件>
```

`first_public` 填第一次让大量普通用户用上的日期（登记后名称、类型、首次公开日都不能改，只有 `date_source` 写错了可以用 `ledger.py update` 更正）（公开测试、抢先体验、正式发售、App 上架中最早的一天，见契约 10.4），公布日、预告日不算；`type` 写 `game`（须在速判日前 0–14 天）或 `other`（0–90 天）。`screen` 指向的速判观察里的 `term` 须是 `terms` 之一（大小写与空格不计）；同一说法不能属于两个方向。

### 7.5 量级观察与简报素材

量级观察用工具生成，不手算：

1. 内置浏览器打开 `https://trends.google.com/trends/explore?hl=en-US`，把 `scripts/trends_fetch.js` 全文加一行 `await xinciTrends({geo: "US", terms: ["<新词>", "<美国锚词>"]})` 交给页面执行；6 国（US、GB、CA、AU、NZ、IE）各一次，两次之间隔几秒，遇到 429 停下。每次执行都要带全文（作用域不保留）。
2. 把各国返回的 JSON 放进下面的输入文件，先只填美国的锚词月量跑一次：脚本会列出"读得出、要查锚词月量"的国家，读不出的自动记 0。
3. 只为列出来的国家去 Semrush 查锚词在该国的月量，补进 `anchors` 再跑一次，观察就写入了。

```json
{
  "series": [ /* trends_fetch.js 的输出,每个查过的国家一份,terms[0] 是新词、terms[1] 是锚词 */ ],
  "anchors": {
    "US": {"volume": 74000, "source": "lexicon", "measured_at": "2026-10-08"},   // 锚词在该国的月量;美国可来自旧词库
    "GB": {"volume": 2400, "source": "semrush", "measured_at": "2026-10-14"}     // 美国以外只能是 semrush
  },
  "skipped": {"IE": "Trends 返回 429,本次没查"}   // 只写没查成的国家与原因;读得出的国家不能放这里按 0 计;6 国每国须恰好出现一次
}
```

查了但 Trends 返回空曲线（`values` 为 `[]`，量太小）的国家照样放进 `series`，脚本按"读不出"记 0，不用放进 `skipped`。

```bash
python3 $S/trends_volume.py --input <上面的文件> --slug gag2-calculator              # 退出码 2:列出要查锚词月量或要换锚词的国家,不写入
python3 $S/trends_volume.py --input <上面的文件> --slug gag2-calculator --semrush-calls 1   # 补齐后写入,打印观察路径
python3 $S/trends_volume.py --input <上面的文件> --slug gag2-calculator --dry-run          # 只打印观察,不写入
```

### 7.6 结算、观察中与建站跟进

```bash
python3 $S/settle.py --slug gag2-calculator --verdict go --reason "首页没人做,基准 1 万" --biggest-unknown "新域名多久能排上去"
python3 $S/settle.py --slug gag2-calculator --verdict watching --reason "量不够但在涨" --biggest-unknown "能否涨到 5 万"
python3 $S/ledger.py watch-check --slug gag2-calculator --ref 证据/gag2-calculator/<新量级观察>   # 复查,给建议
python3 $S/settle.py --slug gag2-calculator --verdict rejected --gate volume --reason "30 天没涨够" --biggest-unknown "无"
python3 $S/ledger.py follow-up --slug gag2-calculator --status started --domain gag2calc.com
python3 $S/ledger.py follow-up --slug gag2-calculator --status launched --date 2026-10-25
python3 $S/ledger.py follow-up --slug gag2-calculator --status abandoned --reason "热度回落"
```

`watch-check` 的建议：最新速判里第一条不过的项 → `rejected:<门>`（AI 概览已答完 → `rejected:answered`）；冲高回落 → `rejected:oneoff`；之后才按量给 `go`、`watching` 或 `rejected:volume`。补挂与复查引用的速判观察，`term` 都须是本方向的说法之一。

`--date` 缺省为今天，须为日历上存在的 YYYY-MM-DD；开建日期不早于判 go 日期，上线日期不早于开建日期。
