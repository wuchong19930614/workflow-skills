# 选词契约（xinci-simple）

本文件是判据的唯一来源；Skill 只串流程。资格结构保持 v2；新注册候选 workflow_version=3，增加核验前进入预检，历史数据兼容规则见 §2。

## 0. 定位与边界

从已有真实搜索量的 US 英文词里，寻找首屏未完成任务、竞争可争取、base 月收入 ≥ $200 的主题簇，交付机会报告。

- 不注册域名、不建站、不写内容。连续运行按轮次预算结束，报告产出不触发提前停机。
- 账本只由 `ledger.py` 写。观察通过 `write_observation.py` 追加；不能覆盖旧观察。观察记现场与判断依据，最终裁决写在 history。
- 零产出如实说零，不凑数。门槛、假设表只由用户变更。
- 与 xinci 新词工作流零运行时依赖，数据区独立。

## 1. 候选、任务组与范围

完整核验前先登记进入预检（§3.1）。核验前用 `ledger.py set-task-plan` 登记 `task_plan`：core_reason 和 groups（id、role=core/support、keywords）。至少一个核心组；主词在逐词表中时必须属于核心组。登记后冻结，可以重复提交相同计划，不能看完结果后改核心组、删组。未列入计划的逐词量不参与本次核验收入。补采更新词量时仍须保留计划中的词。

正式结算须提交计划内每个组的一份观察，组词与计划完全一致。核心组必须通过；支撑组可用 task_group.exclusion_reason 明确剔除，仍须提交该组观察，记录已知结果或未采集的具体原因。剔除组不计收入，但观察同样绑定、报告列明。核心组不能剔除；不能只提交通过组来省略核心失败。

已有 verified 缺绑定任务计划时标待复核，不自动从旧观察推测核心组。

候选是一个主题簇。`cluster.total_volume` 是固定过滤条件下的原始 phrase-match 总量，用于发现和上限预筛；**不是整簇都能取得的流量**。

`cluster.keywords` 保存已实测的逐词量。verify 按真实任务拆组，每组一份观察，`task_group.keywords` 引用该词表中的词，组内与组间均去重。组量为这些词的月量之和；无法归组或未核验的词不进入收入。初次只预览 top 20，值得深查时再补采词表，通过 `ledger.py refresh-cluster` 更新 found/parked，保留旧量级与旧观察。

每组包含代表查询、形态、垂类和 `coverage_reason`：说明组内词为何要求同一种任务、SERP 形态及首屏直答风险。至少核验一个代表查询；差异明显的词另拆组，不用一个长尾查询代表整个大词根。分组存在不确定性时收窄计量，不能把原始总量直接塞入组量。

范围：英文、Google 美区，搜索 URL 带 `gl=us&hl=en&pws=0`。

四条排除，scan 初判、每个任务组 verify 复核：

| 排除 | 判法 |
| --- | --- |
| YMYL | 任务影响健康、金融、法律权利或人身安全。按用途判断；输出线径、断路器、刹车维修等安全相关建议，不能因“只是查表/计算”豁免 |
| 需亲身体验或一手数据 | 写好必须亲自用过、去过、测过。按规格整理与真实体验评价区分，不因有购买意图就自动排除 |
| 纯品牌/导航 | 用户只想去某站，如 login/customer service/单独品牌名 |
| 新闻热点 | 具体事件导致、几周内会消失的短暂尖峰 |

范围明显命中即排除；不能靠改写成工具来规避。

## 2. 状态机与历史兼容

```
found → verified | rejected | parked
parked → verified | rejected
```

- `verified`：全部计入收入的任务组有完整合规证据，重算 base ≥ $200，且 md/html 报告已生成。
- `rejected`：确定硬门否决或收入不足。
- `parked`：季节性不适合或证据不足。未取得证据不等于通过；超 90 天看板提醒，不自动转移。

普通 transition 不开放终态边。维护入口保持原四态：

- `set-task-plan`：非终态的核验前任务清单登记，冻结核心/支撑角色与覆盖词。
- `refresh-cluster`：只补采 found/parked 的词表，不改变状态。
- `requalify`：仅因收入/范围判据被拒的候选，在用户批准相关判据变更后重新申请 verified；要求 `--change-basis`，重新检查全部任务组。G1/G2/G3 或未知拒因不能因收入门槛变更翻案。
- `invalidate`：审计撤销既有 verified；缺证据 → parked，范围命中 → rejected。必须追加说明依据的审计观察，旧报告归档到 `报告/历史/`，不篡改原 history。

新注册候选 workflow_version=3，进入预检必须 ready 才能冻结任务组和完整结算；预检摘要绑定到资格。旧候选不补造过去的预检，仍按原 v2 证据读取；缺进入预检时投入建议为“需要补证据”。

历史 verified 缺 v2 绑定时，看板标记待复核、validator 报错、拒绝重建正式报告。旧 rejected/found/parked 保持可读，不要求补写不存在的历史现场。

## 3. 发现与准入

来源由 `run_log.py --plan` 的 next_source/source_reason 建议；用户指定优先，已 started/blocked 的阶段保持原来源和种子。样本不足默认 Keyword Magic 词根 → 小站反推 → 论坛问题。跨轮词根游标取结构化运行清单，词根表在 `数据采集.md §2.3`。发现反馈口径见 §3.2。

| 来源 | 操作 |
| --- | --- |
| root | 一个词根一次查询，从修饰词找具体任务家族 |
| small_site | 默认 AS < 30 且月自然流量 > 50K 的站，Top Organic Keywords 提炼主题，再回 Keyword Magic 验量 |
| forum | 实读反复提问的帖子，提炼搜索措辞，再回 Keyword Magic 验量 |

固定过滤：US、phrase、KD ≤ 49、排除 Navigational、排除成人。记录过滤后的 total volume，不能用未过滤的另一面板总量替代。

准入：原始簇量 ≥ 50,000 **或** 主词月量 ≥ 5,000，并且四条范围排除未命中。主词量来自逐词记录。注册前查账本避免同簇重复；脚本拒绝重复 slug/规范化主词，语义同簇仍由执行者判断。

先取预览、做排除和准入，再为可进入 shortlist 的候选补代理指标；不为明显排除项查询 Authority Score。一次发现以补足下一批 5 个待核验候选为目标。found 已有 ≥ 5 个时，连续运行跳过 scan 并记 skipped。

### 3.1 进入优势预检

范围和收入上限初筛后、冻结任务组前，用 `ledger.py set-entry-plan` 登记 user_gap（用户卡点）、solution（最小解决方案）、advantage（相对现有做法的具体优势）、delivery_basis（技术/数据获取与维护依据）、biggest_unknown，并引用已追加的观察。这里形成待核验的进入假设，不代替正式 G1–G3；不能用“体验更好”“SEO 做好”代替具体差异。

status=ready 表示方案和交付依据足以继续研究，不表示市场验证通过；unknown 表示关键条件未确认；infeasible 表示已有依据显示当前方案不可交付。后两者先补证据或追加 verify 观察后 parked，不伪造范围/竞争拒因。早期范围或收入预筛否决无需补预检。

任务组冻结前可追加新版预检，history 保留旧版本；相同输入可重试。任务组冻结后不得改写进入方案。观察文件的 SHA 固定，正式资格另绑定预检摘要。旧裁决缺此材料不自动生成有利建议。

### 3.2 发现反馈与去重

`discovery_feedback.py` 从账本与运行清单只读计算来源、种子方向、拒因和 duplicate_index。注册前比较主词、逐词表和用户任务；同簇已经 rejected 时先读原拒因，不为换个词根重复收费。脚本提供匹配材料，语义同簇仍由执行者判断。

学习样本只计已完成结构化 scan 引用、来源一致且当前裁决可重新校验的候选；同 slug 多次触及只计一次。旧记录显示在总量和去重索引中，不把自由文本拒因猜成结构化闸门；有完整证据的历史裁决才能进入学习样本。损坏报告或绑定不计成功。

至少两个来源各有 ≥2 次实际完成 scan、≥3 个可校验终态候选时，按 `(通过数+1)/(终态数+2)/(1+scan调用数/完成scan数)` 优先；这是调度启发式，不是成功概率。每第4次实际发现选择最久未扫描的来源用于探索。skipped 不推进计数；来源不足以比较时保持轮换。种子方向 ≥3 个可校验拒绝且零通过，标 lower_priority，默认选同来源其他任务家族；有新证据或用户指定仍可重查并写明原因。

来源成本仅含结构化 scan 新增调用；verify 可能混合来源，单独披露未归因调用，不摊成每个候选成本。started/blocked 计费纳入总成本，未完成 scan 不算一次完成。建议只改变新阶段的发现顺序，不改研究闸门、现有预算或恢复位置。

`discovery_feedback.py --replay` 比较已登记样本在现行准入与仅按量排序方案下的覆盖。既有账本缺少被筛掉的小量样本，不能从零新增推断没有漏选；真实获客/收入反馈不足时保留当前搜索量门槛和假设表，不用模型输出自证模型。

## 4. 排序

`rank.py` 对 found 按 KD（反向）、原始簇量、低 AS 数、UGC 数、可见内容年龄五项等权排序。池内 min-max，缺失与全相等取 0.5。只排序，不否决。

verify 使用重新计算的排序，不能沿用旧池的分数。

## 5. 现场核验（每个计入收入的任务组）

预检：内置浏览器、美区参数、桌面、未登录。失败则不判 G1–G3，候选留原状态；重试一次仍失败记 blocker。若正常环境下某候选的证据拿不到，记 parked。

首页指前 10 条自然结果，不含广告/PAA/视频轮播/购物模块。首页只有少于 10 条时须写 `natural_results_exhausted=true` 和读尽依据；不能读三条就算读满。继续第二页，记录 `page2_note`。

### G1 首屏直答

AIO、精选摘要或原生组件已完成该任务，用户不必点结果 → rejected。

AIO 存在未完成 → 通过该项，CTR ×0.6。AIO 不存在不等于没有其他直答；三种形式均须记录。异步等待与容器自检见采集规程。

### G2 首页结构

维基级/大媒体、非视频任务中的视频结果、品牌首页霸榜 → rejected。记录实际条数、页面类型和结构理由；不能只凭域名名气否决。

### G3 完整任务占位

K = 同时满足 `completes_task=true`、Semrush AS（字段沿用 `dr`）≥50、`fresh=true`、`format_match=true` 的自然结果数。

- K ≥3 → rejected。
- K=1–2 → 通过该项，CTR ×0.7。
- K=0 → 不折减。

新鲜：可见日期在 24 个月内，或无日期但内容与当前事实一致。格式正确：要表给表、要工具给工具。AS 要有实测来源并按当前域名/URL 匹配，不能凭品牌名猜数，也不能把旧 SERP 的第 N 行硬套到新第 N 行。

可能构成强对手的结果缺 AS/新鲜度/格式时，不能计作零；补采后再判，仍不足则 parked。低 AS 或明确未完成任务的结果可排除为强对手，无需为其补无决策价值的数据。共享实现为 `qualification.strong_results`。

### 季节性与范围

Trends：US、past 12 months。集中 ≤3 个月且无意做季节站 → parked。v2 当前只自动通过 `trends.status=nonseasonal`；有意做季节站也先 parked，另行请求明确的适用口径。

未读到曲线 → `unknown` → parked；近几个月有排名、面板没有季节性提示都不能证明全年平稳。

四项范围复核必须明确为 false，并给 `scope_evidence`；任何 true → rejected，缺项不能当 false。

## 6. 收入模型与提前结束

假设版本 **2026-09-09.2**，门槛 **$200**。变更假设须经用户批准并更新版本；任务组求和口径由资格结构 v2 标识。

| 形态 | base 公式 |
| --- | --- |
| info / lookup | 组量 × CTR 0.07 ÷1000 × RPM |
| tool | 组量 × CTR 0.10 ÷1000 × RPM |
| commercial | 组量 × CTR 0.07 ×外链点击 0.15 ×转化 0.03 ×佣金 $30 |
| mixed（组内仍混合） | info 与 commercial 取小值 |

RPM：tech $10、home $18、hobby $12。每组按自己的形态/垂类计算，再按现场叠加 AIO ×0.6、K=1–2 ×0.7。downside/upside 仅将 CTR 乘 0.5/1.5。

**多组聚合**：各组分别计算后收入相加。顶层 form 在各组形态不同时标 mixed，这不表示再次对整簇取小值。组量是逐词去重合计；未核验量不参与。`volume_needed_for_threshold` 向上取整，多组情况下表示维持当前组量比例和假设时的所需量。

### 6.1 收入上限预筛

在完整 SERP 前可用 `revenue_model.py --upper-bound` 按**原始总量**、所有合理形态/垂类、完全无折减算当前模型内上限。未知形态/垂类默认覆盖所有选项；缩小选项须在观察写依据，不能为了拒绝而选低收入形态。

上限仍 < $200 → rejected，gate=`revenue_prescreen`，保存脚本原输出和依据；无需伪造浏览器预检或现场结果。上限 ≥门槛只表示值得继续，不是通过。这个上限只针对当前模型，不是现实收益上限。

### 6.2 拒绝也须有充分依据

`transition --to rejected` 根据 gate 复核最小证据：G1 要有合规环境及首屏完成任务的明确观察；G2 要读满首页/第二页并有 blocked=true 的结构依据；G3 要读满并确认至少三个强对手；scope 要有命中项与 scope_evidence；revenue 须对完整计划重算且低于门槛；预筛按 §6.1。

不要求早期拒绝项补齐无关后续门。任务计划存在时，支撑组 G1/G2/G3 失败不能直接拒绝整个候选，须交代全部组再结算；核心组可以提前否决。历史 rejected 仍可读，不补造过去证据。

### 6.3 正式通过

日常用 `settle_candidate.py --slug ... --evidence ... --by ... --reason ...`：无 gate 时核验完整计划、重算收入后通过或按收入拒绝，随后生成报告并校验；早期拒绝传 --gate，明确缺证据传 --park。报告阶段失败后用相同命令恢复；不会重复写状态历史。底层提交也必须独立重算；任何数值、形态、版本、输入不一致均拒收。命令见《命令与观察》§6。

$30 佣金并非适用于所有商品；RPM 也不是实测收入。报告明确这些假设，不根据 CPC 自行换算 RPM。需要调整假设时向用户提交证据。

## 7. 证据与运行记录

观察字段见 `数据结构/observation.schema.json`；调用示例见 `命令与观察.md`。每组一份 verify，`task_group` 明确代表词与覆盖词。早期硬否决/证据不足/收入预筛允许部分观察；verified 必须完整。

通过时固定任务计划、剔除组清单，并将本次全部 verify（含剔除组）与 scan 的路径、SHA-256 固定到 `qualification.bindings`。报告只能用这些文件；新增文件不自动替代。旧文件内容改变则校验失败。

每阶段 started/completed/blocked/skipped 用 `run_log.py` 追加结构化清单：run_id、round、max_rounds、source_kind、seed_value、outcome、next_step。计费数是**本条新增调用数**，不能在 started 与 completed 重复累计。发现跳过不算来源已扫描。

`run_log.py --plan` 先汇总全部 run_id：一个未完运行就恢复，多个则返回 conflict 与列表，显式指定 --run-id 后继续；未完运行存在时不允许创建新 ID。返回的 action 与写入允许的阶段共用推导逻辑。found≥5 时仍返回 action=scan、scan_outcome=skipped，先记录跳过，再核验。`run_log.py --finish --run-id ...` 从最新 started/blocked 清单推导轮次、预算、来源与下一步；已完成阶段拒绝重复结束，避免重复计费。历史自由文本清单不猜测为结构化进度，首次切换可人工核对其记录；不要重复计入新轮。

## 8. 报告与完成条件

报告仅由脚本生成：`报告/<slug>.md` 与 `.html`。事实来源是账本与绑定观察，md 是 html 的唯一输入；两份都不手改。修改样式可重出 html；修改事实必须重新核验，不能改 md 绕过。

开篇回答：有人搜吗、首屏是否完成、竞争是否可争取、模型收入、风险。每节第一句直白，并保留“本次”“已核验范围”“模型估算”的边界，不写排名保证。

九节数据与现场要点默认折叠。显示原始量、已核验量、未计入量、逐组收入。play 按已核验量 <150,000 为 single_domain，否则 cluster_expansion，仅供报告解读，不是建站方案。

verified 缺 md/html、html 源 SHA 不符、绑定证据变动、收入重算不符均报错。transition 后生成中断时，恢复先补报告并校验，不能把半成品汇报为本轮完成。

## 9. 停机与错误

连续运行按预算；零候选是该轮结果，记录实际搜索范围，继续下一来源。轮次必须包含实际发现或消化待核验，不能用空动作凑预算。

Semrush 登录失效/验证码/额度提示，或浏览器预检重试仍失败 → blocker，追加日志停下，不绕、不猜。其他脚本拒收先修输入或补证据，不放宽判据。

## 10. 投入判断与现实反馈

研究四态和 $200 月收入门槛只裁决选词资格，不代表已批准投资。新报告在折叠证据前显示投入与最小验证；没有基线就明确“未估算、回本期未知”，不能把成本缺失当零，也不能把研究通过称为商业验证通过。有依据时完成投入计划；缺少试验预算或关键条件时如实列缺口，研究轮次仍可完成，不虚构参数凑齐。

### 10.1 投入建议与变现依据

`verified` 只表示研究通过。`investment.py recommend` 根据当前研究与冻结投入基线只读派生原始投入建议，不增加研究状态，不自动执行试验：

- `needs_evidence`（需要补证据）：缺进入预检/投入基线/适用变现渠道，成本或爬坡未知，或者原基线对应旧裁决。
- `defer`（暂不值得投入）：研究已拒绝、当前方案不可交付、渠道不可用，或所选预测期末 base 扣现金或工时成本后不为正。已知不利条件优先于缺证据。
- `pilot`（值得小规模试做）：研究通过、进入方案 ready、所用变现渠道有依据，成本与爬坡明确，所选预测期末 base 的现金和含时间结余均为正；按最小验证计划验证最大未知。

预测期来自已登记爬坡序列，建议仅适用于该期限；不自动延长期限凑回本。downside/base/upside 的回本与期末结余同时披露，downside 只代表既有 CTR 减半情景，不冒充统计置信区间或现实最坏情形。$200 是收入门槛，不是净利润门槛。

新投入计划填写 monetization：status=supported/unknown/unavailable、channel=ads/affiliate/both、basis、key_assumption、validation_step、source_urls；supported 另须 checked_at 日期与来源。广告依据说明主题与渠道适用条件；联盟依据须具体计划/商品及佣金适用性。多组模型涉及两条收入渠道时必须覆盖两者；固定 RPM/$30 佣金仍为统一初筛假设，不因渠道可用就称其实测。

旧投入计划缺 monetization 仍可读，建议为需要补证据；原预测不覆盖。原始投入建议在报告中展示，实际试验开始后以 review 的指标、预算、时限与反馈进行人工决策，不据原建议自动重复试做或扩张。

### 10.2 冻结投入基线

完成研究裁决的 verified（或用户指定的 rejected 近失候选）可登记一次 `investment`。记录最小产品、相对现有结果的具体优势及证据、交付/数据维护可行性、最大未知；区分已证实依据与待测假设。初始现金、开发/数据/内容小时、每月持续现金与小时、内部时薪逐项填写；现金成本依据须涵盖域名/托管/API/获客，持续时间须涵盖维护/更新/推广，明确各项已含、为零或未估。金额统一 USD，其他币种先注明换算依据；未知数为 null + unknowns 原因。

逐月填写稳态收入的实现比例（0–1），明确起量滞后依据，不能默认第一个月满额。这是进度假设，不是成功概率；三种收入情景使用同一爬坡序列，不虚构加权成功率。月 1 开始计持续成本；现金回本按累计收入减初始及持续现金，经济回本再减初始及持续工时 × 时薪。输出首次回本月、期末结余，并区分“预测期内未回本”和“未知”。首次回本不保证后续盈利。当前模型采用固定月成本、最长 60 个月；不适用时先注明限制，不能用它掩盖显著的变动成本。

基线保留原研究状态、收入、资格和裁决历史快照，绑定摘要；相同输入可恢复，不同输入不可覆盖。`estimate` 可用不同成本/时薪只读比较；新假设先写反馈建议，原预测永久保留。既有 rejected 不因登记计划、收集反馈而翻案；没有收入模型时回本期为未知。

### 10.3 最小验证

只选当前最大未知对应的一种试验：技术可行性、真实用户任务完成、自然搜索获客、变现。预登记假设、样本定义、成功判据、最小样本与成功数、成功比例、观察天数、现金/小时上限、停止与延期条件。样本量和阈值是预先约定的决策线，不是统计显著性保证。对应指标见 `investment.py`；例如可用性 completions/attempts，不能拿它证明 SEO。

计划登记不执行开发、部署、投放或招募，实际行动依已有明确授权开展；不存在授权时停在可审阅的计划。到期或触及预算须复核，样本不足不是验证失败，不允许无限延期消耗资源。出现明确不可交付、损失风险等 stop_rule 条件时可在样本达标前停止；脚本只汇报数值信号，人工判读非数值条件。

### 10.4 追加实际反馈与校准

每候选 `反馈/<slug>.json` 只追加累计快照，不把多次快照相加。日期统一为 UTC 日历日，started_on 不早于基线登记日；同一起点、as_of 严格递增，现金投入/投入小时/已收收入/样本/成功数按同一范围累计。实际现金与工时须涵盖该最小产品自起点起全部投入，不能只报最后一次试验；未知必须 null + 原因，不能写零。已有 id 相同内容可重试，不同内容拒绝覆盖；历史数据修正先保存修正证据并人工审计，当前接口不提供回写。

保存采集渠道、已发生风险、学到的事实、下一步建议及校准建议，并绑定候选证据目录中原始导出/任务日志/收入凭证的 SHA-256。指标必须符合已冻结的样本口径；脚本核对形状、累计关系和文件摘要，不替代对原始数据与口径真实性的核对。直接招募的用户不能算自然流量；未获客不等于产品无用，任务完成不等于能赚钱。

`review` 同屏保留原预测和实际，并分别显示样本信号、预算上限、时间到期、实际现金及含时间结余。规划月按 30 天展示已完成月，未满月不外推月收入；不等长期间不直接算预测误差。反馈既不改变四态，也不自动更新 CTR/RPM/佣金/闸门。积累多候选、足够观察期及同口径证据后，提出具体参数校准供用户决定；不要只总结存活者，也可对用户指定的近失项收集反证，范围排除仍有效。当前版本追踪一个原始试验，换指标或新增试验须另行制定版本方案，不能冒充原试验连续样本。
