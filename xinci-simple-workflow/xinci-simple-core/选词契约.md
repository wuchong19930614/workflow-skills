# 选词契约（xinci-simple）

本文件是 xinci-simple-workflow 全部判据的唯一来源。三个 SKILL.md 只串流程，判断标准一律指向这里。数值（阈值、假设表）与 `scripts/revenue_model.py`、`scripts/build_report.py` 的常量逐字一致；改数值先改这里，再改脚本，再改 SKILL.md 命令模板。

## 0. 一句话与三条硬规则

**定位**：从已有真实搜索量的英文词里，找出 SERP 守得弱、AI Overview 吃不掉、base case 月收入 ≥ $200 的主题簇，产出一份机会报告。建站方式不预设，报告就是交付物。

硬规则：

1. 不注册域名、不建站、不写内容。找到词就停，建站是用户的动作。
2. 账本只能由 `scripts/ledger.py` 写；观察文件只记看到了什么，不写裁决；手工编辑一律禁止。
3. 产出为零如实说零。不凑数、不留 maybe 清单、不为了出报告放宽任何一条判据。

与 xinci 新词工作流零运行时依赖：不引用它的脚本与契约，数据区独立。

## 1. 候选单位与范围

**候选是主题簇**：一个主关键词 + 一组支撑词。一个站要靶一簇；量级、竞争、收入都按簇算。

**范围**：英文 + Google 美区（`gl=us&hl=en&pws=0`）。

**四条零成本排除**（scan 判一次，verify 复核一次；命中任一条直接不注册或 `rejected`）：

| 排除 | 判法一句话 |
| --- | --- |
| YMYL | 题目影响健康、金融、法律权利或人身安全。按类别定义判，不按例子清单；"补剂剂量""贷款利率""签证要求""刹车片更换"都算 |
| 需亲身体验或一手数据 | 写好这页必须自己用过、去过、测过（产品实测、旅行体验、个人测评）；AI 或案头研究写不出可信内容 |
| 纯品牌词与导航词 | `X login` / `X customer service` / `X near me` / 单独品牌名；搜索者要去某个站，不是要一个答案 |
| 新闻热点 | 由具体事件驱动、几周内会消失的词；看 Trends 曲线是尖峰而非平台 |

## 2. 状态机

```
found ──现场核验 + 收入模型通过──→ verified（报告已出，终点）
  ├──任一硬门否决 / 收入不足──→ rejected（终点）
  └──季节性 / 证据不足──→ parked ──→ verified | rejected
```

```python
LEGAL = {("found", "verified"), ("found", "rejected"), ("found", "parked"),
         ("parked", "verified"), ("parked", "rejected")}
TERMINAL = {"verified", "rejected"}
```

没有 tracking、形成期、qualified、decide 分层。`parked` 停留超 90 天由看板提醒，不自动转移。

## 3. 第一层：发现与准入（xinci-simple-scan）

### 3.1 三条来源轮换

| 来源 | 怎么取 | 记什么 |
| --- | --- | --- |
| (a) Keyword Magic 词根轮换 | 一次一个词根输入 Keyword Magic（词根表见 `数据采集.md §2.3`）；不合并词根 | 词根名、预览行数、簇量、top 20 支撑词 |
| (b) 小站反推 | Domain Overview 找 Authority Score < 30 且月自然流量 > 50K 的站；拉其 Top Organic Keywords；每个主题按 phrase-match 回 Keyword Magic 验簇量 | 小站域名、AS、流量、取出的主题 |
| (c) 论坛反复问的问题 | Reddit / 专业论坛里被反复问且靠人肉回答的问题；提炼成搜索措辞后回 Keyword Magic 验量 | 帖子 URL、提炼的措辞、簇量 |

轮换顺序默认 (a) → (b) → (c) → (a)…，以运行清单里上次用的为准；用户指定则用指定的。词根按表顺序不重复本轮已跑的。

### 3.2 Keyword Magic 固定过滤

```
Database   United States
KD         ≤ 49
Intent     排除 Navigational
Content    排除成人词
Match      phrase
```

预览优先，一次看 ≤ 50 行；CSV 只在预览已证明簇值得深看时导。

### 3.3 准入（零成本）

同时满足才注册为 `found`：

- 簇量（phrase-match 合计月量）**≥ 50,000**，或主词月量 **≥ 5,000**；
- 四条范围排除全部不命中。

阈值是可调默认值。改阈值同时改本节与 `xinci-simple-scan/SKILL.md` 的命令模板。

### 3.4 注册时必记的代理字段

`proxy.kd`（主词 KD）、`proxy.low_dr_count`（首页 DR < 30 的域名数，来自 Keyword Overview 的 SERP overview 面板）、`proxy.ugc_count`（首页 reddit / quora / 论坛条数）、`proxy.content_age_median_days`（首页可见日期的中位数，取不到记 null）。这些只服务第二层排序与第三层 G3，不能单独否决。

## 4. 第二层：代理排序（`scripts/rank.py`）

对全部 `found` 算 `rank_score`，决定谁先进现场核验：

- 五项：KD（反向）、簇量、`low_dr_count`、`ugc_count`、`content_age_median_days`；
- 每项在当前 `found` 池内 min-max 归一化到 0–1，缺失取 0.5，等权平均；
- 池内只有一个候选或某项全相等时该项取 0.5。

**代理不能单独否决任何候选。**权重等权是初始口径，首批 verify 后按"排序分与实际通过率的相关性"调。

## 5. 第三层：现场核验（xinci-simple-verify）

环境：内置浏览器面板、美区、桌面、未登录，四项预检写进每份 verify 观察（见 `数据采集.md §4`）。任一不合规 → 本次不写 G1–G3 结论，只在 `points` 记原因，候选留 `found`。

五个定义，全节通用：

- **首页**：Google 第一页前 10 条自然结果，不含广告、People also ask、视频轮播、购物模块。
- **DR**：Semrush Authority Score。
- **完整完成任务**：用户看完这条不必再点别处。
- **新鲜**：页面可见日期在 24 个月内，或无日期但内容与当前事实一致。
- **格式对**：结果形态与查询要的形态一致（要表给表、要工具给工具、要步骤给步骤）。

### 5.1 G1 Google 直答（硬否决）

AI Overview、精选摘要、原生小组件（计算器、换算、天气、日期）在首屏把任务做完 → `rejected`，reason 写"G1 直答：首屏用什么把任务做完了"。判"做完"看用户还要不要点任何结果。

AI Overview 存在但任务未做完 → 通过；收入模型 CTR × 0.6，观察 `ai_overview.completes_task=false` 并记 `excerpt`。

### 5.2 G2 首页结构

读满第一页，继续第二页到明显质量断层。**不得只看前三条。**

否决（`rejected`，reason 写"G2 + 看到的结构"）：维基级/大媒体霸榜；视频霸屏而任务不是视频任务；品牌首页而非内页霸榜。

通过：相当比例是内页、小站、论坛、明显老化内容。

### 5.3 G3 可打败性

首页 10 条中，"完整完成任务 **且** DR ≥ 50 **且** 新鲜格式对"三项同时满足的结果数 = K：

| K | 结论 |
| --- | --- |
| ≥ 3 | `rejected`，reason 写"G3 强占位 K 个：域名列表" |
| 1–2 | 通过；收入模型 CTR × 0.7；报告记风险 |
| 0 | 空位；通过，无折减 |

按结果"做什么"分类，不按"是谁"：大品牌的信息页不算完成任务，小站的可用工具算。

### 5.4 季节性

Google Trends、US、past 12 months。量集中在 ≤ 3 个月且无意做季节站 → `parked`，reason 写月份分布。平稳或多峰 → 通过，观察 `trends_12m` 一句话。

### 5.5 范围排除复核

§1 四条再看一遍，写进 `scope_recheck`；命中 → `rejected`。

### 5.6 形态判定

按 SERP 结果类型与查询意图判一个 `form`：

| form | 含义 |
| --- | --- |
| `info` | 答案是解释、清单、步骤 |
| `lookup` | 答案是一个数字或判断，需逐对象查表 |
| `tool` | 任务要算、转、生成，首页有或应有工具 |
| `commercial` | 带购买意图（best / review / vs / for sale） |
| `mixed` | 两种以上并存 |

## 6. 第四层：收入模型（`scripts/revenue_model.py`）

**假设表版本 `assumptions_version = 2026-09-09.2`。**改任何假设先改版本号，再改脚本 `VERSION`。

### 6.0 变更记录

| 版本 | 日期 | 改了什么 | 依据 |
| --- | --- | --- | --- |
| `2026-09-09` | 2026-09-09 | 初版，门槛 $500 | 用户设计阶段拍板 |
| `2026-09-09.2` | 2026-09-09 | **门槛 $500 → $200**；`volume_needed_for_500` 字段改名 `volume_needed_for_threshold` 并新增 `threshold` 字段 | 首跑 2 轮 6 个候选实测（清单 `运行/2026-09-09-*-r1-1020/r2.json`）：量级够的格被大厂或 Google 自己占满（`unit converter` 撞原生小组件、`pdf/video/image converter` 撞 Adobe/Canva/CloudConvert），没被占满的格量级只有三分之一（`wire size` 310,300、主词 KD 29）。$500 隐含的 66 万簇量在实测里只存在于已被占满的格。用户 2026-09-09 拍板降为 $200 |

门槛与假设表只能由用户变更；执行者在运行中发现门槛不合现实时，只提交实测证据与提案，不自行改（见 §0 硬规则 3 与 xinci-simple-run 的硬规则）。

### 6.1 base 公式

| form | 路径 | base 月收入 |
| --- | --- | --- |
| `info` / `lookup` | 展示广告 | 簇量 × CTR **0.07** ÷ 1000 × RPM |
| `tool` | 展示广告 | 簇量 × CTR **0.10** ÷ 1000 × RPM |
| `commercial` | 联盟佣金 | 簇量 × CTR **0.07** × 外链点击 **0.15** × 转化 **0.03** × 佣金 **$30** |
| `mixed` | 两条各算 | 取 info 与 commercial 中小者 |

RPM 按垂类：`tech`（科技/通用）**$10**、`home`（家居/DIY/汽车）**$18**、`hobby`（爱好/宠物）**$12**。默认 `tech`。

### 6.2 折减（乘在 CTR 上）

- AI Overview 存在但未做完 → × **0.6**
- G3 的 K = 1 或 2 → × **0.7**（K ≥ 3 已被 G3 否决，不进模型）
- 季节性判 `parked` 的不算收入

### 6.3 三情景

downside = CTR × **0.5**，upside = CTR × **1.5**，其余不变。只动 CTR 一个变量。

### 6.4 门槛与出口

- `base ≥ 200` → `transition --to verified --form <form> --revenue-json <模型输出>`，随后 `build_report.py`；
- `base < 200` → `rejected`，reason 写"收入不足：base $X，差 $Y"。

脚本同时输出 `volume_needed_for_threshold`（到门槛所需簇量）与 `threshold`（当次生效门槛，写进账本备查）。`ledger.py` 校验 `revenue.threshold` 必须等于当前生效门槛，防止改小 threshold 绕过。

**判据变更后的受控翻案**：门槛、假设表或范围排除经用户拍板变更后，原先死于该判据的 `rejected` 候选可用 `ledger.py requalify` 翻为 `verified`（普通 `transition` 不开这条边）。要求：当前态必须是 `rejected`、`reason` 写明变更依据、按新门槛重校 `base`。死于竞争门（G1/G2/G3）的候选不因门槛变更而翻案——那与收入无关。

### 6.5 门槛隐含的量级（供解读，不是判据）

无折减情形下 $200 所需簇量（脚本实算）：

| 形态 + 垂类 | 需簇量 |
| --- | --- |
| `info` / `lookup` + `tech`（RPM $10） | 285,714 |
| `info` / `lookup` + `home`（RPM $18） | 158,730 |
| `info` / `lookup` + `hobby`（RPM $12） | 238,095 |
| `tool` + `tech` | 200,000 |
| `tool` + `home` | 111,111 |
| `commercial`（联盟） | 21,164 |

带双折减（AIO ×0.6、强占位 ×0.7）时上表除以 0.42，例如 `tool` + `home` 变为 264,550。

两条读法上的提醒：`commercial` 形态的门槛比 `tool` 低约一个数量级，但它的 $30 佣金假设只适用中等客单价商品——线材一卷 $50–200、3% 佣金只有 $1.5–6，用它算联盟收入会高估。另外 `commercial` 词多半带购买意图，容易撞 §1 的"需亲身体验"排除；缝隙是"规格驱动的购买"（如 `generator for 2000 sq ft house`），有购买意图又不需实测。

## 7. 证据要求

观察文件 `证据/<slug>/<YYYY-MM-DD>-<scan|verify>.json`，字段见 `数据结构/observation.schema.json`。**只记看到了什么，不写裁决**；裁决在账本 `history[].reason`。

| 动作 | 必带 |
| --- | --- |
| `register` | scan 观察，含 `semrush_preview`（查询日期、过滤条件、要点）与 `source_urls`；`--reason` 写准入依据 |
| `→ rejected` | verify 观察；reason 写"哪道门 + 现场看到什么"或"收入不足：base $X，差 $Y" |
| `→ parked` | verify 观察；reason 写季节性读数或缺什么证据 |
| `→ verified` | verify 观察含 `browser_preflight` / `ai_overview` / `serp_top10` / `scope_recheck` / `trends_12m`；`--form`；`--revenue-json` 为 `revenue_model.py` 输出去掉 `passes` |

每次 scan / verify 结束用 `scripts/run_log.py` 写运行清单；Semrush 计费查询数如实计入 `billable_calls`。

## 8. 机会报告（`scripts/build_report.py` + `scripts/build_report_html.py`）

只为 `verified` 生成，**md + html 双格式同批产出**：

- `报告/<slug>.md` 是**唯一事实来源**，给 AI 与审计读；
- `报告/<slug>.html` 由 `build_report_html.py` 从 md **单向生成**，单文件内联样式、双击即开，给人读。html 内嵌源 md 的 SHA-256（`<meta name="xinci-simple-source-sha256">`）。

**html 永不手写、永不手改**——改了 md 就重跑 `build_report_html.py`。`validate_ledger.py` 对 `verified` 候选强制：md 在而 html 不在是**错误**；html 内的源 SHA 与当前 md 不一致也是**错误**（说明 md 改过而 html 没重生成）。这套规矩与 xinci-workflow 的决策书一致，但两边各存一份脚本、互不 import。

### 8.1 结构

开篇是 **「为什么是这个词」**（`scripts/narrative.py` 生成），用人话回答四问加风险：有人在搜吗 / Google 会不会自己答完 / 打得过吗 / 能赚多少 / 最大的风险。之后才是九节数据：主关键词与簇 / 形态与意图 / 量级证据 / 竞争现场 / AI Overview 状态 / 季节性 / 收入三情景 / 范围排除复核 / 建议 play 与风险；末尾「附：现场要点」是采集与判定的原始记录。

**html 的排版目标是「打开就是一页人话」**：单栏窄版、无侧边目录，九节数据与现场要点都折进 `<details>`，要反查再点开；打开即见的正文控制在千余字。md 保持平铺——它是给 AI 与审计读的。

### 8.2 叙述节的纪律

**每个小节的第一句必须是加粗的大白话结论**（有／没有、会／不会、打得过／难打、多少钱），之后才是两三句支撑，每节不超过四段。只有分析逻辑、没有明确答案的写法不合格——这是 2026-09-09 用户明确指出的问题：报告读完得知道答案是「能」还是「不能」，不能似是而非。

结论句按数据区间选措辞，例如：簇量 ≥ 20 万说「量很足」、< 10 万说「量偏小」；无 AIO 说「连 AI 摘要都没有」、AIO 未答完说「只给了通用口径」；硬对手 ≥ 3 个说「难打」、0 个说「没有一个权重高又真把事办完的对手」、1–2 个且有低权重站占前排则点名那个小站。

`narrative.py` 的每句话都**从结构化字段派生**：

- 不接受执行者手写的自由文本进叙述节——同一份数据永远产出同一段话，读者能反查每个数字；
- **不把观察 `points` 与 `ai_overview.excerpt` 的原文倒进叙述节**。那些是机器化的采集记录，叙述节只讲判断并指向原文所在的节次。这是本节存在的理由：数据不解释自己，叙述必须由脚本从数据里算出来，而不是把观察记录堆给读者。

play 分界：簇量 **< 150,000** → `single_domain`（一站一簇）；**≥ 150,000** → `cluster_expansion`（大簇分阶段）。

不含页面地图、内容大纲、域名建议——建站方式未定。

## 9. 错误处理

- 浏览器预检任一不合规 → 不写 G1–G3，候选留 `found`，如实报告。
- Semrush 登录失效 / 验证码 / 额度提示 → 停下如实报告，不绕、不猜数。
- `ledger.py` 拒收：非法转移、证据文件不存在、`reason` 为空、`verified` 缺 `form`/`revenue`、`base` 低于当前门槛、或 `revenue.threshold` 与当前门槛不一致；`requalify` 的当前态不是 `rejected`。
- `revenue_model.py` 拒收：`form` 不在词汇表、簇量非正、`niche` 不在表内、`strong_complete_count ≥ 3`。
- `build_report.py` 拒收：非 `verified`、缺 scan/verify 观察、缺 `form`/`revenue`。
- `build_report_html.py` 拒收：路径不是可读的 `.md` 文件（退出码 2）。
- `parked` 超 90 天 → `report_status.py` 提醒，不自动转移。
