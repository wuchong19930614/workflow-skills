# 命令与观察

以下命令从仓库根执行；`<...>` 均替换为实际值。JSON 写到临时文件再传路径，避免把长 JSON 拼进 shell。判据与数值只看选词契约。

## 1. 数据区与恢复

```bash
python3 xinci-simple-workflow/xinci-simple-core/scripts/report_status.py
python3 xinci-simple-workflow/xinci-simple-core/scripts/run_log.py --plan
```

数据区确实未配置才询问用户，再用 `init_workspace.py --data-root <用户路径>`。已有 resume 时沿用 ID、轮号与预算。

## 2. 观察

公共字段：slug、带时区 observed_at、stage（scan/verify）、source_urls、points。scan 另含 semrush_preview（queried_at/filters/note）。写文件时使用真实观察时间，不用模板时间。

一份可计入收入的 verify 另外必须包含：

| 字段 | 内容 |
| --- | --- |
| schema_version | 2 |
| task_group | id、keywords（引用 cluster.keywords 中的词）、representative_keyword、form、niche、coverage_reason |
| browser_preflight | controllable/desktop/logged_out=true，region=us，evidence |
| query_url | 与代表词匹配的 Google URL，带美区三参 |
| ai_overview | present、completes_task、excerpt；无 AIO 也记录等待重读的依据 |
| direct_answer | featured_snippet_completes_task、native_widget_completes_task、evidence |
| serp_structure | blocked、evidence；描述首页条数与类型 |
| serp_top10 | 每条 pos、domain、url、type、completes_task、dr（Semrush AS）、fresh、format_match；AS 来源与新鲜/格式依据写 points |
| page2_note | 第二页读数；首页不足10条另记 natural_results_exhausted 与 exhaustion_evidence |
| trends | status=nonseasonal/seasonal/unknown，evidence、source_url |
| scope_recheck | ymyl/firsthand/brand_nav/news 四个布尔值 |
| scope_evidence | 按实际用途复核范围的依据 |

```bash
python3 xinci-simple-workflow/xinci-simple-core/scripts/write_observation.py --input <临时观察.json>
```

使用打印的 `证据/<slug>/<唯一标识>-verify.json` 路径。不得手工覆盖旧观察。早期拒绝或 parked 只写已知字段，不填伪造的完整现场。

## 3. 登记与补采

cluster JSON 为 `{"total_volume":原始过滤总量,"keywords":[{"term":"实际词","volume":实测月量,"kd":实测KD}]}`。

```bash
python3 xinci-simple-workflow/xinci-simple-core/scripts/ledger.py register \
  --slug <slug> --primary-keyword '<主词>' --cluster-file <词表.json> \
  --seed-json '<实际来源type/value/queried_at对象>' \
  --proxy-json '<实际kd/low_dr_count/ugc_count/content_age_median_days对象>' \
  --evidence '<scan观察路径>' --by <执行者> --reason '<准入与范围依据>'

python3 xinci-simple-workflow/xinci-simple-core/scripts/ledger.py refresh-cluster \
  --slug <slug> --cluster-file <补采词表.json> --evidence '<新scan观察路径>' \
  --by <执行者> --reason '<补采来源与变化>'
```

refresh-cluster 只作用于 found/parked。代理排序 `rank.py`；只读前5用 `rank.py --no-write --top 5`。

## 4. 收入预筛

```bash
python3 xinci-simple-workflow/xinci-simple-core/scripts/revenue_model.py \
  --upper-bound --cluster-volume <原始总量>
```

不传限制则覆盖所有形态与垂类。有实际依据才能加可重复的 `--possible-form`、`--possible-niche`。将完整输出放进 verify 观察 `prescreen.result`，另记 `prescreen.basis`。只有 can_reject=true 才能：

```bash
python3 xinci-simple-workflow/xinci-simple-core/scripts/ledger.py transition \
  --slug <slug> --to rejected --gate revenue_prescreen \
  --evidence '<预筛观察路径>' --by <执行者> --reason '<上限与差额>'
```

无需填写 browser_preflight/serp_top10；这是收入预筛，不是已完成现场核验。

## 5. 核验收入与出口

```bash
python3 xinci-simple-workflow/xinci-simple-core/scripts/qualification.py \
  --slug <slug> --evidence '<任务组1观察>' --evidence '<任务组2观察>' > <临时收入.json>
```

先检查退出码和输出。一个任务组只传一个 --evidence；多个组追加参数。输出的 form/revenue/passes 均由脚本计算。

```bash
python3 xinci-simple-workflow/xinci-simple-core/scripts/ledger.py transition \
  --slug <slug> --to verified --form <输出form> --revenue-file <临时收入.json> \
  --evidence '<任务组1观察>' --evidence '<任务组2观察>' --by <执行者> --reason '<核验与收入依据>'
python3 xinci-simple-workflow/xinci-simple-core/scripts/build_report.py --slug <slug>
python3 xinci-simple-workflow/xinci-simple-core/scripts/validate_ledger.py
```

拒绝：`transition --to rejected --gate G1|G2|G3|scope|revenue`，并传实际观察/by/reason。缺证据或季节性：`--to parked`。只选择一个 gate，不把竖线列表原样传入。

## 6. 清单

```bash
python3 xinci-simple-workflow/xinci-simple-core/scripts/run_log.py \
  --date <YYYY-MM-DD> --skill xinci-simple-scan \
  --run-id <唯一ID> --round 1 --max-rounds 3 \
  --source-kind root --seed-value Generator --outcome started --next-step scan \
  --billable-calls 0
```

开始、完成、阻塞分别追加；文件名自动唯一。阶段结束补 --source-opened、--candidate-touched、--note 和本条新增调用数。

- scan completed/skipped → next_step=verify。
- verify completed → 非末轮 scan，末轮 done。
- started/blocked → 当前阶段。

单独 scan/verify 也使用唯一 run_id、round=1、max_rounds=1；scan 完成后的 next_step 仍为 verify，便于下次接着核验。重复完成同一轮同一阶段会拒收。

## 7. 历史纠错

先读旧证据，追加 verify 审计观察，带 audit_basis（说明使用哪些已有材料，是否重新采集）、source_urls、points；范围命中须写对应 scope_recheck=true。

```bash
python3 xinci-simple-workflow/xinci-simple-core/scripts/ledger.py invalidate \
  --slug <slug> --to parked --gate evidence --evidence '<审计观察>' \
  --by <执行者> --reason '<具体缺口>'
```

范围命中改为 `--to rejected --gate scope`。原状态必须 verified，旧报告自动归档，历史收入保留供审计但不再作为有效机会展示。

用户批准判据变更后翻案：`ledger.py requalify`，参数同 verified，另加 `--change-basis '<用户批准的变更来源>'`；不允许竞争门拒绝项因收入门槛变更翻案。
