# 数据采集（xinci-simple）

怎么取数据、用哪条通道、什么算合规观察。判据在 `选词契约.md`，本文件只管采集纪律。

## 1. 两条浏览器通道

| 用途 | 通道 | 原因 |
| --- | --- | --- |
| Semrush：Keyword Magic / Keyword Overview（含 SERP overview）/ Domain Overview | **Claude in Chrome**（用户真实 Chrome，共享账号已登录） | 需要登录态 |
| Google SERP（G1/G2/G3）、`allintitle:`、Google Trends | **内置浏览器面板**（美区、桌面、未登录） | 必须未登录，否则个性化污染 SERP |
| DataForSEO（可选，首版不接） | REST API 走 curl，凭据放环境变量 | MCP 未安装；接入后用于批量拉 shortlist 首页域名 rank |

**硬规则**：Chrome 已登录 Google，**不得用它读任何 Google SERP**；内置面板不登录 Semrush。两条通道各干各的。

## 2. Semrush 操作纪律

### 2.1 额度

- 每次计费查询必须能改变一个决策；为流程而跑的查询禁止。决策不变，查询不跑。
- 预览优先：一次看 ≤ 50 行，只记要点（top 20 词 / 月量 / KD + 合计簇量），不整页转录。
- CSV 只在预览已证明簇值得深看时导出。
- 每轮 Semrush 调用数如实计入运行清单 `billable_calls`。
- 登录失效、验证码、额度提示 → 停下如实报告，不绕、不猜数。

### 2.2 三个页面怎么用

**Keyword Magic**（发现）：输入种子 → 过滤 US / KD ≤ 49 / 排除 Navigational / 排除成人 / phrase match → 读前 50 行。记：all keywords 数、total volume（= 簇量）、top 20 行的词 / 月量 / KD。词根轮换时一次一个词根，不合并。

**Keyword Overview**（取 DR）：输入主词 → 页底 SERP overview 面板给前 10 条的 URL 与 Authority Score。数 AS < 30 的条数 → `proxy.low_dr_count`；记下 AS 列供 verify 的 G3 用（本工作流的"DR" = Authority Score）。一次查询拿全，不逐域名查。

**Domain Overview**（小站反推）：找 Authority Score < 30 且月自然流量 > 50K 的站 → Top Organic Keywords 看它靶的主题 → 主题按 phrase match 回 Keyword Magic 验簇量。

## 3. Google SERP 读取规程

三条任一不满足，该次观察不得支撑 G1–G3 结论，重读。

### 3.1 环境

- 内置浏览器面板，未登录；
- 搜索 URL 显式带参数：`https://www.google.com/search?q=<主词>&gl=us&hl=en&pws=0`。

### 3.2 容器自检

- **不用 `get_page_text`**（它选中 web results 容器，整块跳过 AI Overview，且不报错）。
- 用 JavaScript 读 `document.body.innerText` 整页文本，在其中检索 `AI Overview` / `Featured snippet`。
- 读回的文本须从 `Skip to main content` 一类整页开头开始；若从 `Web results` 或第一条自然结果开始，说明选错容器，作废重读。

### 3.3 等待与占位词

- AI Overview 在页面 load 之后异步生成。导航后等待若干秒再读整页。
- 文本里出现 `Thinking` / `Searching` / `Thinking a little longer` → 还在生成，等待后重读。
- 文本里完全没有 `AI Overview` 字样时，隔几秒重读一次确认；重读后仍没有才算真的没有。

### 3.4 读什么

- 首屏：有没有 AI Overview / 精选摘要 / 原生小组件；它把任务做完了没有（用户还要不要点结果）。
- 前 10 条自然结果逐条：域名、类型（tool / article / forum / video / official / brand / other）、是否完整完成任务、可见日期。DR 从 scan 时记的 SERP overview 取；缺则本次到 Semrush 补一次并计费。
- 翻到第二页，到明显质量断层为止；记一句话 `page2_note`。

## 4. 浏览器预检四项

verify 开始前在内置面板打开一次美区查询，现场核对，写进每份 verify 观察的 `browser_preflight`：

| 项 | 怎么核 |
| --- | --- |
| `controllable` | 能用 JS 读到整页文本 |
| `desktop` | `#rcnt` / `#center_col` 在场，或 UA 为桌面且布局为桌面版（面板隐藏时 `innerWidth` 可能为 0，不作依据） |
| `region` | URL 三参 `gl=us&hl=en&pws=0` 齐备 → `us`；页脚位置写进 `evidence`，不凭 `gl` 声称美国 IP |
| `logged_out` | 页面有 `Sign in`，`a[aria-label*="Google Account"]` 与 `img[alt*="Google Account"]` 为空 |

任一不合规 → 本次不写 G1–G3 结论，只在 `points` 记原因，候选留 `found`。不做 SHA 绑定、不设 15 分钟时效。

## 5. Trends 与 allintitle

- **Trends**：`https://trends.google.com/trends/explore?geo=US&date=today%2012-m&q=<主词>`，只记一句话读数（"全年平稳" / "集中在 11–12 月，其余月份 < 峰值 20%"）。JS 重的页面内置面板读不出时，可用 Chrome 通道——Trends 不受登录态影响。
- **`allintitle:"<主词>"`** 结果数只作参考记进 `points`，不进任何门。

## 6. DataForSEO（可选，首版不接）

凭据 `DATAFORSEO_LOGIN` / `DATAFORSEO_PASSWORD` 环境变量，REST API 走 curl。接入后用于批量取 shortlist 首页域名 rank，替代手工从 SERP overview 抄。接入时另加运行清单字段 `dataforseo_calls`。
